# AI 时代，笔记为什么该用 HTML，而不是 Markdown

> 在线阅读排版版：<https://jingmox.github.io/hReader/examples/why-html.html>（这篇文章本身就是用 hReader 排的。）

## 两个让我坐不住的瞬间

第一个瞬间：我用 AI 整理笔记，往里面插了一堆录音。Markdown 里的音频只能是一行链接，或者一个光秃秃的播放器，摘要、逐字稿、说话人各放各的。插到第五段，整份笔记已经乱到没法读。

第二个瞬间：参加一个黑客松，好几支队伍没用 PPT，直接打开一个 HTML 页面做汇报。页面是 AI 现场生成的，有图表、有折叠、有动效，比幻灯片好看，也比幻灯片好改。

这两件事让我想通了一个问题：**Markdown 统治笔记和文档这么多年，到底赢在哪里？这个理由在 AI 时代还成立吗？**

## Markdown 赢在“不让你排版”

HTML 的排版能力全面强于 Markdown：多栏、卡片、对比布局、图文混排、折叠、音视频、内嵌图表。这一点没有争议。

但过去十几年，写东西的人还是选了 Markdown。原因很简单：**排版的成本是人出的**。手写 HTML 太累，于是我们接受了一种“只管写字、样式交给工具”的格式。Markdown 的胜利，本质上是“放弃表现力，换来低成本”。

## AI 把这份成本付掉了

现在情况变了。笔记和文档越来越多由 AI 起草，人负责提要求、审阅、修改。对 AI 来说，写 HTML 和写 Markdown 的成本几乎一样。

于是 HTML 的表现力突然变成了**白送的**。你不需要会写 CSS，也能得到一份有卡片、有对比、有可折叠逐字稿、可以直接播放录音的笔记。

这就是为什么越来越多的人开始让 AI 直接输出 HTML。

## 但 AI 排版太自由，结果是另一种乱

真这么做过的人会发现一个新问题：**AI 每次排的都不一样。**

这一份用卡片，下一份用表格；这一份紫色渐变，下一份深蓝描边；同样是“风险提示”，十份文档有十种样子。单看每一份都还行，放进同一个资料库里，比 Markdown 还乱。

我当初那份插满录音的笔记，本质上也是这个问题：**不是 HTML 不够强，而是缺少约束。**

## 解法：给 AI 一套受约束的排版系统

hReader 做的事情，就是给 AI 一套“只能这样排”的规则：

- **8 个语义组件**：KPI 卡阵、洞察、风险提示、对比分栏、深度折叠、步骤时间线、图表舞台、音视频卡。AI 只需要判断“这段内容是什么”，不需要决定“它长什么样”。
- **视觉和内容分离**：组件只声明语义（`data-hr-component="callout-warning"`），长相全部由主题决定。换主题不动正文，也不花一个 token。
- **文风也能约束**：除了视觉主题，还可以给 AI 一份文风规约和禁用词表，写完用一条命令检查。

结果是：同样让 AI 写十份会议纪要，十份长得一样整齐，录音、摘要、逐字稿永远在同一个位置。

## 改，而不是重写

AI 生成的文档总要改。常见做法是“这段不满意，整份重新生成”，结果是改好一处，坏掉三处。

hReader 给文档里的每个块都标上了稳定的 `data-hr-id`。Agent 可以先读大纲，只读需要改的那一块，再只替换那一块；每次写入都是原子操作，并且可以撤销。

人这边也一样：在阅读器里选中一句话，写下“这里换成具体例子”，Agent 拿到批注，只改这一段，页面自动刷新。**人负责指方向，AI 负责动手，彼此不打扰。**

## 文件是你的

每份文档就是一个普通的 `.html` 文件，存在你自己的硬盘上。不用装任何东西，双击就能在浏览器里打开。

它也不属于任何一家 AI 厂商。Claude Code、Cursor、Codex、DeepSeek，或者任何支持 MCP 或 Skill 的 Agent，都能读写同一份文档。AI 越多、产出越多，“资料在自己手里”就越重要。

## 往后：不止笔记

笔记只是开始。HTML 能装下的东西远比 Markdown 多：幻灯片、报告、看板、交互式讲解，甚至在财务表格旁边嵌一个计算器。

这些形态在“AI 太自由”这个问题上是一样的，所以解法也一样：**表现力交给 HTML，一致性交给约束。** hReader 已经沿着这条线做了统一的嵌入外壳（`media-card`：音频 / 视频 + 图注 + 可折叠逐字稿，同一种卡片），以及笔记、报告、会议纪要、决策简报、幻灯片五种文档形态；接下来是更多主题、Markdown 导入和受控的交互组件。

## 坦白说现状

hReader v1.0 刚刚开源，还很早期：

- 组件目前 8 个，主题只有 1 套；
- 排版约束已经在写入时检查（`hr check`、`hr patch` 回执里的 `warnings`），但只警告、不拒写；
- 桌面版需要本机有 Node 22，安装包也还没签名，所以现阶段更推荐从 MCP 或 Skill 开始用。

如果你也在用 AI 写笔记、写报告，或者已经开始用 HTML 汇报，欢迎试用，也欢迎告诉我你最想往文档里插什么。
