## 工程实践手册（历次复盘累积的硬规则）

> 本手册只收录**踩过坑**才写下的规则，每条都对应一次真实事故或返工。新成员开工前先通读一遍，评审时按条款引用，不另造说法。

### 1.1 可读性与注释

1. **注释只解释签名表达不了的东西**：量级包络（"输入 ≤ 1MB 时 O(n)"）、精度承诺、抛错条件、与外部规范的对应关系（解析器对 `startTag` 的语义约定）。
2. **禁止"注释自我认证"**：`// 与直接赋值同口径` 这类句子，如果实现与它不符，**按高优先级缺陷处理**——读者会当场被骗。
3. 模块头不超过 3 行：说清"这个文件负责哪一件事"，不复述导出的类型。

### 1.2 死代码即高优先级缺陷

- 恒假的谓词、永远走不到的 `if`、`join(" ")` 之后又被归一化抹平的拼接，都属于"读起来像防护、实际上不存在"的代码。
- 覆盖率上不可达的分支**不许用覆盖率豁免注释糊**，也不许用类型断言绕过：优先**合并守卫**让唯一出口真实可达，做不到就删掉那段防御。

### 1.3 列表与单值必须成对建例

- 某次"先净化再判"把列表拼回单个 token，导致多值属性的第二个元素漏检。
- 规则：凡代码里出现 `split(...).join(...)`、`replaceAll` 之后再比对的地方，评审者必须问一句 **"列表的第二个元素呢"**；测试侧必须为每个"多值"属性同时构造单值与列表两组用例。
- 用例语料按 **`{元素} × {属性} × {单值 | 列表}`** 三维交叉建立，而不是按"攻击样例"手工挑。

### 1.4 裸异常不可接受

- 任何非受控异常的抛出（`TypeError`/`RangeError`/`AggregateError`）从公开 API 漏出，一律按最高优先级处理。
- 崩溃修复必须**同时**断言"不抛"与"子树/字节保真"：往返序列化断言比"不崩"更重要，否则会把"静默丢内容"写成绿灯。

### 1.5 签字轮也要报顺手发现

- 评审者核对单个改动块时撞到的既有缺陷，记为"既有 / 非本次引入"并单独列条目，由负责人决定是否阻断当前交付。
- 一次收口正是这样撞出边角解析的裸崩（随机语料小概率命中），比被签的那个改动危险得多。

### 1.6 随机语料必须跨命名空间

- 几千例随机标签串不含跨命名空间组合，就会得出"该分支不可达"这种**弱证据结论**。
- 随机生成至少要覆盖 `外来内容 × 特殊内容模型` 的交叉。

### 1.7 并发与基线

- 评审者改代码时，其他角色**不得**以一次全量测试作为唯一判据（可能跑的是别人的中间态）；评审者必须记录校验和前后一致，否则结论不对应同一份源码。
- 写者并发恒为 1：源码、测试、配置分属不同角色，三者不重叠才允许并行。

### 1.8 交付粒度调整（生效自上一轮迭代）

| 项           | 旧           | 新                                   |
| ------------ | ------------ | ------------------------------------ |
| 任务粒度     | 一功能一任务 | 同文件族的相邻任务合并               |
| 评审轮       | 每轮重跑全量 | 只验返工清单 + 1 个新攻击面          |
| 措辞类问题   | 阻塞提交     | 不阻塞，记入下一任务                 |
| 崩溃与覆盖率 | 零容忍       | **不变**：崩溃清零、覆盖率阈值不放宽 |

### 1.9 依赖策略

旧规则"不新增任何依赖 / 一切零依赖手搓"**作废**。新规则：**按需引入成熟可靠的开源库**。

- 判定顺序：能用成熟库直接解决的问题，**优先用库**，不要手搓。手搓只保留在"库会引入更大风险"的场合（体积、许可、原生依赖、维护停滞）。
- **已经手搓出来的模块允许被替换**：走单独的重构任务，不夹在功能任务里。
- 两个执行边界：
  1. **前端运行时依赖**或**底层核心架构**替换（框架 / 打包器 / 解析引擎）：先出选型方案（候选、体积、维护活跃度、替换成本、回退）给负责人确认，再动手。
  2. 服务端与测试侧的轻量成熟库（HTTP 工具、diff、测试辅助、随机生成器等）**可以自行引入**，无需逐次请示，但必须在任务里登记"引了什么、为什么、替代了什么手搓代码"。
- **不许在未结的任务里推翻已过审代码**：当前任务先收口，替换另开一张重构任务，分批进行。
- 引入依赖时的门禁不变：死代码检查必须仍干净（不许有"装了没用"的依赖）、依赖方向规则不得因新依赖破窗、覆盖率阈值不放宽。

### 1.10 测试与 CI 的执行纪律

事故：内存有限的机器上同时跑了 3 条完整流水线，每条都是编译 + 打包 + 测试线程池 + 覆盖率 + 静态检查，叠加到远超物理内存，交换分区打爆。

规则：

- **全量验证只有一个执行者：负责人**，且收口时只跑 1 次。任何角色跑之前先确认没有别的测试进程在跑。
- 开发/返工期间只跑**定向命令**：单个测试文件、改动文件的静态检查、类型检查。禁止"边改边跑全量覆盖率"。
- 测试配置显式限制 worker 数：这是**限流**，不是放宽门禁（覆盖率阈值不变）。
- 长命令一律**后台 + 轮询**：前台静默数分钟会被看门狗终止，而**它的子进程树不会被回收**——孤儿进程会继续吃内存，这是事故的第二个成因。
- 终止任何子任务后，立刻确认无残留进程。
- 覆盖率红分两类，必须分开处置：**代码死**（该删/该合并守卫）与**测试漏**（该补例）。判据是"哪条用户可见行为会触发它"，答不出来就按代码死处理。

### 1.11 契约瘦身与"零消费字段"三分法

**背景**：一次收口时发现响应体里两个字段**线上零消费**——消费侧连它们的形状都不校验，用户看到的那句话实际来自另一个字段。清账过程中踩出四条硬规则：

1. **零消费字段有三种命运，必须先分类再动手**：
   - **该删**：同义反复型（字段的值已被另一个字段完整表达）。删掉是净收益。
   - **该留（且必须写明用途）**：契约自证型（靠它能证明产物不丢字节，删了就成孤证）。
   - **该用**：护栏型（过期数据的唯一判据）。删掉等于把未来唯一的防线扔掉；正确动作是排期让消费方真的用它，而不是删。

   > 判据一句话：**"删了它，还有别的东西能证明同一件事吗？"** 能 → 删；不能 → 留下的必须写清"线上为什么有它"，且**不许美化**（如实写"当前消费方尚未使用"）。

2. **注释也是代码的一部分**：删掉字段后，任何"前端会拿它做什么"的注释都成了替死人作证。**删字段的任务必须把注释一起审计。**

3. **结构性恒真断言比没有断言更坏**：某断言在结构上不可能失败，却让账本记着一笔"这里验过了"。删它之前必须证明**原意图已由别的断言承接**（办法：临时删掉被测副作用 → 用例变红 → 还原后哈希一致）。

4. **删掉门禁红灯时，只许收窄表面，不许放水**：红灯没有一条靠豁免消掉——能靠合并真值源解决的，绝不靠豁免。

### 1.12 交付报告的"绿"必须与全量验证同一集合

**事故**：交付报告写"类型检查 / 静态检查 / 依赖检查全绿"，复跑**第一道就红**——格式检查三处未格式化。不是撒谎，而是"轻量四联"里**没有**格式检查，而全量验证是九道。

**规则**：

1. 角色的"轻量门"= 全量验证的**真子集**，且必须显式列出跑过哪几道。派任务时要在任务里写死这份清单，不许让角色自己猜。
2. **格式检查属于"改一个空行就能过"的门，必须放在四联里**——它成本最低、最常漏，而漏了它整链是 100% 红的。
3. 交付由**负责人**跑唯一一次全量验证；角色跑定向用例 + 轻量门。角色若被要求跑全量，必须先确认没有别的测试进程在跑。
4. **提交归属**：`git add -A` 会把工作区的中间产物（编译残留、临时脚本）一起扫进提交。**收口提交一律按路径显式 add，禁用 `git add -A`**。

### 1.13 写者的"门禁全绿"永远是自述，不是证据

**事故**：交付报告里写「几项门禁全绿」。复跑时多数确实绿，但死代码检查红了：

```
pnpm knip
Unused dependencies (1)
typebox  packages/<pkg>/package.json:11:6
[ELIFECYCLE] Command failed with exit code 1.
```

差异来源不是撒谎，而是**时序**：写者跑检查时依赖刚写进清单、用法还没落地。门禁是快照，自述是记忆。

**规则**：

1. 写者自述的门禁结论一律按"待复验"处理；**进度里贴的绿，必须由负责人复跑后才算数**。
2. 反之，写者**必须**贴原始输出（命令 + stdout），只写"全绿"两字的报告直接退回——没有输出的绿无法被区分于"跑错命令的绿"。
3. 新依赖引入的批次，死代码检查要在**依赖与用法同一批**里落地；只加依赖不加用法必然红（本条的典型形态）。

### 1.14 用例名不等于断言："假证人"

**事故**：有一条名叫"多字节字符跨块"的用例，刀口实际切在**两个字符之间**——证明的是"数据行没断"，不是"字被切成两半"。同一文件另一条"换行从中间分开"用的帧**根本没有关键字段**，所以对"字段跨拆分存活"零分辨力；相关变异体因此全绿，而真实后果是关键字段丢失。

**这是同一课第二次**。差别在于：前一次是"断言没有分辨力"，这一次是"**断言有分辨力，但分辨的是别的变量**"——更难被发现，因为用例名字自证清白。

**规则**：

1. 用例名里出现的每个名词都必须在断言里有一个**只对它成立**的验证；名字里有几个变量，断言里就要有几条独立证据。
2. 变异测完以后要问一句反向问题：**"我删掉实现里的哪一行会让这条用例红？"** 答不出来的用例就是假证人。
3. 关键断言用逐字全等（`toBe`/`toEqual`），不用 `toContain`——`toContain` 只能证"包含"，不能证"仅此"。

### 1.15 只读角色的报告必须"回传即落盘"

**事故**：只读评审者不能写文件，按协议让报告"正文回传"，**当场没有落盘**。到下一轮时找不到上一轮的报告文件，无法做去重，只能靠记录猜。原文已随上下文压缩丢失，最后只能按摘要重建一个索引文件。

**规则**：

1. **只读角色的报告，回传后立刻写盘**——不要等"这一轮结束再整理"。回传内容一进上下文就可能被压缩，而压缩是有损的。
2. 报告文件名统一编号，落盘后在同一条消息里列一次目录，确认文件非空。
3. 派单给只读角色时，**不要让它"写报告文件"**（它写不了，会白烧一轮），要写"**正文返回，我来落盘**"。

### 1.16 变异测试的复原保障：未入库文件不能 `git checkout`

一次收尾轮出现：目标目录是**新目录、尚未 `git add`**，做完变异想复原时 `git checkout -- <file>` 直接失效（untracked 文件不在索引里，命令静默无效），那次是靠哈希基线 + 逐文件比对才确认全部一致。

**规则（变异测试前必做）**：

1. 先确认目标文件**已入库**（`git ls-files --error-unmatch <path>`）；已入库才可用 `git checkout --` 复原。
2. 未入库：跑变异**前**存哈希基线，每次复原后校验，**并把校验输出贴进报告**。
3. 无论哪种方式，复原后都要**再跑一遍全绿**——只看文件比对不算，因为变异可能改的是格式化后的等价文本。
4. 报告里写清用的是哪种保障，不许只写"已复原"。

### 1.17 交付消息的字数上限

同一轮的三个角色都出现了报告膨胀。**报告的价值在「判词 + 可复跑证据」，不在过程叙事。**

**规则**：交付消息不超过 **25 行**，只允许四类内容——① 判词（一行）；② 每条变异/攻击的「结果 + 点名用例」（一行一条）；③ 要求的定向输出尾部；④ 新发现的缺口（一行一条 + 指向报告节号）。**过程叙事、走过的弯路、"我又想了想"一律写进报告文件，不进消息。** 负责人要的是能不能收口，不是复盘。

### 1.18 注释宣称的保证必须由代码兑现

**事故**：一处注释写着"几条写路径共用同一条快照链"。立项时把这句当事实写进了验收标准。实现时撞红，回头查代码 → **零命中**：目标函数从不写快照，所以一次撤销会**把不相关的改动一起回退**。注释撒了谎，而它撒的谎被写进了验收标准。

**规则**：

1. 任何"复用/共用/同一条 X"的注释，都必须能用一条检索命令证伪或证真。写不出那条命令的注释，就改成陈述**本文件做了什么**，不描述别的文件。
2. 立项时从注释里抄来的"事实"，必须先在代码里核一遍再写进验收——注释与代码不一致时，**代码赢**，且这条不一致本身要登记成缺陷，不能只在任务里改口径了事。
3. 改口径还要留**防线**：修好之前，使用建议必须警示用户可见后果。**反直觉的语义不许只存在于测试里**，因为测试是给机器看的，使用建议才是给人的。
4. 反直觉语义是**差分测试的富矿**：两条写入路径在同一个怪场景下必须同样怪。这比"各自都符合规格"强，因为它能抓到"其中一条偷偷换成了底层原语"。

### 1.19 修一处不实陈述时，先 grep 它的全文找副本

**事故**：两份文档各有一句"校验**目标文件**哈希未被外部改动"，而实现实际只校验**快照自身**的哈希。按评审意见修好了一份，另一份的副本仍是旧的；直到回头检索才发现。

**为什么不是个案**：同一项目的同一事实，通常在**架构文档的原语表、功能卡的使用说明、代码注释、技能文档**四处各有独立拼写。修一处等于把"两份错"变成"一对矛盾"，比不改更糟——后来人不知道该信哪一份。

**规则**：

1. 修任何关于**行为**的不实陈述前，先用该陈述里的关键名词 `grep -rn` 全仓，列出所有拼写副本，一次全改。
2. 行为类事实的**唯一权威**是代码；文档之间互为副本，谁都不是权威。所以改完要用一条命令回证。
3. 反向也成立：**新增**行为说明时，只在**一个**地方写清事实，别处只写"见某文档的 X 节"——副本越多，漂移越快。

### 1.20 路线图不是事实：立项前先证"外部依赖真实存在"

**事故**：一张卡要做一个宿主插件。立项前派了一路只读调研去证伪，结论是**半真半假**——生态真实存在，但三处细节是错的：

| 文档写的            | 真实                                           |
| :------------------ | :--------------------------------------------- |
| `plugin add <name>` | profile 参数是必填，漏了就 usage 报错          |
| 入口只有清单文件    | 两份都要：`package.json` 的字段 + 清单 yaml    |
| "钩子拦截器"        | 该概念**不存在**；真机制是分段注册的 waterfall |

另有两处更隐蔽的：同名旧包是多年前的另一物、命名空间 404，真实组织是另一个；类型合并必须写完整的包名（写错**不报错**，只是校验静默失效）。

**这是上一条的推广**：注释不是备忘而是契约，那么**路线图不是事实而只是提案**。若按错字段名做完，会在真宿主上一次性崩掉，而在此之前 CI 全绿。

**规则**：立项前，凡是任务里引用**本仓之外**的东西（包名、版本、入口字段名、API 名、CLI 用法），必须有一条可复跑的命令证明它的存在与形状：`npm view <pkg> version license`、`npm pack` 后读声明文件、检索官方模板。拿不到就写"拿不到，因为……"，然后把该条降级为"待验证"放进范围之外，不许当事实写进验收。

**补充**：任务初稿写的分段序号是更早版本的真值，实装包已换成另一组常量。实现者按真值取值并给出理由，反过来纠正了任务。

**规则升级**：任务里凡引用**外部包内的常量/枚举/序号**，除了"证明它存在"，还要**贴出取值所在的行**。"我记得是某段"与"路线图这么写的"是同一类错误，只是一个记在自己脑子里、一个记在别人的文档里。

**副产物**：这一卡还顺带证明了两件事——(a) 规约的**内容**半边早就在了，所以"缺这个能力"的判断也要先检索；(c) 面板要求与"无框架"约束直接冲突，被移出本卡。

### 1.21 派单里点名的符号，必须是 grep 得到的东西

**事故**：给测试侧的第一份变异清单点名了十几个待变异目标，其中好几个**在本包里根本不存在**（凭上一张任务的结构印象写的）。执行者只能把多条标 `N/A` 并说"全仓无该符号"——好在他没有被"必须报满"的格式逼着编结果。

**代价是可测量的**：一整轮的部分工力打在空气上，而且如果执行者不够硬，最可能的结局是给一张"全绿"的假报告——因为**变异一个不存在的函数，永远不会红**，写成 `N/A` 还是写成 `KILLED` 全靠自觉。

**规则**：

1. **派单前，每个点名的符号先检索一次**，把 `文件:行` 贴进派单正文。派单里出现检索不到的符号，是派单者的错误，不是执行者的。
2. 执行者遇到不存在的目标，**必须报 `N/A` 并附检索证据**，不许翻译成 `KILLED`，也不许为了凑数找近似物替代（把别的函数当等价物是**被允许**的，前提是明说了"等价物"并给出理由）。
3. 变异表的格式要求里**显式包含 `N/A` 这一列值**，否则格式本身在制造假绿。

**判断句式**（可复制的正确写法）：「本包无某函数；等价物 X 删目录检查 → KILLED（等价物）」

### 1.22 烟测脚本本身从未被烟测过

**事故**：写了一个手工烟测脚本，本轮每跑一次都打印 `SKIP：本机没有可用的依赖`（EXIT=0），于是它从交付到终审**从未真跑过**。装到隔离目录后第一次打它，第一行就抛：

```
Error: invalid profile name "/var/folders/…/profile-XXXXXX"
    at resolveProfileDir (…/lib/index.js:1365)
```

profile 参数收名字不收路径。**这个烟测从写完起就没有一次能通过**，而它不在 CI 里、SKIP 又记 EXIT=0，所以它是"永远绿"的完美形态——一个不受任何回归保护、却出现在交付物里的花瓶。

更隐蔽的一层：它原本的判据是"目录里出现包名"，而在退出码非零的那次失败里看到 **目录已经被写入了包名**——"日志/目录里出现某字符串"是能被失败副作用满足的**软断言**。

**规则**：

1. **任何 `scripts/smoke-*` 交付前必须有一次"真跑"记录**，且真跑必须由**不是写这段代码的人**在另一环境下复现。`SKIP` 不算通过。
2. `SKIP` 必须与 `FAIL` 在输出上可区分，且 SKIP 文案里要给出**可执行**的安装命令。文档要明写"这条能力目前无 CI 回归保护"——不许让读者以为它绿。
3. **禁止软断言**：断言必须落在**产物结构**上——不是"命令成功后的副作用"，而是"插件真的进了合成树"。
4. **家目录必隔离**：会写用户目录的烟测必须显式注入隔离变量，并附"跑完确认无新增"的验证方法。
5. 同理可用的一手价值：装真二进制只需要几分钟与一个隔离目录，比在假身上猜 API 便宜得多——凡是"产出必须在宿主里生效"的能力，**优先装真的**。
