# fixtures/llm/

Recorded real model response bodies, replayed by tests through a fake `fetch` so `pnpm verify` makes zero real calls. The file name is the role the fixture plays in tests.

| File           | Provenance (2026-11-16, `deepseek-v4.1-flash`)                                                                                                                                        | Manual edits                                                                                                                                     |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `ok.json`      | `finish_reason: stop`, usage `{prompt: 2991, completion: 1441, reasoning: 859}`; content is bare JSON                                                                                 | none                                                                                                                                             |
| `fenced.json`  | content taken from the same call as `ok.json`                                                                                                                                         | **only** a ` ```json ` / ` ``` ` line added around the content, which itself is unchanged byte-for-byte; pins the fenced branch of `parseJsonOf` |
| `dropped.json` | `finish_reason: stop`, usage `{prompt: 8821, completion: 1431, reasoning: 888}`; the three-corpus call whose content carried one key the style does not own (`dropped 1` on the wire) | none                                                                                                                                             |

Note: the corpora were renamed and replaced with neutral text; the recordings predate the rename. The recorded bodies were produced against the older corpus drafts, so their content does not describe the current corpus — tests replay the bodies verbatim through a mock `fetch` and assert on the merge/parsing behavior, not on corpus fidelity. Re-record if the pin must prove "today's model output for today's corpus is still consumed".

How to re-record: see `packages/cli/scripts/record-llm-fixture.ts` (one-shot script, never run by `pnpm verify`). Fixtures are bound to the model id: switching the model or changing the prompt requires re-recording, or the replay no longer proves "the current model output is consumed".

## Call ledger (budget: 10 calls)

Counting rule: one run of the record script = one upstream call (the script calls `complete` exactly once). The table lists every run from the 2026-11-16 recording session, with timestamps from the log; `--out` is the argument as logged. The script writes the response body to disk before handing it to core for validation, so a run judged `llm_failure` still cost a call and may have left a usable body — the body in `ok.json` comes from run 1 (authoritative: the bytes on disk and `usage.prompt_tokens: 2991`; a non-zero exit and a usable body are not contradictory, since validation happens after the write).
