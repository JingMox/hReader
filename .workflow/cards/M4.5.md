# M4.5 卡片：PDF 大纲/书签（`hr pdf --outline`）

> 状态：**立卡（v1）**｜立卡人：协调者｜日期：2026-11-17
> 前置：M4.4 已结卡（`53e456a`）。本卡只做一件事：**让 `hr pdf` 产出的 PDF 带可点击的大纲（书签）**。
> 读卡顺序：§1 事实基线（全是侦察实测，**不要重跑**）→ §2 非目标 → §3 设计 → §4 分工 → §5 验收。

## 1. 事实基线（协调者已实测，直接采信）

| 事实 | 证据 |
| --- | --- |
| **CDP `Page.printToPDF` 支持 `generateDocumentOutline: true`**（本机 Chrome 157.0.8103.79 + Node 24.15） | 同一文档不传 41545 字节、传 43078 字节 |
| 传了之后 Catalog 多出 `/Outlines 59 0 R`，根对象是 `<</Type /Outlines /First 60 0 R /Last 67 0 R /Count 9>>` | `strings` 实测 |
| 条目是**无 `/Type` 的字典**（PDF 规范如此：`/Outlines` 是根的类型名，条目本身没有 `/Type /Outline`） | 不要写"找 `/Type /Outline`"的断言 |
| `/Title` 是 heading 的**原文**（含编号，不剥离、不补空格）：`(1.1 Section One)` | 需要 UTF-16BE/BOM 时 Chrome 会写成 `<FEFF…>` |
| 层级**正确成树**：h1 下 `/First` `/Last` `/Count`，同级用 `/Prev` `/Next`，子项 `/Parent` 指回父 | `Chapter One`(60) `/First 61 /Last 63 /Count 3` |
| **Chrome 收 h1–h6 全部**（加一个 h4，条目从 9 变 10，挂在 h2 下、与 h3 同级） | 断言口径要按 h1–h6，不许只数 h1–h3 |
| 目的地形态 `/Dest [<pageObj> /XYZ x y 0]`，**页码正确**：`/Kids [2 0 R 9 0 R 11 0 R]` 三页，三个章分别指向 2/9/11 | 页序 = `/Kids` 数组顺序 |
| **无 heading 的文档**：Catalog 里根本没有 `/Outlines` 键，不报错 | 参数是"有 heading 才产出" |
| 产物是**经典 xref 表 + trailer**（`/Size … /Root … 0 R`），页对象直接可寻，**无 ObjStm / 无 XRef 流** | 所以测试可以用"扫字典 + 跟 `/Kids`"的方式读结构，不必写完整 PDF 解析器 |
| M4.3 已经保证**产物里 `<h1..h6>` 总数 == outline 标题数**（封面/目录标题刻意用 `<p>`） | `packages/renderer-html/src/print-page.ts:42`（AC-4 钉死） |

## 2. 非目标（越界即返工）

1. **不引任何运行时依赖**（不装 pdf-lib / hummus / qpdf 绑定）。本卡预计**零新增模块**，只改请求参数与旗标。
2. **不自写 PDF 增量更新**（追加 `/Outlines` + `/Prev` xref）。Chrome 已经能做，就别自己造解析器。
3. **不改 M4.3 的 HTML/CSS 产物**（`print-page.ts` / `print-css.ts` / `print-html.ts` 一行不动；`printToPDF` 的纸张/余白口径不动）。
4. **不做「大纲标题改写」**（不剥编号、不加"第 N 章"、不做 `--outline-title-template`）。Chrome 给什么就是什么，可读性由打印稿的 heading 文本负责。
5. **不给 `hr png` 加大纲**（PNG 无此概念）。
6. **不碰 `docs/**`**（协调者写）。

## 3. 设计要点（不满足即返工）

**D1 一个参数、一个旗标，不许扩散**
- `printToPDF` 请求里加 `generateDocumentOutline: <boolean>`，**由命令层显式传**（协议层不许有默认值、不许 `?? true`）。
- CLI：`--outline`（默认**开**）与 `--no-outline`（关）互斥，同传 → `invalid_input` exit 1（与既有旗标互斥口径一致）。
- `--no-outline` 出现在 `hr png` 上 → `invalid_input` exit 1（同 M4.4 对 `--page-size` 的处置：已知旗标放错子命令属于用户输入错）。

**D2 `--json` 键集固定，只加一个键**
`hr pdf --json` 变成 `{pdf,bytes,pages,outline,out}`（键集精确、不省键、顺序按此）。`outline` = **本次打印稿的 heading 数（h1–h6）**，`--no-outline` 或文档无 heading 时为 `0`。
**为什么取 heading 数而不是解析产物**：src 里不引 PDF 解析器（非目标 1）；"产物大纲数 == 打印稿 heading 数"这条不变量由 e2e 真 Chrome 断言（AC-6），而不是让运行时再读一遍自己的产物来自证。

**D3 纯层留证据：请求构造必须可单测**
`packages/cli/src/chrome/pdf.ts` 里"参数 → CDP 请求"的那一步必须能被单元测试**直接看到** `generateDocumentOutline` 的取值（导出纯构造函数，或在假传输里断言发出的 `Page.printToPDF` params）。**不许**只有 e2e 能验证到它——否则"参数忘了传"在单元层全绿存活。

**D4 结构断言工具只放测试**
新增 `packages/cli/tests/helpers/pdf-scan.ts`（**仅测试用，不进 src**）：从字节里扫 `N 0 obj … endobj`、跟 `/Root`→`/Pages`→`/Kids` 算页序、从 `/Outlines` 沿 `/First`/`/Next`/`/Parent` 还原标题树（含 `<FEFF…>` UTF-16BE 解码）。这层本身也要有用例（喂三份手写字节：单条目、嵌套三层、无 `/Outlines`）。

**D5 确定性边界照旧**
不断言字节相等。可以断言：同输入两次的**条目数、标题序列、每条的页序**完全相等（e2e）。

## 5. 验收

- **AC-1** `hr pdf a.hreader --out a.pdf` → exit 0，产物含 `/Type /Outlines`；`--json` 键集精确 `{pdf,bytes,pages,outline,out}`，`outline > 0`。
- **AC-2** `--no-outline` → 产物**无** `/Outlines` 键，`--json.outline === 0`。
- **AC-3** `--outline --no-outline` 同传 → `invalid_input` exit 1；`hr png … --no-outline` → `invalid_input` exit 1；两者都**不落盘**。
- **AC-4** 无 heading 的文档（只有正文段落）→ exit 0，产物无 `/Outlines`，`outline === 0`（**不是**报错）。
- **AC-5** 标题保真：产物的 `/Title` 序列 == 打印稿 `<h1..h6>` 的 `textContent` 序列（空白正常化后逐条相等）；含中文/全角/`&<>"` 转义字符时按 PDF 文本串规则还原后仍相等。
- **AC-6**（e2e，真 Chrome）三条硬不变量：① 大纲条目数 == 打印稿 heading 数；② 每条 `/Dest` 的页对象 ref 经 `/Kids` 换算后的页序，与该 heading 在产物里所在的页**一致**（至少断言首章=第1页、跨章条目严格不减）；③ 同输入两次渲染的标题序列与页序相等。
- **AC-7** `$TMPDIR` 无新增 `hr-chrome-*`；`pgrep -fl 'hr-chrome-' | grep -v pgrep` 为空。
- **AC-8** 全量 `pnpm verify` EXIT=0（协调者复跑两遍），文件数/用例数只增不减，四维 perFile 100%。
- **变异清单（≥8，测试员执行，每条都要"能红"）**：把 `generateDocumentOutline` 恒 `false`；恒 `true`；协议层塞默认值；`--no-outline` 不生效；`outline` 恒 `0`；`outline` 抄 `pages`；`--no-outline` 在 png 上被静默接受；`pdf-scan.ts` 的 `/Kids` 顺序反转（证明它真在读页序）。

## 7. 协调者裁定（2026-11-17，回应 `spec-M4.5.md` §3 的 A1–A14）

测试员的 14 处歧义全部采纳其**建议项**，此处固化，写者/测试员/审计员一律照此，不再另议：

| 编号 | 裁定 | 关键理由 |
| --- | --- | --- |
| A1 | `outline` = 打印稿 HTML 里 `<h1..h6>` **元素个数**（`parseHtml(product.html)`） | 用 `buildOutline().nodes` 会因 `OUTLINE_DEPTH_LIMIT = 4`（`packages/core/src/ops/outline/constants.ts:23`）和缺 `data-hr-id` 省略（`walk.ts:130-133`）而变小；数源 `<article>` 会把封面/页头也算进来 |
| A2 | h1–h6 全算；h5/h6 属**未实测**，unit 不硬断言，留 e2e 观察 | 基线只验到 h4；`HEADING_LEVELS`（`packages/core/src/model/constants.ts:20-27`）是 h1–h6 |
| A3 | 两边都用 `normalizeWhitespace`（`packages/core/src/html/text.ts:45`）归一 | 仓库里已有唯一实现；**禁止 NFC/NFKC**，全角 ＡＢＣ 必须原样相等 |
| A4/A6 | `--no-outline` / 无 heading → `outline` 键**存在**且为数字 `0` | D2「键集精确、不省键」；现有键集测试用 `keysOf(...)` 顺序比对（`packages/cli/tests/pdf-command.test.ts:73-87`） |
| A5 | 只有 `--outline` × `--no-outline` 互斥；`--no-outline --force` 必须能覆盖已存在文件且 `outline === 0` | 其余旗标与本卡正交 |
| A7 | `hr png` 上 `--outline` **和** `--no-outline` 都 `invalid_input` exit 1 | 不许留「正向 exit 2 / 反向 exit 1」的对称裂缝 |
| A8 | **不钉**互斥错误文案 | 钉文案会把「改一句人话」变成返工 |
| A9 | 默认值只在命令层；协议层键必须显式存在（`printParamsOf("a4", false).generateDocumentOutline === false`，键存在） | D1「协议层不许有默认值」 |
