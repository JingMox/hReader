# M1.5 · `hr_patch_node` 增量 Patch + 原子写 + undo

> 依据：`docs/05-feature-cards.md` §M1.5（AC1–AC8）、`docs/04` §6（目录：`io/` 是唯一允许碰 fs 的地方）、
> `docs/04:228-230`（clock / idGen / fsLike 注入；原子写；history 保留）。
> 本卡是第一张**有文件系统副作用**的卡：纯变换与 IO 必须分层，90% 的逻辑要能在无 fs 的情况下测。

## 0. 分层（硬性，审计按此判 P0）

| 层 | 路径 | 职责 | 允许碰 fs |
|---|---|---|---|
| 纯变换 | `src/ops/patchNode/**` | 在字符串上完成 patch、校验、ID 分配 | ❌ |
| 端口 | `src/io/*.ts`（类型） | `FileSystem` / `Clock` / `Sleeper` 结构类型 | ❌ |
| 适配 | `src/io/node-fs.ts` 等 | 上述端口的真实实现（唯一 `node:fs` 引用） | ✅ |
| 编排 | `src/io/**` | 原子写、备份/undo、锁、路径校验 | ✅ |

- `ops/patchNode` 不得 import `node:fs`/`node:path`（depcruise 规则收紧为**禁止**，不许例外）。
- `FileSystem` 端口只声明本卡用到的方法：`readFile`/`writeFile`/`rename`/`unlink`/`mkdir`/`lstat`/`readdir`/`realpath`/`open`(exclusive)/`close`。**一个**端口，不拆 `Writer`/`Reader`。
- 注入方式：函数的**最后一个参数**是 `deps`（`{ fs: FileSystem; clock: Clock; sleep: (ms: number) => Promise<void> }`），不做全局单例、不读 `process.cwd()`。

## 1. 纯变换 API（`ops/patchNode`）

```ts
type PatchAction = "replace" | "insert_before" | "insert_after" | "append" | "delete";

type PatchRequest = {
  targetId: string;      // 目标的 data-hr-id（必须是块级元素）；"root" 表示 <article> 自身
  action: PatchAction;
  html?: string;         // replace/insert_*/append 必填；delete 必须不传
};

applyPatch(html: string, request: PatchRequest): { html: string; newIds: readonly string[]; changed: boolean }
```

裁定：
- **`changed: false`** 当 `replace` 的内容与现内容规范化后逐字相同 → 编排层**不得**写盘、**不得**留历史（幂等 AC7 靠此实现，不是靠 `sha256` 比较）。
- `delete` 传 `html` → `HrError("invalid_input")`；其他 action 缺 `html` 同理。
- `newIds` 只含**本次新分配**的 ID，按文档序；已存在的元素 ID 一律不动（不重排、不改名）。
- `targetId` 为 `root` 时：`append` 追加到 `<article>` 末尾；`replace` 替换 `<article>` 的全部子节点但保留 `<article>` 自身及其属性；`delete`/`insert_*` → `HrError("invalid_input")`。
- 新节点 ID 复用 `html/inject.ts` 的种子规则（父 path + 内容 hash + 冲突后缀），保证同输入同输出。

## 2. 片段校验（AC5）

`parseFragment(html)` 规则，全部同步、纯函数：
1. 允许省略外层包裹；出现 `<html>/<body>/<head>` 视为外壳，剥掉后取内容。
2. 必须**恰好一个根元素**；零个或多个根元素、仅文本、仅注释 → `HrError("invalid_fragment")`。
3. 元素名与属性按 `html/parse.ts` 的既有白名单走；命中 `<script>`、`<style>`、`<iframe>`、`<object>`、`<embed>`、`<link>`、`<meta http-equiv>` 任一个 → `HrError("forbidden_content")`，报文点名字符串（`<script>` 等）。
4. 属性名以 `on` 开头（大小写不敏感）或值是 `javascript:`/`data:text/html` → `HrError("forbidden_content")`。
5. 未闭合/错配 → 直接由解析器报 `HrError("invalid_fragment")`，**不**走"尽力修复"。
6. 校验失败时**原文件字节不变**（编排层在写之前完成全部校验，不许"先写后校验"）。

## 3. 编排 API（`io/patchFile`）

```ts
patchFile(input: { workspace: string; file: string; request: PatchRequest }, deps: PatchDeps): Promise<PatchResult>
type PatchResult = { path: string; bytes: number; newIds: readonly string[]; historyPath: string | null; changed: boolean; undoable: boolean };
undoPatch(input: { workspace: string; file: string }, deps: PatchDeps): Promise<UndoResult>
type UndoResult = { path: string; bytes: number; restoredFrom: string; sha256: string };
```

### 3.1 路径安全（AC8）
- `file` 必须相对 `workspace`；绝对路径、`../` 逃逸、`workspace` 外的 `realpath`（含父目录符号链接）→ `HrError("path_outside_workspace")`。
- 目标必须存在且是**普通文件**（`lstat` 后 `isFile()`），否则 `HrError("not_a_file")`。
- 拒绝操作 `workspace/.hreader/**`（history 目录不可被 patch）。

### 3.2 原子写（AC3）
1. 写 `<file>.hr-tmp.<nonce>`（**同目录**，保证 rename 同 fs），`fsync` 后 `rename` 覆盖。
2. `rename` 前任何失败 → 删 tmp，原文件不变，抛 `HrError("io_failure")`（`cause` 带原始错误）。
3. tmp 文件名固定前缀 `.hr-tmp.`；下次启动/写入前清理本目录下遗留的 `.hr-tmp.*`（只清同前缀）。
4. 不得整文件重排/重写格式：除被 patch 的子树与新增 ID 属性外，其余字节层输出保持既有序列化器行为（不新增空白/换行）。

### 3.3 备份与 undo（AC4）
- 写前把**原文件字节**复制到 `workspace/.hreader/history/<sha1(相对路径)>/<ISO8601 时间戳>-<seq>.html`；`clock` 注入，seq 保证同毫秒内不覆盖。
- 每个文件保留最近 **10** 份，写入后裁剪（按时间戳排序）。
- `undoPatch` 取最近一份，原子还原，删除该快照；无快照 → `HrError("undo_unavailable")`。
- 还原后 `sha256(file) === sha256(快照)`，逐字节一致。
- 快照不参与 `git` 跟踪（`.hreader/` 进 `.gitignore`）。

### 3.4 并发锁（AC6）
- 锁文件：`workspace/.hreader/locks/<sha1(相对路径)>.lock`，内容 `{ pid: number; nonce: string; at: number }`（`open` 用 `"wx"` 独占创建）。
- 抢锁失败时按 25ms 间隔重试，默认上限 **2000ms**（参数可调），超时 → `HrError("locked")`。
- 陈旧锁接管：锁内容 `at` 早于 `now - 60000`，或 `pid` 对应进程已不存在，或内容不可解析 → 删除后重试一次；接管次数上限 1，避免活锁。
- 释放锁必须在 `finally` 里；进程被 kill 留下的锁由上述规则接管。
- `delete`/`replace`/`append` 等所有写操作共用同一把锁（按文件，不按 action）。

## 4. 错误码（本卡新增 4 个，冻结）

| code | 触发 |
|---|---|
| `invalid_fragment` | 片段不用恰好一个根元素 / 解析失败 |
| `forbidden_content` | `<script>` 等可执行容器、`on*` 属性、`javascript:` URL |
| `path_outside_workspace` | 绝对路径、`..` 逃逸、realpath 越界 |
| `not_a_file` | 目标不存在 / 非普通文件 / 指向目录 |
| `io_failure` | 原子写、rename、备份任一步的系统错误（`cause` 保留原错） |
| `undo_unavailable` | 无快照可回滚 |

既有 `node_not_found` 用于 `targetId` 不存在；`locked`、`invalid_input` 沿用。**已分配码不得改名或复用。**

## 5. 非目标

- 不做多文档事务、不做 patch 队列、不做跨文件 undo 链。
- 不做 HTML 语义校验（`validateDocument` 由调用方决定是否跑）。
- 不做 diff/patch 格式（不走 unified diff）。
- CLI 接线在 M1.8，本卡只出 core API。

## 6. 门禁（本卡额外）

1. `pnpm verify` EXIT=0，四维 100%（`io/**` 与 `ops/patchNode/**` 都算）。
2. **kill 测试**（AC3）：子进程写 tmp 后停在 barrier，父进程 `SIGKILL`，断言原文件 sha256 不变 + 无残留 tmp；再跑一次写入，断言遗留 tmp 被清理。用真实子进程，不许 mock kill。
3. **并发测试**（AC6）：两个子进程同时 patch 同一文件 → 一个成功一个 `locked`（或串行都成功），最终文件必须能被解析且 `sha256` 等于其中一次结果；不允许"两次内容混合"。
4. **路径逃逸测试**：`../x.html`、绝对路径、指向 workspace 外的符号链接、`/tmp` 外链目录，四种都要有断言。
5. 真实语料：用 `docs/` 下任意一份 HTML 夹具（若 docs 无 HTML，用 `readNode` 夹具）跑 `replace/append/delete` 三种 action，断言 `hr_read_node` 仍能读到改后的节点。
6. 变异体 ≥5：锁超时不生效、history 用 copy 而非原字节、rename 前不删 tmp、`changed:false` 仍写盘、`root` 保护失效（删掉 `<article>` 属性）——每个都必须被套件杀死。

## v2 裁定（协调者，2026-11-13，G2 后）—— 覆盖上文冲突处

1. **AC4'（收紧，覆盖 §2 的"保持既有序列化器行为"）**：patch 后，**除被替换/插入/删除的那段源码区间外，文件其余字节必须逐字保留**（含 CRLF、引号风格、实体写法、BOM、缩进）。实现用 `parse5` 的 `sourceCodeLocationInfo` 做**源码区间拼接**，不许 `serialize(parse(whole))` 全文重排。`parseHtml` 可加**可选** `locations: true` 参数（默认关，不改变 M1.1 既有行为）。
2. **`changed` 的判定口径改为"写盘字节是否等于原字节"**（不是子树比较）。美化过的文档、空白差异、BOM 差异都会被正确捕获。
3. **`targetId === "root"` 的 `delete`/`insert_*` → `invalid_input`**；`replace` 只换 `<article>` 的子节点，`<article>` 的属性（含 `data-hr-id`）必须原地保留（P1-3）。
4. **片段一律剥离 `data-hr-id` 后重新注入**（片段里的 ID 不可信）；`newIds` 只含重新注入产生的 ID（P1-4）。
5. **BOM**：读入时剥离并记录，写回时**只加一次**（P1-5）。
6. **undo 完整性**：快照文件名带内容哈希前缀 `<sha256-16>-<ts>-<seq>.html`；undo 前校验哈希，不匹配 → `io_failure` 且**不消费**快照（P1-9）。
7. **锁**：单次 `open(wx)` + 一次性写完整 JSON（消除空锁体窗口）；接管必须原子 rename 到 `.steal-<nonce>` 再比较 nonce；接管条件 = 内容不可解析且年龄 >5s，或 pid 已死，或 pid 存活但年龄 >120s（P1-1）。
8. **tmp 清理**：tmp 文件名含 pid：`.hr-tmp.<pid>.<nonce>.<basename>`；只清理"pid 已死 或 年龄 >5min"的 tmp（P1-2）。
9. **片段拒绝名单追加**：`<base>`、`<meta charset>`、`<meta http-equiv>`、`<link>`、`<svg><set attributeName="on*">`（P1-7）。
10. **TOCTOU**：tmp 创建用 `O_EXCL|O_NOFOLLOW`；写 tmp 前与 rename 前各做一次 `realpath(dirname)` 复核 `isInside(workspace)`；rename 目标若变成符号链接则拒绝（P0-1）。
11. **G1 自证口径**：只允许报"`tsc -p tsconfig.json` / `eslint .` / `pnpm test` 的**真实输出**"，且必须写明命令与作用域；不得写"src 干净"代替"仓库干净"。与测试员本轮新增测试文件的冲突，标注"test-scope 正在写"而非宣称全绿（P0-2 的流程部分）。

## v3 裁定（协调者，2026-11-13，R1 后运行套件发现 10 红）

**#12 幂等与"剥 ID 重注入"的冲突（P1-4 vs AC7）——按此解决：**
- 判定幂等时比较的是**"剥除 `data-hr-id` 后的内容"**：把请求片段剥 ID 后的规范形式，与该目标节点**现有子树剥 ID 后的规范形式**比较。
- 相等 → 直接返回**原输入的字节**、`changed:false`、不写盘、不留历史（**不重新注入 ID**）。文档里已有的 ID 因此原样保留。
- 不等 → 正常走"剥 ID → 重注入"，新节点拿新 ID。
- 这不是"特例"，它是 AC7 的正确定义：幂等意味着**对同一内容重复执行不产生任何字节变化**。

**#13 空片段**：`parseFragment("")` / 仅空白 / 仅注释 → `invalid_fragment`（不是 `invalid_input`，不是 `forbidden_content`）。

**#14 错误码顺序**：任何路径先做"参数/契约校验"，再做 fs 的 `resolveTarget`。`undoPatch` 在文件本身不可读时应报 `io_failure`；只有"目标存在但不是普通文件"才报 `not_a_file`。

**#15 锁文件读取失败**（EACCES/EISDIR 等）→ `io_failure`（带 `cause`），不得当成"锁不存在"直接抢锁。
