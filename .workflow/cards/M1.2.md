## 分层裁定

- **真相源**：`ParsedHtml.root`（M1.1）。模型 `DocumentModel` 由 `toDocumentModel(parsed)` **按需派生**，不缓存、不回写、不持有 parse5 节点引用。
- 将来 M1.5 的 Patch 作用在原始树上，改完重新派生模型；因此模型**必须是无状态的纯数据**（可 `structuredClone`，无类实例、无 getter、无循环）。
- 每个语义节点对应一个 `data-hr-id`；没有 ID 的块级元素在模型里**不出现**（它们已被 M1.1 注入覆盖），出现即诊断。

## 契约

1. **模型形状**（AC1）
   `DocumentModel = { id: string; tag: string; component?: string; text: string; children: readonly DocumentModel[] }`
   - `id` = 该元素的 `data-hr-id`；`tag` = 小写标签名；`component` = `data-hr-component` 的合法值（非法值不填，另出诊断）。
   - `text` = 该节点**自身**的可见文本：直接文本子节点 + 内联后代（`a/strong/em/code/span/br/sub/sup/mark/kbd/abbr/cite/q/small/del/ins/u/s`）的文本拼接，空白归一（连续空白→单空格，首尾 trim）；**不含**块级后代的文本（块级文本各自在 `children` 里）。
   - `children` = 块级后代（沿用 M1.1 注入清单）；顺序 = 文档顺序。
   - 顶层：`DocumentModel` 中 `tag === "article"` 的节点恰好 1 个；它的 `id` 必须是 `article` 的 `data-hr-id`。
   - 映射到块：`toDocumentModel(parsed): DocumentModel`，**不可恢复问题抛 `HrError("invalid_document")`**（如 0 个或多个 `<article>`），可恢复问题只进诊断。
2. **校验**（AC2）：`validateDocument(parsed: ParsedHtml): readonly Diagnostic[]`（与 M1.1 的诊断**合并返回**，同一 code 空间）。
   - 新增窄联合码：`duplicate_id`（同一 `data-hr-id` 出现 ≥2 次，报出全部位置）、`missing_article`（0 个）、`multiple_article`（≥2 个）、`heading_level_jump`（h2→h4 等，跳级 >1；h1 只能在 `<article>` 外出现，否则 `heading_level_skip_root`）。
   - **`invalid_hr_id` 沿用 M1.1 的定义**，不得另立同名新码；`diagnostics` 顺序 = 文档顺序（稳定，测试会逐条比对）。
   - 严重度：`duplicate_id`/`missing_article`/`multiple_article` = `error`；`heading_level_jump` = `warning`；不得出现其它档。
3. **不可变**（AC3）：模型节点与数组 `Object.freeze`（深层）；对模型/入参的任何写操作必须无效或抛 TypeError；`toDocumentModel` 对同一 `ParsedHtml` 调用两次返回**深等但非同一引用**的数据（不可共享可变子结构）。
4. **无未转义 HTML**（AC4）：模型只含已解码文本与属性值；`text` 里不允许出现 `<` 与 `&` 以外的任何标记残留；序列化只在 `serializeHtml` 层发生。
5. **一致性**：模型 `text` 的空白归一必须与 M1.1 解析归一一致（复用 `src/html/text.ts` 的既有函数，如不够用则扩展它并说明）；不得复制第二份归一逻辑。
6. **性能**：`toDocumentModel + validateDocument` 对 1MB 文档 ≤ 200ms；深度 4000 的文档不得栈溢出（迭代或显式栈）。
7. **代码形态**：文件 ≤ 400 行、函数 ≤ 40 行、复杂度 ≤ 10、模块头 ≤ 3 行；导出面按 v3 两级制（模块门面可多导出，包门面只导契约符号）；不许 `any`/`as`/`!`。

## 审计重点

模型是否真只读（`Object.freeze` 是否深到底、数组是否冻结）；派生是否泄漏 parse5 节点；`text` 与块级文本的边界（`<p>a <span>b</span></p><p>c</p>` 的归属）；`heading_level_jump` 是否把 h1 在 article 内的正常用法误报；`duplicate_id` 是否只报第一处；诊断顺序是否稳定；`validDocument` 对 10 万节点是否 O(n²)；`missing_article` 抛错 vs 诊断是否与契约一致。

## 测试义务

`text` 归属与空白归一（含换行/制表/全角空格/NBSP）、块/内联边界、h2→h4 跳级与合法降级、h1 位置、重复 ID（≥3 处，位置齐全）、多/零 article、冻结深到底、深等非同一引用、4000 深不溢出、1MB 性能、诊断顺序稳定、与 M1.1 诊断合并去重。
