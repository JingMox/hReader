## 2. 非目标（越界即返工）

1. **不引任何运行时依赖**。不装 puppeteer / playwright / pdf-lib / sharp / canvas。Chrome 交互只用 Node 内置（`child_process` + `globalThis.WebSocket` + `fetch`）。
2. **不做 PDF 大纲/书签**（M4.5）、不做 PDF 合并/签名/加密、不做 OCR、不做 SVG/图表新渲染。
3. **不在单元测试里依赖真 Chrome**。真 Chrome 只出现在 `pnpm test:e2e`（可跳过），单元测试必须能在"无 Chrome"的机器上全绿。
4. **不改 M4.3 的 HTML 生成逻辑**（`print-html.ts` 的骨架/编号/转义一行都不许动）。需要额外信息请**新开纯函数**，不要就地改旧函数签名。
5. **不做 GUI 进度条/并发渲染池**。一次一个进程，串行。
6. **不碰 `docs/02`**（路线图由协调者写）。`docs/05` 只追加"使用节 + 错误码行"，由协调者补。

## 3. 设计要点（不满足即返工）

**D1 分层必须是「协议 / 传输 / 会话 / 命令」四层**
- 协议层：CDP 报文的**纯构造与解析**（`{"id":n,"method":…}`、错误映射）——纯函数，零 I/O，可单测。
- 传输层：一个**接口**（`send(text): void` / `onMessage` / `close()`），真实现是 `globalThis.WebSocket`，测试实现是内存假双工。**不许把 WebSocket 写进协议层或命令层。**
- 会话层：启动 Chrome（`--remote-debugging-port=0`）、从 stderr 抓 `DevTools listening on ws://…`、等目标、超时、`kill -TERM` 兜底。所有"进程 + 端口 + 超时"的丑东西关在这层。
- 命令层：`hr pdf` / `hr png` 只做参数 → 调会话 → 校验产物 → 落盘。

**D2 错误分类必须是闭集，且与退出码表对齐**
新错误码（需协调者批准后写进 `docs/05`）：`chrome_missing`、`chrome_failed`（进程起不来/握手失败/渲染报错）、`render_timeout`、`render_empty`（产物 0 字节或结构不合法）。全部 exit 3；`chrome_missing` 的 message 必须点名 `HREADER_CHROME` 与三个候选路径。
**绝不把 Chrome 的原始 stderr 整段塞进 envelope**（泄路径/撑爆输出）：最多保留首个错误行 + 截断 200 字。

**D3 确定性边界要写清**
PDF/PNG 字节含时间戳与内核版本，**不许断言字节相等**。断言点：PDF 的 `/MediaBox`（按 `--page-size`）、`/Type /Page` 计数（正则用 `/\/Type\s*\/Page\b(?!s)/gu`，旧写法 `[^s]` 遇 EOF 会漏 1）、字体是否内嵌（`/FontFile`）；PNG 的 IHDR 宽高与位深（直接读 8..24 字节，别引解析库）。同一输入两次渲染**页数/宽高必须相等**——这条要真 Chrome，放 e2e。

**D3b 纸张与余白的口径（v4 修订：纸型要真重排，不许只换纸）**
- `printToPDF` 固定 **`preferCSSPageSize: false`**（`print-css.ts:11-14` 的 `@page{size:A4}` 若让 CSS 赢，`--page-size` 永远失效）。
- 但 `preferCSSPageSize:false` **只换纸张不改版心**：实测 letter/a5 的版心仍是 A4 的 658×971 CSS px，a5 右侧被纸边硬切。因此 **`--page-size` 必须同时也改 CSS 的 `@page`**：
  - `packages/renderer-html/src/print-css.ts` 的 `@page` 改为**参数化**：`printCssOf(pageSize: PaperSize)` → `@page{size:<a4|letter|a5>; margin:20mm 18mm}`；`a4` 为默认，保持 M4.3 产物逐字节不变（用快照钉住）。
  - `print-html.ts` 的入参加必填 `paper: PaperSize`（D7 禁可选），由 CLI 传。
- 余白必须显式传：`marginTop/Bottom = 20/25.4` in、`marginLeft/Right = 18/25.4` in。
- 纸张表（pt，测试容差 1.5pt）：`a4` 595.28×841.89（Chrome 输出会舍到 595.92×841.92）｜`letter` 612×792｜`a5` 419.53×595.28（实测 420×595.92）。
- **验收改硬（v5 实测校正）**：三档纸张的版心宽必须**各不相同**，实测值 @96dpi：`a4 658px`｜`letter 680px`（letter 纸更宽 215.9mm>210mm，必然大于 a4）｜`a5 423px`；容差 ±6px。a5 右缘留白必须 > 6mm（实测 18.0mm）。**旧卡写的 624/462 是算错数，按本行判。**
- 真重排的有效性判据（测试员已用）：把 `printCssOf` 退回忽略 `paper` 后，同文档 a5 的目录点导引右缘只剩 13.5mm（越界 17px），现行实现 18.0–19.6mm。

## §17 v6 待办（测试员 §15.A 轮留的尾巴）

1. **`printCssOf` 无运行期守卫**：`PAPER_KEYWORD[paper]` 直接索引，`undefined` 静默产出 `size: undefined;`。→ 加 `?? throw new HrError("invalid_input", ...)`（纯函数里抛，单测覆盖）。
2. **`png-command-pixels.test.ts` 的真机/realpath 坑**：`$TMPDIR` 是 `/var/...` 而 `realpath` 给 `/private/var/...`，导致合法路径被误判 `path_outside_workspace`。→ 测试里对 workspace 先 `realpathSync`；并把这条写进 `docs/03` 教训（一行）。
- `--page-size` 默认 `a4`，非法值 `invalid_input` exit 1。

**D4 长图必须是「整页」而非「首屏」**
长图高度用 `Page.getLayoutMetrics` 的 `cssContentSize.height` 取，再 `Emulation.setDeviceMetricsOverride` + `Page.captureScreenshot{captureBeyondViewport:true}`。要有**高度上限**（默认 20000px，超出按 `--max-height` 截断并在 `--json` 里 `clipped:true`），否则 100 页文档会 OOM。宽度默认 1200，`--scale` 1–3。

**D5 `--out` 一套规矩，不许分叉**
`hr pdf`/`hr png` 必须复用 `assertOutInsideOf` + `writeAtomic` + `--force`/`file_exists` 的既有语义（同 M4.3）。**禁止**各自再写一份路径判定。产物先写临时名再原子改名（`writeAtomic` 已具备），渲染失败时**盘上零残留**。

**D6 进程卫生**
- Chrome 必须带 `--user-data-dir=<临时目录>`（否则复用用户 profile，污染 + 单例冲突）。
- 任何一条退出路径（成功/超时/异常/信号）都要 `kill` 子进程 + `rmSync` 临时目录；`finally` 里做，不许靠 `process.on('exit')`。
- **`--headless=new` 会 fork 渲染子进程**，只 `kill` 主 pid 会留孤儿占住 `--user-data-dir`：子进程必须 `spawn(..., {detached: true})` 并 `process.kill(-pid, 'SIGTERM')` 杀整个进程组。自检命令：`pgrep -af 'remote-debugging-port|hr-chrome' || echo clean`（应为 clean）。
- 超时默认 60s，`--timeout` 可调（1s–600s），到点先 `SIGTERM`，2s 后 `SIGKILL`。

**D7 裸类型 + 可读性**
所有对外函数单对象入参、返回命名对象；无 `any`/`as`/可选参数默认值；注释只写签名看不出的事（"为什么 2s 后 SIGKILL"、"为什么 PNG 宽高要读 IHDR 而非用 Chrome 返回值"），**不许**写"这里渲染 PDF"这类复读机注释。

## §15 v4 裁定（测试员真机发现后，2026-11-17）

1. **`--page-size` 必须真重排，不许只换纸**。实测现状：三档纸张版心全是 A4 的 658×971 CSS px，a5 右缘被纸边切断。→ `print-css.ts` 的 `@page` 参数化（`printCssOf(pageSize)`），`print-html.ts` 入参加必填 `paper`，CLI 传入。A4 产物必须与 M4.3 逐字节一致（快照钉住）。
2. **补三个存活变异体的用例**：
   - M04 `process.kill(-pid)` → `kill(pid)`：需要一个能真正区分"杀进程组"与"只杀主 pid"的假 chrome（`fake-chrome.mjs` 里 fork 一个每秒 touch 标记文件的孙进程，断言主进程死后孙进程在一个 tick 内也停）。
   - M12 页数正则 `[^s]` → `\b(?!s)`：需要一个**以 `/Type /Page` 结尾**的 PDF 字节夹具（无尾随换行），断言页数不含 `-1`。
   - M17 不 `await loaded`：需要一个"`Page.navigate` resolve 但 `Page.loadEventFired` 晚 200ms 到"的假传输，断言渲染在 load 之后才 `printToPDF`（否则截图/打印会拿到半渲染页）。
3. **stderr 缓冲必须有上限**（P1 真机缺陷）：实测 50 MB stderr 洪流把 RSS 从 114 MB 抬到 553 MB，且 `session.ts` 的 `buffer += text` 永不封顶、resolved 后监听器不摘。要求：只保留**前 64 KiB**（够了：DevTools 行在开头、错误首行在前 200 字），超出直接丢；结束/成功后摘掉 stderr 监听器。
4. `chrome_failed` 的 stderr 首行仍按 D2 截 200 字，不受 64 KiB 上限影响。

## §16 v5 裁定（测试员 png 首轮，2026-11-17）

测试员真机实测推翻了三处实现假设，全部**必修**：

1. **`--max-height` 根本没裁**（P1）：`cdp.ts:255-268` 只把 height 塞进 `setDeviceMetricsOverride`，`Page.captureScreenshot` **没传 `clip`**，`captureBeyondViewport:true` 直接出整页。实测 `--max-height 2000` → json 报 `2400×4000 clipped:true`，IHDR 实为 **2400×9322**（与不裁剪那档字节完全相同）。
   → 截图必须带 `clip:{x:0,y:0,width,height,scale}`。
2. **上报的 height 是陈旧视口值**（P1）：`getLayoutMetrics` 在 `setDeviceMetricsOverride` **之前**调，`--width ≤ ~300` 时实测 IHDR 7229 vs json 4661。
   → 顺序改为 `setDeviceMetricsOverride({width, height: 1000})` → **重新** `getLayoutMetrics` → 再 `setDeviceMetricsOverride` 到真实高 → 截图；且 `width/height/clipped` **一律从 IHDR 反读**，不许自算。
3. **像素上限按 CSS px 算，Chrome 会崩**（P0/P1）：19929 CSS px 内容 `--scale 2`（2400×~40000 设备像素）稳定 `chrome_failed：Page.captureScreenshot 失败：连接已断开`，exit 3。
   → 新增硬闸：设备像素 `width*scale ≤ 16384` 且 `maxHeight*scale ≤ 16384`，且总像素 `≤ 2.5e8`；超限 **`invalid_input` exit 1**（文案给「请降 `--scale` 或 `--max-height`」），不许把 Chrome 打死。`--scale 3 --max-height 50000` 必须被这条挡住。
4. **`--max-height` 边界语义**：`max-height == 内容高` 应 `clipped:false`；`> 内容高` 也不裁。
5. **覆盖基建 flake**（卡 AC-7）：全量 `vitest run --coverage` 两次 `ENOENT coverage/.tmp/coverage-N.json`，并出现 `chrome-session*.test.ts` 的 `TypeError: detach is not a function`（单跑绿、全量崩），且失败时在 `$TMPDIR` 留 11 个空 `hr-chrome-*`。
   → 查清是**并发 worker 争抢 fake-chrome 状态目录**还是 coverage 目录竞态；修法优先「每个测试独占 `mkdtemp` + 唯一 fake 模式」，不许用 `--no-threads` 掩盖。

## §18 v7 · 终审后两份判决的处理（协调者裁定）

终审：审计 **APPROVE WITH NOTES**（无 P0/P1）、测试 **PASS WITH NOTES**（3 次全量 CI 全绿）。其中四条进 R7 返工：

1. **单边像素闸 16384 被实测证伪**：真 Chrome 出过 `1200×76663`。→ `PIXEL_EDGE_LIMIT` 改 **65535**，真实上限交给面积闸 `2.5e8`。
2. **预检面积误拒**（测试 P2）：`--width 4096 --scale 3` 因**默认** `maxHeight=20000` 被算成 737M 而拒。→ 宽度单边闸永远查；面积闸预检**仅当用户显式传 `--max-height`**（`args-png.ts` 增 `maxHeightExplicit: boolean`）；面积闸终检（量到真实高后）永远查。
3. **内部不一致不能报用户错**（审计 P2-2）：`assertShotWidthOf` 的错码 `invalid_input` → **`chrome_failed`**；补同形状的 `assertShotHeightOf`（`IHDR.height === clipHeight × scale`）。
4. **短文档被撑到 1000px 留白**（审计 P2-1，真缺陷）：`MEASURE_HEIGHT=1000` 对短文档量成视口高。→ `contentHeight <= MEASURE_HEIGHT` 时以高度 100 重新落视口再量一次；短文 IHDR 高不得为 1000。

**AC-9 的自检命令改写**（原写法会匹配执行它的 shell 自身，假阳性）：
`pgrep -fl 'hr-chrome-|remote-debugging-port=0?[1-9]' ; ls -d "$TMPDIR"/hr-chrome-* 2>/dev/null` —— 以「无 `hr-chrome` 命名的进程 + 无临时目录」为准；IDE 自带 `--remote-debugging-port=0` 属噪声，不算违规。

**P3 观察（记录不动）**：量高后二次改视口对 `vh` 内容的回流；`onExit`/`onError` 两条 detach 无 `listenerCount` 断言；脚本入口是 `pnpm test:e2e`（`package.json:18`），无 `pnpm e2e`。

### §18.5 协调者授权

`vitest.config.ts` 增 `reportOnFailure: true` 以修 `coverage/.tmp` 的 ENOENT 假红（§16.5），属卡片 §6 允许清单外的**协调者批准例外**。
