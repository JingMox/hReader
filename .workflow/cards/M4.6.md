# M4.6 验收网加固（把「记录在案的洞」变成门禁）

立卡：2026-11-18（协调者，M4.2 结卡后）。上一卡 `d536a4b`→M4.2 结卡提交 `d537b5a`（state.md 记 `d736a4b` 为其 amend 前 short sha，以 `git log` 为准）。

## 1. 为什么开这张卡

M4.2 八轮返工挖出的问题，**没有一条是"打字错"**，全是"我们的判据不成立"。其中六条已经写进 `docs/03` §11.45–§11.50，但**它们目前只是文档**：下一个写者不知道、CI 也不查。本卡把这六条里能自动化的部分变成**可执行门禁**，把不能自动化的部分变成**可指认的样本**。

## 2. 目标（四项，全部可判定）

**G-1 `verify` 与 `ci.yml` 步骤对齐检查（§11.49 的工具化）**
- 新增 `scripts/check-ci-parity.mjs`：读 `package.json:scripts.verify`，按 `&&` 切步骤；读 `.github/workflows/ci.yml` 的所有 `- run: pnpm <x>`（排除 `install`）；断言**同序同集**，不一致时打印缺/多/乱序三张清单并非 0 退出。
- 挂进 `verify`（作为新的一步，放在 `format:check` 之后）与 `ci.yml` 的 `checks` job。**注意：这两处要同时改**，否则本卡自己就违反 G-1。
- 反例自检：临时从 `ci.yml` 删 `pnpm knip` → 脚本非 0 且指名 `knip` 缺失；改回 → 0。

**G-2 ICO 判据剩余无覆盖断言（`len >= 45`）**
- `packages/desktop/src-tauri/src/lib.rs` 的 `assert_valid_ico` 里 `payload.len() >= 45` 至今**没有独立样本**（现有 4 份样本由 size / DIB 长度 / IHDR / IEND 各自兜住）。
- 补第 5 份样本：PNG 签名 + IHDR 合法 + 以 IEND 结尾（满足 IHDR 与 IEND 两侧）但总长 < 45。用 `catch_unwind` 断言 panic 文本含该长度断言的措辞，证明**是它赢**。
- 若实测发现这条断言**不可能单独赢**（例如 IHDR+IEND 的最小合法组合必然 ≥ 45），则**删掉该断言**并在旁边注释写"最小 PNG 头尾已 ≥ 45，此断言不可达"——不许留不可达判据。

**G-3 `cargo test` 并行竞态（M4.2 遗留风险，唯一已知不稳定项）**
- 症状：`cargo test` 并行下 `packages/desktop/src-tauri/src/signals.rs` 的 `tests::r1_watch_with_reports_each_signal_it_registers` 偶发红，根因是全局 `reset_for_test()` 被并发用例互踩。
- 要求：**不改断言强度、不放宽 CI**。二选一：① 测试改为每个用例独占的句柄（把全局状态做成 `OnceLock`/`Mutex` 守护的 `TestSignalHub`）；② 给该模块的测试加 `serial` 语义（`--test-threads` 只能全局设，故优先 ①）。
- 判据：`cargo test` 连跑 10 遍全绿，且把 `reset_for_test()` 调用删掉后至少一条用例红（证明它还在被用）。

**G-4 §11.47 的 `lint:sh` 守卫固化为负样本**
- 现有 `lint:sh` 已能对坏脚本/缺目录/空集三者非 0（M4.2 R5/R7 实测）。缺的是**让它每次都被验一次**：新增 `scripts/lint-sh-selftest.sh`，在临时目录里造 ①语法错脚本 ②空目录 ③不存在目录，逐个跑 `bash -n`/`lint:sh` 断言非 0，然后返回 0；挂进 `verify`（`lint:sh` 之后）。
- 判据：把 `package.json` 的 `lint:sh` 改回旧的 `find … -exec … +` 写法 → selftest 必须红。

## 3. 非目标

- 不碰 `launchParentPid` 幸存者（采集时机缺陷，单测层不可达，M4.2 已裁定接受）。
- 不碰 `serve-helpers` 的 `hasRef` 兜底分支（覆盖它需要 mock 私有符号）。
- 不新增运行时依赖；不引 `serial_test` 之类的 dev 依赖（用标准库能解的用标准库）。
- 不动阅读器/导出链业务代码。

## 4. 验收方式

1. 审计员逐项判 G-1…G-4 的判据是否**真能红**（每项都要看反例证据，不看声明）。
2. 测试员独立跑：`pnpm verify` 两遍、`pnpm desktop:check` 两遍、`cargo test` 10 遍；并尝试绕 G-1/G-4 的新门禁（改 `verify` 顺序、删 `ci.yml` 一步、把 selftest 短路）。
3. 全量门禁双绿 + 反例三连记录进报告，方可结卡。

## 5. 门禁

`pnpm verify` EXIT=0（265 文件 / 2971+ 例 / 四维 perFile 100%）+ `pnpm desktop:check` EXIT=0（cargo 80+ 例）。两处都要贴退出码，不许用"verify 绿"代表"全绿"（§11.49）。

## 6. 协调者裁定（D1–D10，2026-11-18，答复 G0 的 A-1…A-10）

依据 `.workflow/reports/spec-M4.6.md` §4。**裁定即施工口径，写者不得自行更改；有异议先回报，不许边做边改。**

- **D1（A-1）** `scripts/check-ci-parity.mjs` 用 **`.mjs`**，同时把 `knip.json` 的 root entry 加 `scripts/**/*.mjs`（两处同改）。不引 ts-node/tsx，不把 `scripts/` 塞进 `tsconfig.json`。
- **D2（A-2）** parity 在 `verify` 里**紧随 `format:check`**（`i === f + 1`），越早红越省墙钟。
- **D3（A-3）** `checks` job 只认整行 `- run: pnpm <script>`（`^\s*- run: pnpm [^\s]+$`）；**白名单仅一条**：`pnpm install --frozen-lockfile`（跳过比对）。其余带参数形态 → 非 0 并指名"无法解析"。`desktop` job 整块不参与。
- **D4（A-4）** 多行 `run: |` **禁止**，fail-closed（非 0 + "不支持多行 run"），理由写进脚本头注释：§11.47-2，判据必须是退出码，不许静默跳过。
- **D5（A-5）** parity 也配 selftest：脚本支持 `--ci <path>` / `--verify <path>`（默认指仓库文件），selftest 用 `/tmp` 副本跑四个反例（缺步/多步/乱序/恒真断言）。+1 步、≈0.2s 值得。
- **D6（A-6）** `lint:sh` 的根**扩成 `scripts`**（`find scripts -name '*.sh'`），让 `scripts/*.sh` 与新 selftest 自身都被 `bash -n` 覆盖；**不选**"首行自证"，也不把 selftest 塞进 `scripts/gui/`。
- **D7（A-7）** selftest 支持 `LINT_SH_CMD` 环境变量覆盖（默认从 `package.json` 读），使"换回旧写法必红"成为**只读**命令，可进 CI。
- **D8（A-8）** G-3 采**方案①（每用例独占句柄的测试夹具）**，`reset_for_test()` 随之删除；等价判据 = 删掉独占入口后 `cargo test --lib` 至少 1 条红。
- **D9（A-9）** `cargo test` 10 遍由**协调者收口跑**（禁止与 `verify` 并发，§11.50），允许 `--test-threads=8` 施压；30 轮为可选项。
- **D10（A-10）** 新脚本**不要求**进覆盖率（不改 `vitest.config.ts` 的 `include`）。

**另两条据 G0 证据修正卡面**：
