## v3 修订（协调者裁定 G2-R 的 2 个新 P1 + 4 条 P2，2026-11-12）

20. **meta 白名单 = 文档化三字段**（P1-R1，**推翻了 #16 的"只认 annotations"**）：`hr-meta` 顶层合法字段就是 `docs/02:100-104` 的 `version`、`style`、`annotations`。`KNOWN_FIELDS` 必须收录这三个；三者之外的键 → 诊断 `invalid_meta`，报文列出"只接受 version / style / annotations"并点名字段。**只校验顶层键名，不校验值形状**（`style` 内部结构留给 M1.9）。理由：白名单式可确定、可测；编辑距离式会随文档演进误伤。
21. **删掉不可达臂**（P1-R2）：`truncate.ts:122` 的三元表达式在 `prefix` 非空时 `fits(...)` 恒真（`prefixThatFits` 的二分不变量保证），`"none"` 臂不可达，导致 branches 100% 门结构性不可满足。改成 `prefix` 非空即 `return "partial"`；**禁止**用 `/* istanbul ignore */` 掩盖。
22. **`stripped_shell` 报文覆盖两类**（P2-R2）：计数已含子树 `script/style/template`，文案改成"已剔除 N 处不可读内容（页面外壳 / 可执行容器，见 readNode 的不可读清单）"，不再只写"页面外壳锚点"。改文案后由测试员同步 2 条逐字断言。
23. **契约 1 补入参前置条件**（P2-R3）：`#id`/`[data-hr-id]` 选择器要求 `parsed` 来自 `injectNodeIds(...).parsed`；裸 `ParsedHtml` 只支持 `tag` 与 `nth-of-type` 形态（`#id` 退化为 `node_not_found`）。写进卡片契约与函数注释一句话（这是签名表达不了的），供 M1.5 CLI 遵循。

## v2 修订（协调者裁定审计 P0-1/P1-1..3 + 4 条 P2，2026-11-12）

10. **截断以"元素可进入"为准**（P0-1）：判定改成「开标签 + 预留给自身闭合标签」能否装下；能装下就进入并按预算裁子节点。只有**开标签单独都装不下**才整块丢弃。禁止"子树整体装不下就返回空壳"——那会让读 `<article>` 在正常大文档下返回 35 字节空内容。
11. **`maxBytes` 下限写进契约**（P1-2）：`maxBytes < 开标签字节 + 闭合标签字节` → `HrError("invalid_max_bytes")`，报文必须给出该目标的最小可行值。**禁止**返回空串、**禁止**输出超预算。
12. **路径约定统一为"子节点序号"**（P1-1）：`resolve.ts` 必须与 `src/html/inject.ts` 使用同一套索引（子节点序号，不是同名兄弟序号）。允许新增 `src/html/path.ts` 作为**唯一**路径生成函数，`inject`/`validate`/`resolve` 三处都调用它（`inject` 只改调用点、不改输出字节）。加栅栏测试：同一节点的 resolve path 与 M1.1 诊断 path 逐字相等。禁止用字符串前缀以外的方式做子树判定（前缀法在统一后是可靠的）。
13. **内容级外壳同样剔除**（P1-3）：`script`/`style`/`template` 出现在目标子树内时，整块剔除并计入 `stripped_shell`（不只 `#hr-meta`/`#hr-theme`）；与"目标本身禁读"合起来才算真防护。
14. **`#id` 只认 `data-hr-id`**（P2-8）：删掉 `attrs.ts:13` 的 `id` 兜底——作者页面的 `id` 不得成为锚点（否则与 `hr-meta` 的 id 空间混淆）。`#x` 与 `[data-hr-id="x"]` 必须完全等价。
15. **入口形状校验**（P2-3/P2-7）：`readNode` 收到非 `ParsedHtml`（含把 `injectNodeIds` 的返回值直接传入）→ `HrError("invalid_input")`（第五个码），不许抛 `TypeError`。
16. **meta 字段名写错要说话**（P2-2）：`hr-meta` 里存在 `annotations` 之外的疑似字段（如 `pending_annotations`）→ 诊断 `invalid_meta`（沿用 M1.3 码），报文点名字段。
17. **报文措辞**（P2-5）：`truncated_output` 的"原 N 字节"必须写"序列化后"。
18. **BNF 注明大小写**（P2-1）：属性名比较是大小写不敏感（HTML 语义），BNF 注释里写清。
19. **卡片措辞修正**：契约 3 的"目标若 script/style/template → node_not_allowed" 与 #13 合并理解为「目标禁读 + 内容剔除」，实现按 #13 执行。

## 契约

1. **签名（裸类型，抛 `HrError`）**
   ```
   readNode(parsed: ParsedHtml, target: string, maxBytes: number): ReadNodeResult
   ReadNodeResult = { html: string; annotations: readonly PendingAnnotation[]; truncated: boolean; diagnostics: readonly Diagnostic[] }
   ```
   - `maxBytes` 默认 `65536`，由调用方显式传或省略（默认参数即可，**不要**造 options 对象/类）。
   - 错误码（`HrError`，跨入口 `instanceof` 必须成立）：`node_not_found`、`invalid_selector`、`node_not_allowed`。**只有**这三种走异常；其余全部进 `diagnostics`。
2. **选择器**（AC2）——**只支持这 4 种形态，其余一律 `invalid_selector`**（不允许"尽力而为"）：
   ```
   #<id>                        // 等价于 [data-hr-id="<id>"]
   [data-hr-id="<id>"]          // 单引号/无引号也接受同一 id
   <tag>                        // 全文档第一个该标签（文档顺序）
   <tag> > <tag> :nth-of-type(<n>)   // 单层子选择器 + 精确序号，n >= 1
   ```
   - 解析必须**手写窄文法**（逐字符扫描），不得引入 CSS 选择器库；`>` 两侧空格可选；属性值里的 `"` 不许未转义嵌套。
   - 非法：空串、`..`、逗号、通配 `*`、伪类除 `:nth-of-type` 之外、`nth-of-type(0)`/负数/非整数、括号不配对。**返回 `invalid_selector` 异常**，不抛裸 `SyntaxError`。
   - 多个匹配（如 `section`）：取**文档顺序第一个**，其余进 `diagnostics`（`ambiguous_selector`，报文含总数）。
3. **不泄漏外壳**（AC3）：`html`/`body`/`head`/`script#hr-meta`/`style#hr-theme` 永远不可读 → `node_not_allowed`。
   - 目标节点若是 `<script>`/`<style>`/`<template>`（其他 id）→ `node_not_allowed`。
   - 目标节点是 `<article>` 本身 → **允许**（返回 article 子树），但其中嵌套的 `<script id="hr-meta">` 必须被**剔除**且产生诊断 `stripped_shell`（新码）。
4. **输出**（AC1）
   - `html` = 目标节点的**子树 HTML**（复用 `serializeHtml`，不得另写序列化）；不含目标节点自身的 `data-hr-id` 属性？——**保留**（它是调用方定位锚点），但**不**输出页面外壳。
   - `annotations` = `hr-meta` 中 `targetId === 目标 id` 的所有批注（**不限** `status`，与 M1.3 的 `pending_*` 过滤不同；这是刻意差异，报文/文档要写清）。目标 `id` 未知（按 `tag` 选中）→ `annotations: []`。
   - `diagnostics` = 读取过程中的全部可恢复问题（含 M1.3 的 `outline_*` 之外的新码，见 5）。
5. **截断**（AC4）
   - 序列化后字节数（UTF-8）> `maxBytes` → 截断到**码点边界**（不得切坏代理对/组合字符），`truncated: true`，并保证输出仍是**可解析的 HTML 片段**（在元素边界截断 + 补齐闭合标签；若单元素本身就超限，允许输出其自身开标签 + 文本前缀 + 闭合标签）。
   - 截断后 `html` 前缀必须保留目标节点的开标签（调用方能识别是哪个节点）。
   - 诊断 `truncated_output`（新码），报文含"原 N 字节 / 上限 M 字节 / 已保留 K 字节点"。
   - `maxBytes <= 0` → `HrError("invalid_max_bytes")`? **不需要**：按契约 2 一律进诊断会掩盖调用方 bug，故这里**允许**第四个错误码 `invalid_max_bytes`（非整数、≤0、> 16MB）。
6. **新诊断码**（窄联合扩容）：`ambiguous_selector`、`stripped_shell`、`truncated_output`。除这三个外不得新增；`Diagnostic` 五字段形状不变。
7. **确定性**：同输入两次 `html` 逐字节相等；`annotations` 按 `hr-meta` 数组顺序（不排序）；`diagnostics` = M1.1 段的**相关子集**（只保留落在目标子树内的）+ 本卡诊断（文档序），跨段顺序不做全局排序（与 M1.2 v3 #10 同口径）。
8. **性能**：1MB 文档 + 读取 64KB 子树 ≤ 60ms；读取 `<article>` 全量（1MB）时截断路径 ≤ 120ms；不得为了算字节数把整个结果 `Buffer.byteLength` 反复算 3 遍（原始实现常见问题）。
9. **代码形态**：文件 ≤ 400 行、函数 ≤ 40 行、复杂度 ≤ 10、模块头 ≤ 3 行；两级门面；无 `any`/`as`/`!`；注释只写签名表达不了的东西（选择器文法、截断策略、复杂度上界），**不许出现卡号/审计编号**。

## 审计重点

选择器是否真的窄（能不能用 `:not()`/属性选择器绕过读 `hr-meta`）；`#id` 与 `[data-hr-id]` 是否真同义（文档里 `id` 属性与 `data-hr-id` 混用时）；`nth-of-type` 是否按"同胞中同类型"而非全局计数；泄漏面（`article` 内嵌套 `hr-meta`、`<template>` 内容、注释里的 HTML）；截断是否可能产出 `</div>` 不配对导致调用方拼回文档时破坏结构；`truncated` 与 `diagnostics` 是否可能矛盾（`truncated: false` 但仍 `truncated_output`）；批注是否错误过滤掉 `resolved`；性能是否有 O(n·m)。
