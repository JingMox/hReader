# M1.8 · CLI `hr`

> 依据：`docs/05-feature-cards.md` §M1.8（AC1–AC6）、`docs/02:224`（`hr.mjs` 零配置封装）、`docs/04` §4/§6（无隐式状态；`cli/` 只做编排与格式化）。
> 原则：CLI 是**薄适配层**——只允许读 argv、调 core、格式化输出、映射退出码；**不允许**任何 HTML/CSS/YAML 逻辑。

## 0. 结构与依赖

- 新包 `packages/cli`，`name: "@hreader/cli"`，`bin: { "hr": "./src/main.ts" }`（开发期直接跑 TS，`node --experimental-strip-types`；**不引入构建步骤**，与 M1.0 一致）。
- 唯一依赖：`@hreader/core`（workspace）。**不引入** argv 解析库——面很小（4 条命令、固定 flag），自写 `parseArgs` 纯函数更好审计。
- 目录：
  ```
  packages/cli/src/
    main.ts         入口：argv → 分发 → 退出码（唯一调用 process.exit 的地方）
    args.ts         纯函数 argv 解析（不读 process.argv）
    commands/{outline,read,patch,style}.ts   每个命令一个文件，纯函数 (input, deps) => Promise<Result>
    output.ts       人读格式化 + JSON 序列化（唯一碰 stdout 的地方）
    usage.ts        --help 文本（单一来源，测试直接 import 断言）
    exit-codes.ts   code → 退出码映射表
  ```
- `args.ts` / `commands/*` 不得 import `node:process`；`process` 只允许出现在 `main.ts`、`output.ts`。

## 1. 命令与参数（AC1）

```
hr outline <file> [--json]
hr read <file> <nodeId|selector> [--json] [--max-bytes <n>]
hr patch <file> <nodeId> --action <replace|insert_before|insert_after|append|delete> (--html <s> | --html-file <p> | --html-stdin) [--json]
hr style <file> (--visual <id> | --tone <id> | --lint) [--json]
hr --help | hr <cmd> --help
```

裁定：
- `--html-stdin` 是新增（AC1 未列，但 Agent 管道必需）：读 stdin 全文作片段。三选一**互斥**，同时给两个 → 用法错误（exit 2）。
- `delete` 与任何 `--html*` 同用 → 用法错误（exit 2），不是 `invalid_input`（在 CLI 层就拒，不进 core）。
- `--max-bytes` 只对 `read` 有效，非法值（非正整数/超 1e7）→ 用法错误。
- `--json` 可出现在任意位置；未知 flag → 用法错误并打印该命令的 usage。
- 位置参数多余 → 用法错误。
- 文件路径一律相对 cwd 解析，但 `--workspace` 可选（默认 `process.cwd()`），`patch`/`style --visual` 用它做路径安全边界；`outline`/`read` 只读，不校验 workspace。

## 2. 退出码（AC2，冻结表）

| 退出码 | 触发 | 例子 |
|---|---|---|
| `0` | 成功（含 `--help`） | — |
| `1` | 可预期业务失败 | `node_not_found`、`no_article`、`invalid_selector`、`invalid_fragment`、`forbidden_content`、`style_not_found`、`invalid_style`、`locked`、`undo_unavailable` |
| `2` | 用法错误（CLI 层，非 HrError） | 未知命令/flag、缺参数、互斥冲突 |
| `3` | IO/权限/路径 | `path_outside_workspace`、`not_a_file`、`io_failure`、`invalid_utf8` |
| `70` | 内部错误（未捕获的非 HrError） | 断言失败、bug |

- 映射表放 `exit-codes.ts`，**穷尽** `HrErrorCode`（`satisfies Record<HrErrorCode, number>`），新增 code 不改表就类型报错。
- `70` 路径：打印 `message` 到 stderr，**不打印 stack**（`--debug` 除外，见 §4）。

## 3. 输出契约（AC3/AC4）

- **stdout 只放结果**；诊断、进度、警告一律 stderr。
- 无 `--json`：人读文本（`outline` 是缩进树，`read` 是 HTML 原文，`patch` 是 `patched <file> (<n> bytes, +<k> ids)`，`style --lint` 是每行 `<nodeId>: <word> — <excerpt>`，`style --tone` 是编译后的 prompt 原文）。
- `--json`：**单行**（无缩进、无尾随空格）合法 JSON + 恰好一个 `\n`；键序固定（手写序列化，不用 `JSON.stringify(obj)` 的隐式键序）。
- JSON 形状（冻结）：
  ```json
  { "ok": true,  "data": { ... } }
  { "ok": false, "code": "node_not_found", "message": "…" }
  ```
  - 错误 JSON 在 `--json` 下输出到 **stdout**（Agent 只读 stdout 也能解析），同时把同一 message 写 stderr；非 `--json` 时 stdout 为空。
- 无颜色码、无 ANSI 转义，任何情况下都不做 TTY 探测（管道/终端一致）。
- `data` 字段按命令固定：`outline` → core 的 `Outline` 原样；`read` → `{ html, ids }`；`patch` → `{ path, bytes, newIds, changed, historyPath }`；`style --tone` → `{ prompt }`、`style --lint` → `{ hits }`、`style --visual` → `{ path, changed }`。

## 4. `--debug`

- 仅在设置 `HR_DEBUG=1` 时输出 stack 到 stderr；这是**唯一**允许读环境变量的地方，且在 `main.ts` 顶层解析后作为参数传下去（`docs/04:19` 允许边界解析）。

## 5. 新增错误码

| code | 触发 |
|---|---|
| `invalid_utf8` | 读文件/`--html-file`/stdin 时解码失败（`TextDecoder({fatal:true})` 抛错） |

`invalid_utf8` 归 exit 3（IO 类），进 `exit-codes.ts` 映射表。

## 6. 非目标

- 不做 `serve`/WebSocket（M2）、不做 `--watch`、不做 shell 补全、不做配置文件（`.hreader/config`）。
- 不做彩色输出、不做进度条。
- 不打包二进制、不发 npm（M1 内部）。`skills/hreader/scripts/hr.mjs` 是 M1.9 的薄封装，不在本卡。

## 7. 门禁（本卡额外）

1. `pnpm verify` EXIT=0，四维 100%（含 `packages/cli`）。
2. **真子进程**跑 CLI（`node --experimental-strip-types packages/cli/src/main.ts …`），**不**直接 import `main()` 做单测；5 个退出码各至少 2 条用例（成功/失败）。
3. `--json` 输出：`JSON.parse` 通过 + 单行（`\n` 计数为 1）+ 键序与 §3 一致 + 错误路径也有合法 JSON。
4. `--html-stdin`：`echo '<p>x</p>' | hr patch …` 真管道测试；stdin 为空 → 用法错误。
5. 非法 UTF-8（`Buffer.from([0xff,0xfe])`）→ exit 3 + `invalid_utf8`，且目标文件字节不变。
6. `--help` 覆盖所有命令与 flag（测试断言 usage 文本包含每个 flag 字面量）；`hr` 无参数 → exit 2。
7. 管道无 ANSI：断言 stdout/stderr 字节中不含 `\x1b`。
8. 变异体 ≥5（含：错误 JSON 走 stderr、退出码表用默认 1 兜底、`--json` 用 `JSON.stringify` 的隐式键序、`delete` 带 `--html` 被静默忽略、`--help` 返回 exit 2）。

## 8. 合并 M1.9（Universal Skill 壳）— 协调者裁定，2026-11-13

本卡**合并原 M1.9**：Skill 壳的唯一依赖是 CLI，分开做要付两套门禁。新增交付面：

### 8.1 交付物
- `skills/hreader/SKILL.md`：触发条件、五原语工作流、7 个组件选择器 HTML 速查、禁用词提醒。**≤ 200 行**，中文。
- `skills/hreader/scripts/hr.mjs`：零依赖封装，`node skills/hreader/scripts/hr.mjs outline <file>` 直接可跑。
- `skills/hreader/references/components-spec.md`：每个组件的**完整可用片段**，复制即用。
- `skills/hreader/references/style-authoring.md`："访谈式"生成自定义 `style.yaml` 的流程。

### 8.2 预设裁定（不要再讨论）
| # | 裁定 | 理由 |
| --- | --- | --- |
| 1 | `hr.mjs` **不打包、不复制** core 代码：它 `spawn` 一个 `node --experimental-strip-types <repo>/packages/cli/src/main.ts` 子进程，退出码原样透传 | 零依赖 + 单一事实源；复制一份 CLI 逻辑给 skill 用，等于两份会漂移的实现 |
| 2 | `hr.mjs` 用 `import.meta.url` 解析自身路径，**不读** `process.env.HR_ROOT` | 可移植；环境变量越多，Agent 里越容易配错 |
| 3 | 仓库路径含空格/中文必须可用（`spawn` 传数组参数，不拼 shell 字符串） | 用户目录常见情形 |
| 4 | `bin` 指向 `src/main.ts`，但**不加 shebang**：M1 用 `node --experimental-strip-types` 调用；npm 全局安装留到首发 | 加 shebang 会让人以为可直接执行，实际 Node 会因 strip-types 报错 |
| 5 | `components-spec.md` 的组件 id **必须**与 `docs/02` §组件库逐字一致（`callout/insight/warning/quotes/table/specs/steps/compare` 的确切集合以 `src/html/constants.ts` 为准），并由测试用例交叉校验 | 文档与代码漂移是本项目已知风险 |
| 6 | `references/*.md` 里的代码片段**必须**能在 `hr patch` 里原样通过（测试逐段抽出喂 CLI） | "复制即用"是可执行承诺，不是排版承诺 |
| 7 | SKILL.md 用 YAML frontmatter（`name`、`description` 两键），正文不重复 docs/02 的长表 | 触发靠 description；正文超 200 行 Agent 读不完 |

### 8.3 AC5（浏览器验证）拆分 —— 诚实边界
原 AC5 要求"headless 浏览器断言计算样式"。本仓库**不引入 Playwright**（M1 无此预算，且 CI 需浏览器二进制）。改为：

- **AC5a（CI 内，测试员执行）**：临时目录端到端——生成含 3 组件的 HTML → `hr outline` → `hr read` → `hr patch` 重写一段 → `hr style --lint` → `hr style --visual`，逐步断言退出码、stdout 形状、目标文件字节变化、以及**最终文档能被 `parseHtml` 重新解析且往返稳定**；再交叉断言：文档里用到的每个 `data-hr-component` 与 `class` 在主题 CSS 里都有对应选择器（缺一个就红）。
- **AC5b（人工，不进 CI）**：真浏览器目视 + 截图，记录在 `.workflow/reports/manual-visual.md`。**不允许**伪造截图或用 DOM 库冒充布局断言。M2.1 UI 落地时再自动化。

### 8.4 门禁补充
- `pnpm verify` 必须把 `skills/**` 纳入：`prettier --check`、markdown 行数检查（SKILL.md ≤ 200）、`hr.mjs` 的 `node --check`。
- `packages/cli` 的覆盖率同样 perFile 100%：`main.ts` 的 `process.exit` 分支用**子进程**测（不进覆盖率分母的写法要说明）。
