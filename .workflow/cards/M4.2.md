# M4.2 桌面卡：Tauri v2 桌面壳（`@hreader/desktop`）

> 协调者立卡前的侦察结论全在 §1，**写者不要重跑侦察**；§5 的 AC 由测试员 G0 先扩成矩阵再开工。

## 1. 事实基线（协调者已实测）

- **工具链在手**：`cargo 1.98.0` / `rustc 1.98.0`；`npx @tauri-apps/cli@2 --version` → `tauri-cli 2.12.5`；已装 target 只有 `aarch64-apple-darwin`（外加 musl/thumb，与本卡无关）。**crates.io 可达**（`cargo add tauri@2 && cargo fetch` 真实下载成功，不是只写进 Cargo.toml）。
- **阅读器现形态**：`@hreader/app` 的 `build` 产 `dist/index.html` + `dist/assets/{index.js,styles.css}`（`packages/app/scripts/build-static.mjs` 明写：`daemon 静态托管 dist/`，`/` → index.html，`/assets/*` → dist/assets/*）。
- **守护进程**：`hr serve`（`packages/cli/src/commands/serve.ts`）薄适配 `@hreader/core` 的 `startServer`；`packages/core/src/server/server.ts` 负责装配/监听/SSE/`daemon.json` 生命周期，`packages/core/src/server/daemon.ts` 管 `~/.hreader/daemon.json`（原子写 + `0600` + 探活）。认证是 `cookie/token + host/origin` 白名单（`packages/core/src/server/auth.ts`）。
- **CI 现状**：`.github/workflows/ci.yml` 单 job `checks`，`ubuntu-latest` × node `[22,24]`；`pnpm verify` = `format:check` + `lint` + `typecheck` + **`build`** + `test:coverage` + `depcruise` + `knip`（**七步**，`package.json` 为准）。**没有 e2e job，也没有 Rust**。

### 1.1 G0 侦察后确认的关键事实（已由协调者逐条核过源码，写者直接采信）

- **`daemon.json` 里没有 docId**（`packages/core/src/server/contracts.ts:34-39`：`port`/`token`/`pid`/`workspace`）。
- **bootstrap 认证链**：`GET /` 是 `cookie` 级（`routes.ts:66`）；`?t=` **只在** `GET /s/:doc`（`routes.ts:67`，`token` 级）被认，命中后 302 到原 path 并 `set-cookie`（`server.ts:120-126` + `http-io.ts:196-200`）。**所以壳必须先导航 `/s/<docId>?t=<token>`，再进 `/`**——直接 `/?token=…` 必 401。
- **`/s/:doc` 接受 workspace 内任意 docId**（`runtime.ts:167-173` + `remember(docId)`），不限于 `startServer` 的初始文档——所以"复用已有 daemon + 换文档"在协议层可行。
- **`hr serve <file>` 必带一个文档**（`args.ts:170-176` 缺 file 直接报错）；`--port 0` 是默认值 = 自动分配（`args.ts:162-168`）；`--workspace`/`--allow-host`/`--app-dir` 已存在。
- **`home` 写死在 `homedir()`**（`packages/cli/src/run.ts:232`），**没有 `--home` 旗标**——所以壳拉起的 daemon 会覆写用户的 `~/.hreader/daemon.json`（`writeDaemonOf`/`removeDaemonOf`）。本卡批准补一个只对 `serve` 生效的 `--home <dir>`（默认仍 `homedir()`，行为不变）。
- **本卡前基线**：`02f2649`（M4.5.1 结卡），261 文件 2937 例，`pnpm verify` EXIT=0。

## 2. 非目标（写死在卡里，不许自行扩张）

1. **不做代码签名 / 公证 / 自动更新**（需要证书与 Apple ID，本地不可验）。
2. **不在本机声称"Windows/Linux 安装包已可用"**：这两个平台的 bundle 只能在 CI matrix 里产，本卡只要求 **配置就位 + 本地 macOS bundle 真产物**。
3. **不引前端构建链**：webview 只加载 daemon 托管的现有静态资源，`packages/app` 不加 bundler、不加框架。
4. **不改阅读器 UI**（`packages/app/**` 的 product 行为）、**不改 `packages/core/**` 的协议语义**、**不改 `docs/**`**（docs 由协调者改）。
5. 不做托盘菜单的完整交互（若做，必须能被 `--smoke` 之外的真机证据钉住，否则砍掉）。

## 3. 设计要点（写者有权改进，但改要向协调者报备理由）

### 3.1 协调者已裁定（这些不是建议，是决定）

- **D1 壳只用自己拉起的 daemon，且用隔离的 home**：壳调 `hr serve <doc> --workspace <ws> --port 0 --home <appData>/hreader`。**永不**读写用户的 `~/.hreader/daemon.json`，**永不**杀自己没拉起的进程。"复用活着的 daemon"只在**自己的 home** 里看 `daemon.json`（同进程重启、窗口重开）。
- **D2 bootstrap 走 `/s/<docId>?t=<token>`**（302 种 cookie）→ 再进 `/`。**不改 `packages/core` 的认证语义**。
- **D3 `.html` 关联 = 要服务的文档**：`--open <file>` / LaunchServices 传入的文件路径 → 作为 `hr serve <file>` 的文档；workspace 取 `--workspace`，未给则取文件所在目录。**没有 `hr import` 这个命令**，不要凭空发明导入流程。
- **D4 CLI 定位顺序**：`--cli-path` > 环境变量 `HREADER_CLI` > `PATH` 里的 `hr`。全部落空 → **非 0 退出 + 一行能看懂的错**（不许硬编码本机 node 路径，不许静默回退到 `node_modules`）。干净机器需要先装 `hr` —— 这条写进 `L-42`。
- **D5 `--smoke` 证据是三层**（单靠它不够，见 spec §A2）：① exit 0 且 stderr ≤ 2 行、**不含 48 字符 base64url**；② 打印"将导航的 URL"（token 段脱敏），**path 必须是 `/s/…`**；③ 一次人工双击 `.app` 看正文（协调者记时间戳，不追自动化）。
- **D6 只产 `.app`，不产 `.dmg`**（签名/公证是非目标，`.dmg` 只是包装，证据价值为零）。
- **D7 新增忽略规则**：`packages/desktop/src-tauri/target/`、`gen/` 必须进 `.prettierignore`/`.gitignore`/`knip.json`（必要时 `.dependency-cruiser.cjs`），否则 `pnpm verify` 会去格式化 Rust 构建产物。
- **D8 Rust 侧零豁免**：不许 `#[allow(dead_code)]`/`#[ignore]`/`#[allow(unused)]` 之类的"让它过"注释（与 JS 侧禁 `v8 ignore` 同一条原则）；`cargo clippy -- -D warnings` 必须干净。

### 3.2 待写者自行设计（但需报备）

- **分层**：Rust 纯逻辑（URL 拼装与脱敏、`daemon.json` 解析与探活判定、CLI 定位、`.html` 参数 → 动作映射、快捷键配置解析）与平台副作用（`tauri`/window/shell/global-shortcut）必须分文件，纯逻辑能 `cargo test` 且**不 require 真窗口**。
- **进程监督**：子进程必须在壳退出/崩溃时收拾干净（含异常路径）；daemon 就绪探测要有上限重试和超时报错，不许裸 `sleep`。
- **`--smoke` 是否建窗口**：你定，但卡在证据里要说清"smoke 证明了什么、没证明什么"。

> 以下为原设计初稿，保留供对照：**不要自造 webview 服务器**（壳 = 发现/拉起 `hr serve` → 导航）。不改阅读器 UI、不改 core 协议语义。

### R1-P1 · W2 启动窗口期父死失效（G3′ B5 FAIL，最高优先）

**现象**：壳在 `hr serve` 刚 spawn、还没 ready 时被 `kill -9` → daemon 的 `ppid` 已是 1，`startupParentWatch()`（`packages/cli/src/parent-guard.ts:29`）此时才读 `process.ppid`，把 **1 当成正常父 pid** 记下 → `parentGone` 永远 false → 孤儿 daemon 活 4s+、端口不还、`daemon.json` 残留（eval 原文见报告 §3.5，`ORPHAN 2974`）。

**要求**：
- 壳启动的 ppid 必须在**任何 `await` 之前**采集（`packages/cli/src/main.ts` / `run.ts` 顶部模块作用域常量），一路传到 `serveCommand`；`startupParentWatch()` 改成纯函数 `launchParentWatch(parentPid, readParentPid)`，不再在调用点自行读 `process.ppid`（排除"采集时机"这一类隐患）。
- `--exit-with-parent` 且启动时 pid 已是 1 → **立刻失败退出**（`BadDaemonFile` 式的可读错误，退出码非 0），不建服务、不写 `daemon.json`。未传 `--exit-with-parent` 时行为完全不变。
- 退出路径（含失败退出）都必须清掉自己写的 `daemon.json`；B1 里"壳死了但 json 残留"也要一起消失。
- 测试：单测钉"ppid===1 即判孤儿"、"采集值来自注入而非二次读取"、"失败退出不落 json"；**真机案必须复现 G3′ §3.5 那三条时间线**（0.03s/0.3s/0.6s 三个杀点）。

### R1-P1 · Windows 图标缺失（G3′ §3.9，未变异即可复现）

`packages/desktop/src-tauri/icons/` 只有 `icon.icns` + `icon.png`，`tauri-build` 在 Windows target 下要 `icons/icon.ico`，`cargo check --target x86_64-pc-windows-msvc` 直接红 → **Windows CI 首跑必红**。

**要求**：加 `icons/icon.ico`（16/32/48/256 四档，从 `icon.png` 生成，二进制入库）+ `tauri.conf.json` 的 `bundle.icon` 列表补上它；再加一条**仓内测试**断言 `.ico` 存在且 ICO 头合法（`00 00 01 00` + 目录项数 ≥4）——本机没有 Windows target，这条测试就是唯一守门人，报告里不许写"已在 Windows 验证"。

### R1-P2 · M2「安装点」结构性洞（G3′ M2 SURVIVED）

`signals::watch()` 挪到 `connect()` 之后，`cargo test` 69+3 全绿 —— 没有任何用例钉住"必须早于 connect"。

**要求**：把顺序做成**类型强制**而不是测试强制：`signals::watch()` 返回一个不透明 token（如 `SignalSubscription`），`connect_with(...)` 的签名**要求**传入该 token（`Option` 都不行，必须是非 `Copy` 的实参，移进去即消费）。于是"先 connect 后 watch"变成编译错误，`ac14_watching_twice_is_idempotent` 保留。若这条不成立（比如 `window::run()` 里确实需要二次安装），要在报告里写清为什么、以及替代的守门手段。

### R1-P2 · M6「语义面无 R 层用例」（G3′ M6b SURVIVED-R）

`serve.ts:44` 改成无条件 `watchParent(...)` 后，**只要给定时器加 `.unref()`** 就 634 条 R 层用例全绿，只有 S 层真进程案能杀。

**要求**：把"要不要看父进程"抽成纯判定（如 `serve.ts` 导出 `shouldWatchParent(input): boolean`），并加两条 R 层用例：①`--exit-with-parent` 缺省时**不建定时器**（假时钟 + 断言 `setInterval` 未被调用/无活跃 timer）；②传了才建。R 层用例要在 `.unref()` 变体下**依然变红**（写进报告：附那条变异的重跑结果）。

### R1-P2 · GUI 证据脚本入库（G2′ P2）

`impl-M4.2.md` 引用的 `/tmp/hr-gui/*.sh` 会被清空，评审不可复核 ⇒ 移到 `scripts/gui/m4.2/`：可执行、从脚本自身位置推仓根（不许硬编码 `/tmp` 或绝对路径）、token 从 `daemon.json` 现读不落盘、每个脚本头部一行说明用途。报告改引用仓内路径。**`pnpm verify` 必须仍绿**（注意 prettier/eslint 对 `.sh` 的影响，必要时加 ignore 并写明）。

### R1-P3 · `default_home()` 的 Windows 回退（G2′）

`lib.rs:267` 只读 `HOME`，Windows 常规只有 `USERPROFILE` → 回退 `"."` 会把 `daemon.json` 写进 cwd，正违背 W7。改成 `HOME → USERPROFILE → Err`（**不要再回退 `"."`**），`Err` 时给出可读错误；加注入 `USERPROFILE` 的单测。
