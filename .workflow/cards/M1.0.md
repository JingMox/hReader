# M1.0 · Monorepo 骨架与最严 CI

- 上游规格：`docs/04-engineering-standards.md` §5（CI/工具链）、§3（裸类型）、§2（注释）；`docs/02` §2（包边界）、§8（里程碑判据）。
- 目标：在干净 clone 上，`pnpm ci` 一次跑通全部检查；并且**这些检查真的会拦人**（负向验证必须有证据）。
- 本卡不写业务逻辑。

```

pnpm-lock.yaml
.npmrc

packages/app/{package.json,tsconfig.json,src/index.ts}

```

`Out of scope`（越界即 P0）：`tests/**`、`**/*.test.ts`、`docs/**`、`skills/**`、`styles/**`、`.workflow/cards/**`、`.workflow/state.md`。

## 契约

1. **workspace**：`packages/*` 五个包，全部 `"private": true`、`"type": "module"`、`"sideEffects": false`，包名 `@hreader/<dir>`，`exports` 指向 `./src/index.ts`（M1 不引入打包步骤）。
2. **TS 最严**：`strict`、`noUncheckedIndexedAccess`、`exactOptionalPropertyTypes`、`noImplicitOverride`、`noPropertyAccessFromIndexSignature`、`noImplicitReturns`、`verbatimModuleSyntax`、`isolatedModules`。禁止 `skipLibCheck: false` 之外任何"放宽"项；若某项与 vitest/ESLint 生态冲突，允许 `skipLibCheck: true`，但必须在报告里写清原因。
3. **ESLint**：flat config + `strictTypeChecked`；以下为 error：`no-explicit-any`、`no-non-null-assertion`、`consistent-type-assertions(never)`（禁 `as`）、`max-lines-per-function`(40)、`complexity`(10)、`max-depth`(3)、`max-params`(4)、`import/no-default-export`（配置文件除外，用 override 白名单）。**全仓库不得出现 `eslint-disable` / `@ts-ignore` / `@ts-expect-error`**（若必须，先问协调者）。
4. **边界**（dependency-cruiser，全部 error）：禁止环；`core` 不得依赖任何其他 `@hreader/*`；`renderer-html` 不得依赖 `chrome-extension`/`app`；`protocol` 只可依赖 `core`；`src` 不得 import `devDependencies`；不得 import 未声明的外部依赖。
5. **死代码**：knip 接入，entry 为各包 `src/index.ts`；不得用 ignore 压制真实问题（ignore 仅允许：`docs/**`、`skills/**`）。
6. **测试**：vitest 已配置（projects 指向各包 `tests/**/*.test.ts`），覆盖率 `perFile: true` 且四项阈值 **100%**，`include: packages/**/src/**`。M1.0 的测试由测试员写；你只保证配置可用（可临时用 `--run` 观察空集合行为，观察完删除临时文件）。
7. **CI**：`.github/workflows/ci.yml`，`ubuntu-latest` + node `22`/`24` 矩阵，`pnpm install --frozen-lockfile`，依次跑 `format:check`、`lint`、`typecheck`、`test:coverage`、`depcruise`、`knip`。所有脚本在根 `package.json` 里，`pnpm ci` = 上述 `&&` 串联。
8. **最小真实构件**：`packages/core/src/index.ts` 只允许放**后续每张卡都要用**的东西。本卡定为**错误基类**：一个 `HrError`（携带稳定的字符串 `code`，`instanceof` 可判断）及其 `code` 的窄联合类型。不得为凑 CI 造 `demo`/`hello`/占位常量。其余四个包的 `src/index.ts` 允许为空导出（`export {}`），但不得出现未被使用的导出。
9. **可读性**：所有配置文件顶部允许 1 行说明"这层管什么"；不得复制官方文档。

## 验收（自证，写进 impl-M1.0.md）

- `pnpm install` 后 `pnpm ci` 全绿，贴**真实输出**（含每个子命令的退出码）。
- **负向验证**（临时文件，验证后删除，贴证据）：① 源码里写 `const x: any = 1` → lint 必须红且报 `no-explicit-any`；② 写 `foo as Bar` → 必须红；③ 高手写一个 41 行的函数 → 必须红；④ `core` 里 `import '@hreader/protocol'` → depcruise 必须红；⑤ 删掉某个 `src/index.ts` 的引用 → knip 必须红。每条给出"违规 → 报错原文"。
- 报告逐条列出：每个规则/配置解决了哪个具体风险，以及你在 M1.0 里**主动放弃**的严格项及原因（没有就写"无"）。

## 审计重点（给审计员）

配置是否"看起来严但实际可绕过"：`exclude`/`ignore`/`overrides` 是否开得太宽；`consistent-type-assertions` 是否被 `as const` 合法豁免误导；`perFile` 覆盖率是否会因空文件而虚高；CI 是否真的 `frozen-lockfile`、是否因 `continue-on-error` 或 `|| true` 而永不失败；lockfile 与 `package.json` 是否一致。

## 测试义务（给测试员）

1. 为 `HrError` 写真实测试：`instanceof` 跨包可用、`code` 稳定、`message`/`cause` 透传、`name` 正确。
2. 写"门禁有效性"测试：在临时目录构造违规，断言 `pnpm lint` / `depcruise` / `knip` 退出码非 0（不写进仓库，或用 `fixtures/` 且被 lint 白名单隔离——由你裁决哪种更干净）。
3. 证明空文件不会让覆盖率虚高：临时加一个未测试的 `src/x.ts`，断言 `test:coverage` 失败，然后删除。

## R1 修订（协调者裁定，2026-11-12）

审计 `audit-M1.0.md` 判 G2 FAIL（P0×3、P1×4）。以下为**架构层裁定**，编写员据此返工，不接受绕行方案：

1. **类型检查改单一工程**（解 P0-1 + P1-2）：删除 5 个包的独立 `tsconfig.json` 与根 `tsconfig.json` 的 `references/files:[]` 结构；改为一根 `tsconfig.json`：`noEmit: true`、`include: ["packages/*/src/**/*.ts", "packages/*/tests/**/*.ts"]`、`paths` 继续映射到各包 `src/index.ts`、**不设 `rootDir`、不设 `composite`**。`typecheck` = `tsc --noEmit -p tsconfig.json`。理由：测试与源码同图，类型错误无处可藏；M1 无构建产物，`tsc -b` 的增量/引用机制收益为零、复杂度全部是成本。M5 需要 chrome 类型或产物时再按需拆分，届时必须同时保证 tests 在图中。
2. **跨包引用只承诺"类型与测试层可用"**（解 P0-2）：workspace 声明 `workspace:*` 依赖、vitest `resolve.alias` 把 `@hreader/<pkg>` 指到源码、TS `paths` 指到源码——`protocol → core` 必须能编译、能被 vitest 解析、`instanceof` 必须成立。**运行时裸 Node 解析（dist）不在 M1 承诺内**，必须写进 `docs/04` 以外的实现报告"已知限制"一节，禁止在报告里给测试员相反指引。
3. **没有代码的包不建空的 `src/index.ts`**（解 P1-3 虚高覆盖率 + 虚假导出面）：`protocol`/`renderer-html`/`chrome-extension`/`app` 本卡只保留 `package.json`（`private`、`type`、`sideEffects: false`、`exports` 指向本卡尚不存在的入口——**改为本卡先不写 `exports`**），等各自首张卡落地时再加。`core` 保留 `src/index.ts`。
4. **depcruise**（解 P0-3 + P1-4）：`exclude` 只留 `dist|coverage`；`doNotFollow` 只对 `node_modules` 生效且不得出现在 `exclude` 里；扫描范围 `packages/*/src` **与** `packages/*/tests`；补一条"tests 不得被 src 反向依赖"。
5. **ESLint 覆盖面**（解 P1-1）：`files` 覆盖 `**/*.{ts,tsx,mts,cts}`，并显式声明本卡无 `.tsx` 但配置必须先覆盖，避免后续静默零检查。
6. **vitest**：取消 `projects` 分片，单一配置 `include: ["packages/*/tests/**/*.test.ts"]`，`resolve.alias` 按 §2。
7. P2 全部登记进 `impl-M1.0.md` 的"技术债"表，本卡不修。

以上改完必须重跑 5 条负向验证（尤其是 P0-3 的 `left-pad` / `eslint` 两条），并新增两条：⑥ 测试文件里写类型错误 → `pnpm typecheck` 必须红；⑦ `protocol` 里 `import { HrError } from "@hreader/core"` → typecheck 与 vitest 都必须通过。
