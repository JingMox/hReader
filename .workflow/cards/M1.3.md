# M1.3 · `hr_outline` 骨骼提取

- 上游规格：`docs/05` M1.3 AC1–AC5、`docs/02` §"三、核心工具协议"（`hr_outline` 行）+ `<script id="hr-meta">` 结构；依赖 M1.2（`66382e7`）。
- 定位：这是 Agent 的**省 token 入口**。它输出的字节数就是产品价值本身，所以"输出体积"与"正确性"同级。


## v2 修订（协调者裁定，2026-11-12）

11. **诊断必须受预算约束**（P0-1，硬要求）：`Outline.diagnostics` 的 `JSON.stringify` 字节数 **≤ 1024 B**，与节点/批注同属 8KB 预算之内。
    - 聚合规则：同一 `code` 最多保留 **3 条**（同 `code` 且同 `message` 的重复项先折叠，报文含真实计数）；被省略的另补 1 条 `outline_truncated`，`message` 写明"另有 N 条诊断省略"。
    - `outline_truncated` 自身只允许出现 **1 条**，且必须同时报告真实丢弃节点数与省略诊断数（不得拿扫描上限当丢弃数）。
12. **字数只计可见正文**（P1-1）：`<style>`/`<script>`/`<textarea>`/`<template>` 内的文本**不计**；`<noscript>` 计（它是兜底可见内容）；`<code>/<pre>` 仍计。
13. **词切分口径定死**（P1-2）：以 `[\p{L}\p{N}]` 连续串为 1 词，且**仅判 CJK（Han/假名/谚文）逐字符计 1**，其余（含非 ASCII 拉丁、希腊、西里尔、带变音符字母）一律"整串 = 1"。连字符/中点/逗号/句点/空格都是**分隔符**：`state-of-the-art` = 4、`1,234.56` = 3、`l'été` = 2。NFC/NFD 必须同值（先 `normalize("NFC")` 再计数）。
14. **`level` 严格取标题自身数字**（P1-3）：`h3` → 3，即使父级是 h1 或 section 无标题；`section`/`header` 取其内部第一个 h1–h4 的 level；无标题 section 继承父级（顶层 `0`）。**禁止**"父链缺失就压缩级别"的补偿逻辑。
15. **`script_in_meta` 与 `invalid_meta` 双报是允许的**（P1-3 裁定）：一个是 HTML 层观察、一个是 JSON 层观察，禁止跨层抑制（会造成隐藏耦合）。但 `invalid_meta` 的报文必须点明"hr-meta 不是合法 JSON"，测试同时钉住这一对。
16. **不许复制归一逻辑**（P2）：outline 侧文本归一必须复用 `src/html/text.ts` 的既有实现；如需不同口径，扩展它并写清参数，禁止再抄一份（现已出现两处结果不同的副本）。
17. **命名去重**（P2）：`ops/outline/derive.ts` 与 `model/derive.ts` 同名，改名为 `assemble.ts`（或更能说明职责的名字），并在模块头写清"这层管什么"。
18. **单节点文本上限**（P2）：任何进入 outline 的 `text` 字段 ≤ 120 字符，超出以 `…` 结尾并计入 `outline_truncated` 的省略说明（防单节点独自撑爆预算）。

## 分层裁定

- `<script id="hr-meta">` 的**解析只做一次、只在一个模块里**（`src/meta/`），`ops` 层只消费其结果；M1.5/M1.6 必须复用，禁止各自 `JSON.parse`。
- `hr_outline` 是**纯函数**：`buildOutline(parsed: ParsedHtml): Outline`。不读盘、不抛"文件不存在"（那是 CLI 层的事，M1.8）。
- outline 的排序 = 文档顺序，一次遍历得出；**禁止**两次排序后依赖 `Array.prototype.sort` 的稳定性做业务保证。

## 契约

1. **`Outline`**（AC1）
   ```
   Outline = {
     nodes: readonly OutlineNode[];
     pendingAnnotations: readonly PendingAnnotation[];
     wordCount: number;          // 全文（article 内）字数，规则见 3
     diagnostics: readonly Diagnostic[];   // 复用 M1.1/M1.2 码空间
   }
   OutlineNode = { id: string; tag: string; level: number; text: string; wordCount: number; children: readonly OutlineNode[] }
   ```
   - `level`：`h1`→1 … `h4`→4；`section`/`header` 取**其所属标题层级**（section 内第一个 h1–h4 的 level；无标题的 section 继承父级 level，顶层无标题 section 记 `0`）。
   - `text`：该节点自身标题文本（标题节点）或 section 的**首个标题文本**；无标题的 section/header → 空串（不得用"前 80 字"之类的启发式，M1.4 负责读正文）。
   - `id` 必来自 `data-hr-id` 且非空；缺失则该节点**不输出**并产生 `outline_node_without_id` 诊断（新码，见 6）。
2. **包含范围**（AC2）：只输出 `<article>` 内的 `section`/`header`/`h1`–`h4`；`h1` 是 article 的标题时，它作为 `nodes` 的顶层节点出现，其下挂 `level > 1` 的兄弟结构。不要输出 `p`/`div`/列表/表格。
3. **字数**（AC1 精确规则）：
   - CJK（含扩展 A、假名、全角字母）每字符 = 1；连续拉丁/数字串（`[\p{L}\p{N}]` 且非 CJK）每串 = 1；标点/空白 = 0；`<code>`/`<pre>` 内的文本**计入**（它们也是内容）。
   - 计数对象 = `article` 的**全部**可见文本（含未出现在 outline 里的正文），与 `OutlineNode.wordCount`（该节点子树内文本）口径一致。
   - 必须用 `\p{Script=Han}` 之类的 Unicode 属性类，禁用手写码点区间表。
4. **体积**（AC2）：1MB 文档的 `JSON.stringify(outline)` ≤ 8KB。为达成此目标允许**截断**：`text` 逐节点上限 120 字符（CJK 按 1 计，超出以 `…` 结尾，`truncated` 不入结构而是由结尾 `…` 表达）；`nodes` 深度上限 4（article → section/h1 → section → h2…超出不再展开）；**任何截断都必须由诊断 `outline_truncated` 报告一次**，不许静默。若截断后仍超 8KB，godoc 写明"极端文档允许超"，但必须在报告里给出实测最大值。
5. **批注**（AC3）：从 `<script id="hr-meta">` 读 `annotations`。
   - `status === "pending_ai"` 全部进 `pendingAnnotations`：`{ id, targetId, comment }`，`comment` 截断至 200 字符（`…` 结尾）。
   - `targetId` 在文档中不存在（无同名 `data-hr-id`）→ 仍输出该批注 + 诊断 `annotation_target_missing`（带 `annotationId`，放进 `message`，不许新增 `Diagnostic` 字段）。
   - `hr-meta` 缺失 → `pendingAnnotations: []` 且**无诊断**（合法文档形态）；`hr-meta` 存在但 JSON 非法/结构不符 → 诊断 `invalid_meta`，且 `pendingAnnotations: []`（不抛）。
   - `annotations` 不是数组、元素缺 `id`/`targetId` → 逐条诊断 `invalid_meta`，跳过该条，其它条照常。
6. **新诊断码**（窄联合扩容，需追加到 `DiagnosticCode`）：`outline_node_without_id`、`outline_truncated`、`annotation_target_missing`、`invalid_meta`。除这四个外不得新增；`Diagnostic` 五字段形状**不变**。
7. **确定性**（AC5）：同输入两次 `JSON.stringify` 逐字节相等；不得依赖 `Object.keys` 顺序以外的不稳定来源；所有数组顺序 = 文档顺序。
8. **扁平文档**（AC4）：无 `section`、只有一串 `h1`–`h4` + 段落时，按标题层级建树（`h3` 出现在 `h1` 后且无 `h2` → 直接成为 `h1` 的子节点，`level` 保持 3）；不得崩、不得产生空 `nodes`。无标题文档（只有 `p`）→ `nodes: []` + `outline.truncated`? 否：给 `nodes: []` 且**不**诊断（合法形态）。
9. **性能**：1MB 文档 `buildOutline` ≤ 150ms；10k 节点不得栈溢出。
10. **代码形态**：文件 ≤ 400 行、函数 ≤ 40 行、复杂度 ≤ 10、模块头 ≤ 3 行；两级门面；无 `any`/`as`/`!`；注释只写签名表达不了的（字数规则、截断策略、复杂度上界）。

## 审计重点

体积是否真 ≤8KB（自己算，别看报告）；截断是否静默（无诊断）；字数规则是否漏 emoji/组合字符/全角（`Ａ` 是 1 还是 0）；`section` 的 `level` 推导是否在"嵌套 section + 无标题"时错乱；`pendingAnnotations` 的 `targetId` 校验是否被 `id` 与 `data-hr-id` 混淆；`hr-meta` 里的 `</script>` 注入是否破坏解析；JSON 双重解析（`ops` 里又 parse 一次）；outline 是否把 `header`（页面级）当正文；`level: 0` 是否引发下游排序 bug；10k 节点递归是否爆栈。
