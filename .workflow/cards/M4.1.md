## §2 决策与裁定（D1–D12，写者不得改动，认为有问题就停手报"待裁定"）

- **D1 双层架构，core 不碰网络**。
  - 统计层 + 组装层 + 合并层 + 校验层全部在 `packages/core/src/style/extract/**`（纯函数，不 import `node:http`/`fetch`）。
  - 网络传输层在 `packages/cli/src/llm/**`（唯一允许 `fetch` 的地方）。core 只暴露 `LlmPort` 接口（`{ complete(prompt: string): Promise<string> }`），由 cli 注入。
  - 理由：core 是底座且被 MCP/Pi/dsh 三个宿主复用，任何一层引入网络就会把"离线可测"这条地基抽掉（`L-21` 是同类教训：产物离开仓库即失效）。
- **D2 降级是默认路径，且必须进 CI**。`--no-llm`、或 `OPENCODE_API_KEY` 未设置、或显式 `--model` 之外没有任何模型参数时，走**纯统计版**：`persona`/`narrative_rules`/`rhythm.style` 由模板 + 统计值填充，`examples` 留空数组。纯统计版必须**通过严格 schema 校验**并被 `hr style --tone` 使用。**禁止**把 LLM 路径做成"没 key 就报错"——那会让 M4.1 的核心能力在 CI 里永远不跑（`docs/03` §11.22 的 SKIP 假绿）。
- **D3 LLM 只许"建议"，统计值是权威**。`max_paragraph_sentences` 一律取统计值（LLM 输出该字段直接忽略并记一条 `DROPPED`）；`vocabulary.forbidden` = 统计命中表 ∪ LLM 追加（去重、保序、上限 24 条）；`persona`/`narrative_rules`/`rhythm.style`/`examples` 取 LLM。LLM 给的类型不对（字符串当数组、超长）按字段丢弃，不整体失败。
- **D4 校验通过才写盘**。产物经现有严格解析器（`packages/core/src/style/spec.ts` 的 `parseStyleYaml` 路径）验证；`--out` 指向已存在文件时**必须** `--force`，否则 `HrError("invalid_input")` 不覆盖。写盘用既有原子写（`packages/core` 的 `atomicWrite`），不许自己 `fs.writeFileSync`。
- **D5 温度与确定性**：`temperature: 0`、`stream: false`、`max_tokens` 常量（≤ 2048）。prompt 组装必须是**纯函数且字节稳定**（同输入同输出，键序固定），否则"同输入同输出"的断言无从谈起。
- **D6 会话头**：`x-opencode-session` 默认 `crypto.randomUUID()`，可用 env `HR_LLM_SESSION` 覆盖（注释里写清"这是 OpenCode Zen 的路由要求，缺了直接 400"）。**不许**把它写成常量——那会让同一 id 被并发请求共享。
- **D7 超时与重试**：单次请求 `AbortSignal.timeout(30_000)`；**不自动重试**（非幂等写盘 + 费用不可控），失败即 `HrError`，文案给出"可再加一次"的人话。
- **D8 不出仓库的东西**：一切错误消息、日志、yaml 注释里**不得**出现 key（含前缀/长度）；错误消息截断响应体到 ≤ 200 字符。测试用假 key（`sk-test-…`）断言不泄漏。
- **D9 语料入参**：`hr style extract <file...>` 接受 1..N 篇 `.md`/`.html`；0 篇 → usage 错误；单篇允许但 stderr 打一行 WARNING（"单篇语料萃取的规则会很窄"）；单文件 > 1 MiB 或语料总量 > 4 MiB → `HrError("invalid_input")`。
- **D10 命令形状**（与既有 CLI 一致，`--json` 也必须支持）：
  ```
  hr style extract <file...> --id <style-id> --name "<显示名>" [--out <path>]
                   [--inherits-visual <theme-id>] [--no-llm] [--force]
                   [--model deepseek-v4.1-flash] [--base-url <url>] [--json]
  ```
  `--id` 必须匹配既有 `STYLE_ID` 正则；缺 `--id`/`--name` 时用文件名 slug 生成 `id`、用 `id` 当 `name`，并在 stderr 说明用了默认值。
- **D11 语料 fixture 用本仓文档**（用户未提供个人语料，不阻塞）：`fixtures/extract/` 下放 3 篇本仓现成长文（如 `docs/03-collaboration-workflow.md` 的 §11 段落抽取、`docs/05-feature-cards.md` 的 M3.3 节、`skills/hreader/references/style-authoring.md`），逐字节固定，作为统计层的真值来源。**这些是测试资产，不许被后续统计逻辑"调参到通过"**——真值断言写在卡 §4。
- **D12 真调用只许录 fixture**：开发期允许**≤ 10 次**真实调用（仅用于录制 `fixtures/llm/*.json`），录完即用回放；CI 与 `pnpm verify` 里**零真实调用**。录制命令与次数写进 §9 证据栏。

## §6 假绿形态（写者自己先反问，测试员会照这个打）

1. **`describe` 里只测纯统计版**，LLM 路径只测"没 key 时不崩" → 等于没测 LLM。
2. **假 `LlmPort` 返回手搓的完美 JSON**：必须至少一条 fixture 用**真实录制响应**（含真实模型会带的赘余/格式瑕疵），否则合并逻辑的容错分支永远不跑。
3. **`contains(persona)` 这类子串断言**：必须断言"叶子值相等"（`yaml` 解析后 deep equal），并至少一条断言"LLM 给了别的 `max_paragraph_sentences` 会被丢弃"（反向输出）。
4. **`fixtures/extract/` 被调参适配**：真值必须先于实现固定；写者若发现实现与真值不符，**改实现或停下报裁定**，不许改真值（除非在 §9 记录并给出理由）。
5. **覆盖率靠 `/* v8 ignore */`**：仓库全面禁止，`fetch` 分支用假 `fetch` 打，不豁免。
6. **`--json` 只测 happy path**：必须有一条"错误也出 JSON"的断言。**实现口径以 `packages/cli/src/output.ts:31-32` 为准**（单行 `{"ok":false,"code":"…","message":"…"}`，不是 `{error:{code}}`）——卡面原措辞已按此更正（R3）。

## §8 这张卡为什么存在

路线图 `docs/02` M4.1 原文要求"用户丢 3~5 篇历史文章，Agent 分析句式节奏、转折词、叙事结构与高频词汇，一键生成专属 `style.yaml`"。但"Agent 分析"这句在过去两年里反复变成两种东西：要么是一个无法验收的 prompt 玩具，要么是一段把模型返回体直接 `yaml.parse` 写盘的脚本（模型一抽风就写出坏 `style.yaml`，而 `style.yaml` 是**用户下一次写作的全部输入**，坏一次污染整条链路）。本卡把"分析"拆成"可离线验证的统计层"与"只许建议的 LLM 层"，就是为了让 M4.1 的核心能力在**没有 key 的机器上也能被 CI 验证**，同时让模型永远无法越过严格 schema 与统计权威。

## §10 裁定补记 R1–R8（2026-11-16，写者复述时发现卡面 6 处与代码不符，逐条裁定）

写者（`ce384949`）复述阶段核出：卡里 `atomicWrite`/`parseStyleYaml` 两个名字在代码中不存在、`HrErrorCode` 无网络类码、`--json` 错误形状与实现不一致、D2 触发条件语句读不通、`forbidden`/`recommended` 归属未定义、`max_paragraph_sentences` 真值口径未定。以下为裁定，**优先于 §2/§4 中被引用的旧措辞**。

- **R1（错名与导出面）**：真名是 `writeAtomic`（`packages/core/src/io/atomic.ts:102`，签名 `(input: {path, workspace, data: Uint8Array}, deps: PatchDeps) => Promise<void>`）与 `parseStyleText`（`packages/core/src/style/spec.ts:248`，`(text, at) => StyleSpec`）。**两个都不进公开面**（core barrel 是极小导出面）。改为新增 `packages/core/src/style/save.ts` → `saveStyleText(input: {path, workspace, text, force}, deps: StyleDeps): Promise<void>`：先 `parseStyleText` 校验（不过就抛 `invalid_style`，**一个字节都不写**）→ 目标已存在且非 `force` → `file_exists` → `writeAtomic`。从 `packages/core/src/style/index.ts` 与 `packages/core/src/index.ts` 导出。`workspace` 取 CLI 已有的 `args.workspace`（`packages/cli/src/args.ts:83` = `resolve(cwd, --workspace ?? cwd)`），`--out` 落在 workspace 外一律 `path_outside_workspace`（与其它写命令一致，别架空守卫）。
- **R2（错误码）**：`HrErrorCode` 增两枚：`"llm_failure"`（网络失败/非 2xx/超时/响应体不合约/choices 为空，**统一一枚**，detail 进 `message`，不许把 key、prompt、响应体原文写进 `message`）与 `"file_exists"`（`--out` 已存在且无 `--force`）。`packages/cli/src/exit-codes.ts` 的 `satisfies Record<HrErrorCode, number>` 会强制补齐；`docs/03`/`docs/05` 各记一行。
- **R3（`--json` 形状）**：以 `packages/cli/src/output.ts:31-32` 的实现为准（单行 `{"ok":false,"code","message"}`）。卡面 §6.6 已更正。
- **R4（D2 触发条件）**：取写者建议 **A**——有 `OPENCODE_API_KEY` 即默认走 LLM，`--no-llm` 强制纯统计；无 key 时静默降级为纯统计并在 stderr 打一行提示（**不是**错误退出）。这样 AC-4/AC-8 的失败面在默认路径可达。
- **R5（`forbidden` / `recommended` 语义）**：`forbidden` = 内置口语/套话表里**在语料中出现 0 次**的条目（≤24，按表内固定顺序；LLM 可追加，去重保序后仍 ≤24）。理由：`forbidden` 的语义是"这位作者不这么说"，把作者真用过的词禁掉是反的。`recommended` = 语料实词 top16（去停用词、长度 ≥2、频次降序、同频按 Unicode 码位升序）；**LLM 不得触碰**（D3 只授权它追加 `forbidden`）。套话表落在 `packages/core/src/style/extract/fillers.ts`（纯常量 + 一句出处说明）。
- **R6（`max_paragraph_sentences` 口径）**：取 **P75**（线性插值后 `floor`，再 `clamp(2,5)`），**不取 P25**——P25 会让生成文本比语料更碎，"最多几句"是上限语义。句末判定 = `。！？!?…` 与"后跟空白或行尾的 ASCII `.`"；**`；` 不算句末**（分号连的是小句不是句）。`spec.ts:189` 的 `positiveIntOf` 只要求正整数，`[2,5]` 是本卡的软区间。
- **R7（`narrative_rules` 必填，卡面空白）**：`packages/core/src/style/spec.ts` 的 `requiredListOf` 要求至少 1 条，否则整份 yaml 被拒。**纯统计版必须产出确定性模板规则**（例：`每段控制在 N 句以内`、`避免使用：a、b、c`、`维持三段式视觉节奏`），不许空、不许随机；LLM 版可替换为模型规则（≤6 条、每条 ≤120 字），但过滤后为 0 条时**回落到模板规则**而不是交空数组。
