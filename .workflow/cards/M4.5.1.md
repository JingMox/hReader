# M4.5.1 加固卡：`outline` 取产物真值 + `hr pdf` 人读行补书签数

> 状态：**立卡（v1）**｜立卡人：协调者｜日期：2026-11-17
> 前身：M4.5（`1dcfcba`）已结卡，但留下 `L-40`：`--json.outline` 是"打印稿 DOM 里 `h1–h6` 元素数"这个**近似值**，`display: none` 的标题会把它算多而 Chrome 不为它生成书签。本卡把这个近似值换成**产物真值**，并顺手补齐 `humanPdf` 漏印书签数。

---

## 1. 事实基线（协调者已实测，直接采信，**不要重跑侦察**）

| 事实 | 证据 |
| --- | --- |
| Chrome 产物里大纲根对象形如 `64 0 obj <</Type /Outlines /First 65 0 R /Last 65 0 R /Count 3>>`，条目字典无 `/Type`（规范如此） | `strings` 实测 |
| 每条的 `/Dest` 是 `[<pageObj> 0 R /XYZ x y 0]` | 同上 |
| **`/Title` 不只出现在大纲里**：`/Info` 字典也有一条文档标题 `1 0 obj <</Title <FEFF969085CF> …` | 同上 —— 所以"数 `/Title` 出现次数"会**恒多 1**，必须从大纲根对象进树 |
| 产物是**经典 xref 表 + trailer**（`trailer <</Size N /Root 68 0 R /Info 1 0 R>>`），对象都是未压缩字典 | 同上 |
| 大纲条目数 == 打印稿 `h1–h6` 元素数，在**可见标题**的文档里成立（M4.5 e2e 已钉） | `.workflow/reports/test-M4.5-G3.md` |
| `--json.pdf` 是 **base64 字节**（人读行才给路径） | 实测 |
| 已完成：`pdfPagesOf`（`commands/pdf.ts:41-43`，正则数 `/Type /Page`）、`pdfHeadingsOf`（`:59-70` + `:75`） | 读码 |

**未确证、本卡要把它变成不相关**：`display:none` / `visibility:hidden` / `content-visibility:hidden` 的标题 Chrome 到底收不收。**本卡完成后这个问题不再影响任何报告值**——因为值来自产物，不来自 DOM 估计。

## 3. 设计要点

**D1 新模块 `packages/cli/src/pdf/bookmarks.ts`（只读、纯函数、无 IO）**
导出 `bookmarkCountOf(bytes: Uint8Array): number`：
1. 从 `trailer` 取 `/Root` → Catalog 对象号；
2. Catalog 里取 `/Outlines` → 大纲根对象号；**键不存在则返回 `0`**（这是"没开大纲"与"文档无标题"的正常路径，不是错误）；
3. 从根对象 `/First` 起做 DFS：跟 `/Next` 走兄弟链、跟 `/First` 进子层，数条目；
4. 若根对象还带 `/Count`，**交叉核对**：实走数 ≠ `Math.abs(/Count)` → 抛 `HrError("render_empty", …)`（"产物自相矛盾"）。**不许**静默取其中一个。
5. 任何结构断链（`/First` 指向不存在的对象、对象不是字典、`/Kids`/`/Pages` 混淆）→ 抛 `render_empty`，**不许**回退成 `0`（回退 0 会把"Chrome 换了输出格式"伪装成"这份文档没有大纲"）。

**D2 语义换成产物真值**
`commands/pdf.ts` 的 `productPdfOf` 删掉 `input.outline ? pdfHeadingsOf(product.html) : 0`，改成 `bookmarkCountOf(bytes)`；随后**删除** `pdfHeadingsOf` / `headingsOf` / `HEADING_TAGS` 及那条"近似值"注释。`--no-outline` 自然得 0（产物里没有 `/Outlines` 键），**不需要**在命令层短路。

**D3 `humanPdf` 补书签数（唯一的人读行变更）**
`packages/cli/src/output.ts` 的 `humanPdf`：`<path> (N 页, M 条书签)`，`M` 恒出现（`0 条书签` 也印），与 `--json` 的 `outline` 同一个值。同步更新已有的输出断言用例。

**D4 测试的扫描器保持**独立实现**（这是本卡唯一允许的"重复"）**
`packages/cli/tests/helpers/pdf-scan.ts` 是**独立 oracle**：src 的 `bookmarks.ts` 与它刻意不共用代码，否则"src 读错了"和"oracle 读错了"会一起错、一起绿。两处都要有注释写明这条理由（一句话即可）。
`tests/helpers/pdf-scan.ts` 已能解标题树，本卡要让它也能报 `/Count`，供 e2e 做"实走 == /Count == 打印稿 heading 数"三方对照。

**D5 失败模式的用户可见性**
`bookmarkCountOf` 抛的 `render_empty` 走既有 exit 3；message 要能区分两种：产物里根本没有 `%PDF-` 头（既有）与"大纲结构解析不出"（新）。两种都用同一个 code，靠 message 区分——**不新增错误码**。

## 5. 验收

- **AC-1** 正常多章文档：`--json.outline` == 产物内实走条目数 == 打印稿 `h1–h6` 元素数（三者相等，e2e 三方对照）。
- **AC-2** 含隐藏标题的文档（`style="display:none"` 行内属性；若被打印层剥掉就用 `hidden` 属性，写者先用真 Chrome 确认哪种能进打印稿）：`outline` **等于产物条目数**（不再差 1）；若 Chrome 实际上仍然收录它，则该用例退化为 AC-1 的等价断言，**必须在报告里写明实测结论**。
- **AC-3** `--no-outline`：`outline === 0`，产物无 `/Outlines` 键，人读行 `0 条书签`。
- **AC-4** 无标题文档：`outline === 0`，产物无 `/Outlines` 键，exit 0（不是错误）。
- **AC-5** 结构自相矛盾（手写字节让 `/Count` 与实走不等）→ `render_empty` exit 3，**不落盘**；结构断链同样抛错而不是返回 0。
- **AC-6** 人读行格式 `a.pdf (3 页, 3 条书签)`，与 `--json.outline` 同值。
- **AC-7** `grep -r "pdfHeadingsOf\|headingsOf\|近似值" packages/cli/src` 为空；`L-40` 由协调者在 `docs/05` 关闭。
- **AC-8** 全量 `pnpm verify` EXIT=0 连跑两遍（协调者复跑），文件数/用例数**只增不减**，四维 perFile 100%。
- **变异（≥8，每条都要能红）**：`/Count` 恒当答案（不实走）；实走不跟 `/Next`；不跟 `/First`（只数第一层）；交叉核对删掉；断链改成返回 0；`/Outlines` 键判断写成"总有"；人读行 `M` 恒 0；`/Info` 的 `/Title` 被算进去（证明没从根对象进树）。

### 5.1 G3' 变异轮追加（2026-11-18，全部已完成）

- **MV-R3-1** `trailerOf` 去掉 `offset < lastStartxref` 过滤 → 原为**全绿**（测试洞），已由 `bytesWithTrailingTrailerOf` 夹具封口：真 trailer 之后再写一个**非注释** `trailer << /Size 99 /Root 99 0 R >>`，断言仍取它之前那个真 trailer（`toBe(1)`，不是抛错、不是 99）。
- **MV-R3-2** 删掉 `stream`→`endstream` 跳过 → 原来只有真机 e2e 会红，`HREADER_SKIP_CHROME=1` 下全绿；`OUTLINE_STREAM_TRAP` 已重造成「流体重定义 Catalog 且指向不存在的 98 0 R」，**纯合成、无 Chrome 也红**。
- **MV-R3-3** 删掉 `seen` 环检测 → 可红（182ms），但原形态是整轮挂死。**裁定采用 A 方案**：删掉冗余步数上限、只留 `seen`，并围绕其实性写明向注释（鸽笼约束 ⇒ `steps ≤ 对象总数` ⇒ 重复必在 `seen` 处更早被逮住 ⇒ 第二道 `throw` 按构造不可达，只能靠覆盖率豁免养着）。**全仓零 `v8 ignore`/`c8 ignore`/`istanbul ignore`**。残余风险（`seen` 被改坏时回归形态是挂死而非即时红，靠 CI 作业级超时兜底）已记入 `docs/03` §11.44 第 4 条。
- **反对象拒开的先例**：B 方案（`/* v8 ignore */`）被否——本仓零先例的价值就在于它是零；C 方案（上限改派生值）只是把不诚实藏深一层。理由存档：冗余守卫的只一收益是“测试期少等 120 秒”，不值当花掉“门禁无豁免”这条资产。
