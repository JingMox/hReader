## 用户可见行为

我在一个空目录里手写了一篇 `article` 风格的 HTML（没有任何 `data-hr-id`）。我要能：

1. `hr normalize my.html --write` —— 它给我补上 id 并原地写回；再跑一次**什么也不变**（幂等）。
2. `hr serve my.html` —— 它打印一个**我能直接点开就进阅读器**的地址；我不用知道 token 是什么。
3. 打开阅读器后，左栏有这篇文档、目录有三级标题、正文可读、能划词批注。

## 契约（G1a 与 G1b 共同的唯一事实源，两边都只能读这一节 + `--help`）

### C1 `hr normalize`

```
hr normalize <input.html> [--write] [--json]
```

- 作用：对缺 `data-hr-id` 的文档注入稳定 id（复用 `injectNodeIds` 的语义：同一输入 → 同一批 id，与运行次数无关）。
- 不带 `--write`：把规范化结果打印到 stdout（JSON 模式下 `{"ok":true,"data":{"needsNormalize":bool,"html":"…","injected":n}}`）。
- 带 `--write`：原地写回；写回后 `needsNormalize === false`。
- 已有完整 id 的文档：`needsNormalize === false`、`injected === 0`、`--write` 不产生字节变化。
- 非法输入（非 HTML / 缺根 `<article>`）：`{"ok":false,"code":"invalid_document",…}`，退出码 1。

### C2 `hr serve` 的可点链接

```
hr serve <doc> [--port n] [--app-dir p] [--token <custom>] [--no-redirect-print]
```

- 人类输出（非 `--json`）**必须**打印一行可直接打开的地址：`open <http://127.0.0.1:PORT/s/<doc>?t=TOKEN>`，且该地址 `GET` 后**必须** 302 到文档并把 cookie 种上（现状已如此，缺的只是"打印它"）。
- `--json` 输出增加 `url`（即上面那串，含 token）与 `readerUrl`（`http://127.0.0.1:PORT/?doc=<doc>`）。
- **不得**再把不带 token 的裸 `/` 当作"访问入口"打印（现状 `serving … on http://127.0.0.1:8805/` 打开是 401）。

### C3 `GET /?doc=<name>[&t=<token>]`

- 带 `t`：与 `/s/<name>?t=` 同效（种 cookie）后 302 到 `/?doc=<name>`。
- 只有 `doc` 无 `t`：若已有有效 cookie → 200 阅读器并选中该文档；否则 401 JSON（与现状一致）。
- `doc` 指向未注册文档：404 JSON，`code:"not_found"`。

### C4 `hr outline` 对缺 id 文档的行为

- 不再静默返回空树 + 一句 warning；改为：`{"ok":false,"code":"needs_normalize","message":"文档缺少 data-hr-id，先跑 hr normalize <file> --write"}`，退出码 2（新增退出码，不得复用 1）。
- 已有 id 的文档：行为**零变化**（回归护栏）。

## 验收标准 (AC)

- **AC-1 幂等**：`normalize --write` 连跑两次，第二次 `injected === 0` 且 `bytes` 与第一次后一致（按内容 md5 比）。
- **AC-2 稳定**：同一输入在不同进程、不同 cwd 下 normalize，产出的 id 集合逐字节一致（无时间/随机/路径依赖）。
- **AC-3 可点**：测试**照着 `serve` 打印的那行地址去 `GET`**，必须拿到 302 + `Set-Cookie`，随后 `GET /?doc=` 得 200 且 body 含 app 根节点。**判据不是正则匹配打印文本**。
- **AC-4 首用路径**：在 `mkdtemp` 空目录里手写一篇无 id 文档，只用 `normalize → serve → curl 打印的 url → curl /?doc=`，全链路成功（这条用例就是 journey 维度的样板）。
- **AC-5 定向错误**：`outline` 对无 id 文档退出码 2 + `code:needs_normalize`；对有 id 文档退出码 0、输出与 M4.7 完全一致（用黄金文件比）。
- **AC-6 不回归**：`pnpm verify` 十步 EXIT=0；`desktop:check` EXIT=0；`hr serve --json` 的旧字段一个不少（`token/port/doc/pid`），只增不减。

## 风险点

- `injectNodeIds` 的 id 生成若含随机/时间，AC-2 会揭穿 —— 若真含，**不许**为了过 AC 改成"测试里先固定随机源"，要改实现使其内容寻址（这是本卡的核心风险）。
- `/` 与 `/s/` 的 cookie 语义有两处已存在实现，改 C3 时容易漏 `SameSite`/`Path`（审计必查）。
- `--json` 增字段是"只增不减"，但 `--no-redirect-print` 是逃生门：新增打印行不得让既有 grep 型脚本（`skills/**`）失效。
- 新增退出码 2 要和既有 `EXIT_USAGE = 2` 的语义对齐（若已占用，改用 3 并在契约里写明）。
