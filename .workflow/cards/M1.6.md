# M1.6 · 双维风格引擎（`style.yaml` + tone 编译 + 禁用词 Lint）

> 依据：`docs/05-feature-cards.md` §M1.6（AC1–AC6）、`docs/02:150-180`（style.yaml 正典样本、Anti-Slop Lint、三段一视觉）、
> `docs/04` §6（`style/` 只管解析/编译/lint；fs 只在 `io/`；无隐式状态、不读环境变量）。

## 0. 依赖裁定（协调者，2026-11-13）

- 引入 `yaml@^2`（`@hreader/core` 的 **runtime** 依赖）：**唯一**授权的新依赖。理由：手写 YAML 解析器是 bug 农场，且与"封装规整"冲突。
- 不允许再引入别的依赖；`yaml` 只允许在 `src/style/parse.ts` 被 import（depcruise 加规则），其他模块只吃解析后的**裸对象**。
- YAML 用 `parseDocument` + `schema: "core"`（禁止 `!!js/*` 自定义标签、禁止 merge key 之外的扩展），解析后必须转成普通对象再校验。

## 1. 类型（裸对象，无 class、无 Result 包装）

```ts
type LanguageStyle = {
  persona: string;
  narrativeRules: readonly string[];
  sentenceRhythm: { maxParagraphSentences?: number; style: string };
  vocabulary: { forbidden: readonly string[]; recommended: readonly string[] };
  examples: readonly { bad: string; good: string }[];
};

type StyleDefinition = {
  id: string;               // ^[a-z0-9][a-z0-9-]{1,63}$
  name: string;
  description: string;
  inheritsVisual: string | null;   // YAML 键 `inherits_visual`；缺省 null
  languageStyle: LanguageStyle;   // YAML 键 `language_style`
};
```

- **YAML 键一律 snake_case，TS 字段一律 camelCase**，映射表在 `style/parse.ts` 顶部一处写死；不接受 camelCase 键（严格模式）。
- `parseStyle(yamlText: string): StyleDefinition` —— 纯函数；任何校验失败抛 `HrError("invalid_style")`，`message` 形如 `style.yaml: <path> 需要 string，实际缺省`（路径用点号，如 `language_style.sentence_rhythm.max_paragraph_sentences`）。

## 2. 校验规则（AC1，严格模式）

1. 顶层键只允许 `id/name/description/inherits_visual/language_style`；`language_style` 下只允许 `persona/narrative_rules/sentence_rhythm/vocabulary/examples`；`sentence_rhythm` 下只允许 `max_paragraph_sentences/style`；`vocabulary` 下只允许 `forbidden/recommended`。
2. 未知键 → `invalid_style`，报文列出**允许的键集合**（与 M1.4 的 `KNOWN_FIELDS` 同一风格，禁止"只报一个"）。
3. 必填：`id`、`name`、`description`、`language_style.persona`、`language_style.sentence_rhythm.style`。其余可缺省，缺省值为：`narrative_rules=[]`、`vocabulary={forbidden:[],recommended:[]}`、`examples=[]`、`max_paragraph_sentences=4`、`inherits_visual=null`。
4. `max_paragraph_sentences` 必须是 **1–12 的整数**（浮点/字符串/0/13 → `invalid_style`）。
5. `id` 必须匹配 `^[a-z0-9][a-z0-9-]{1,63}$`，且不得以 `-` 结尾。
6. 数组元素必须全是非空字符串（`trim()` 后非空）；`examples` 必须是 `{bad, good}` 两键齐全的映射，多余键报错。
7. 空字符串 `persona`/`style`/`name`/`description` → `invalid_style`。

## 3. tone 编译（AC3）

```ts
compileTone(style: StyleDefinition): string
```

- 输出**纯文本**、固定骨架、固定顺序，逐字节可重现（同输入必同输出，无时间戳/随机数/对象键序依赖）：
  ```
  ## 角色
  <persona>
  ## 叙事规则
  - rule
  ## 句法节奏
  每段最多 N 句。<style>
  ## 用词偏好
  - 推荐：x
  - 禁用：y
  ## 改写示例
  - 劣：bad
  - 优：good
  ```
- 空集合的段落**整段省略**（不留空标题）。
- 用户文本原样嵌入，不做转义/不加引号；注入防护靠"输出只是文本，永不求值"——在函数头 1 行注释写清这一点。
- 输出末尾**恰好一个** `\n`。

## 4. 内置 3 个预设（AC5）

- 位置：`src/style/presets/{atelier-editorial,feynman-tech,executive-brief}.ts`，**TS 字面量**（`satisfies StyleDefinition`），不读 yaml、不碰 fs。
- `listPresets(): readonly string[]`（按 id 字典序）、`getPreset(id: string): StyleDefinition`（未知 id → `HrError("style_not_found")`）。
- `atelier-editorial` 的 `vocabulary.forbidden` 至少含：`总而言之`、`在当今数字化时代`、`毋庸置疑`、`赋能`、`抓手`。

## 5. 自定义风格加载与覆盖（AC6）

```ts
loadStyle(input: { id: string; homeDir: string; projectRoot: string }, deps: StyleDeps): Promise<StyleDefinition>
```

- 查找顺序（后者覆盖前者，**深合并且数组整体替换**）：
  1. 内置预设（若有同 id）
  2. `<homeDir>/.hreader/styles/<id>/style.yaml`
  3. `<projectRoot>/.hreader/style.yaml`（**仅当**其 `id` 等于请求 id 时参与覆盖；不等则忽略）
- 深合并只允许对 §1 的对象层级生效（`sentence_rhythm`、`vocabulary`），数组不拼接。
- 全部来源都没有 → `HrError("style_not_found")`。
- 文件不存在视为"该层不存在"；文件存在但解析失败 → 直接抛 `invalid_style`（**不得**静默回退到预设）。
- `id` 是用户输入：`^[a-z0-9-]{2,64}$` 不匹配 → `HrError("invalid_style_id")`，**不做任何 fs 访问**（防路径穿越，`../../etc` 一类必须在拼路径之前就被拒）。

## 6. 禁用词 Lint（AC4）

```ts
lintForbiddenWords(input: { html: string; style: StyleDefinition }): readonly ForbiddenWordHit[]
type ForbiddenWordHit = { nodeId: string; word: string; excerpt: string; offset: number };
```

- 作用对象：`injectNodeIds` 后的**块级元素的文本**（复用 `ops/outline/text.ts` 的取文本逻辑，不另写 walker）。`nodeId` 取该块的 `data-hr-id`；`offset` 是命中起点在**该块文本**中的 UTF-16 下标。
- 归一化：`NFKC` 后再比较；拉丁字母大小写不敏感（`A/B` 与 `a/b` 同命中），中文不做额外处理。
- **通配**：禁用词条目含 `...` 时，`...` 匹配 **0–8 个非换行字符**（`/X(...)Y/` 语义），因为 `docs/02:171` 正典样本里就有 `不仅...而且...`。不含 `...` 的条目按字面匹配。`word` 返回**命中的原文片段**（不是条目模板）。
- `excerpt`：命中位置前后各 20 个字符（不足则截断），单行化（`\n` → 空格）。
- 同一块内同一 `word` 多次命中要去重，保留**第一次**的 offset。
- 结果按 `(文档序, offset)` 升序，稳定可重现。
- `html` 无 `<article>` → `HrError("no_article")`（复用既有码）。

## 7. 新增错误码（冻结，3 个）

| code | 触发 |
|---|---|
| `invalid_style` | YAML 语法/结构/类型/未知键/必填缺失 |
| `style_not_found` | 预设与两层目录都没有该 id |
| `invalid_style_id` | id 不匹配正则（先于 fs，防穿越） |

## 8. 非目标

- 不做 theme.css / 视觉主题（M1.7）。
- 不做 `hr_apply_style` 的 DOM 注入（M1.7）。
- 不做 AI 风格萃取（M4.1）、不做"三段一视觉"的自动重排（只暴露 `maxParagraphSentences` 数值）。
- 不读环境变量、不读 `process.cwd()`、不猜 `os.homedir()`（`homeDir` 由调用方传）。

## 9. 门禁（本卡额外）

1. `pnpm verify` EXIT=0，四维 100%。
2. **正典样本**：把 `docs/02:156-176` 的 YAML **原样**（含中文注释与引号）做成 `packages/core/fixtures/styles/sharp-reviewer.yaml`，断言 `parseStyle` 零错误、字段值与文档逐项对齐。注释行号写进测试名。
3. **严格性反证**：未知键、snake→camel 混用、`max_paragraph_sentences: 4.5`、空 `persona`、`examples` 缺 `good` —— 五个各自断言 `invalid_style`，且报文含**允许键列表**。
4. **覆盖优先级**：同一 id 三层齐备时，项目层字段覆盖用户层、用户层覆盖预设；数组是替换不是拼接（用长度可区分的样本断言）。
5. **穿越**：`id` 为 `../../etc`、`a/b`、`A`（大写）、`-x` → 全部 `invalid_style_id`，且用 mock fs 断言**零 fs 调用**。
6. **编译稳定性**：同一 style 编译 1000 次逐字相同；空集合段不出现空标题；末尾恰好一个换行。
7. **Lint 通配**：`不仅...而且...` 命中 `不仅便宜而且快`、不命中 `不仅`（缺后半）；拉丁大小写与全角归一各一条。
8. 变异体 ≥5（含：`...` 变成字面量、NFKC 去掉、数组改成拼接、id 校验挪到 fs 之后、末尾多一个换行）。
