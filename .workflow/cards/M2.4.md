# CARD M2.4 — 阅读器接线（让 `hr serve` 默认就是能用的阅读器）

- 里程碑: M2
- 依赖: M4.7；sweep-R1 的 `B-07`…`B-13`、`B-17`
- 状态: todo
- 来源: 巡回测试 R1 台账（`.workflow/reports/sweep-R1.md`）。测试员用真 Chrome + CDP 读渲染后 DOM 得出，**不是**单元测试推的。
- 分工: 业务编写员 → `packages/app/src/**`、`packages/core/src/server/**`、`packages/cli/src/**`；测试编写员 → 对应 `tests/**`

## 问题一句话

阅读器的**模块**都在（`packages/app/src/{anchors,notes-*,keys,style-switch,flash}.ts` 有单测），但**外壳没有把它们接起来**：`hr serve` 默认吐 186 字节链接页；带 `--app-dir` 时左栏书库/目录为空、`j`/`k` 不响应、批注入口 `hidden`、CLI 写完页面不热更新。`packages/app/src/widgets/copy.ts:7` 甚至把 `本章有 0 条批注（M2.3 启用）` 写死了。

## 用户可见行为

1. 我在文档目录里跑 `hr serve my.html`，它打印的地址**直接就能进阅读器**（三栏齐全），不需要我传 `--app-dir`、不需要我找 token。
2. 左栏书库列出同目录的 `.html`，点一下切文档；目录列出各节，点一下跳过去，滚动时高亮当前节。
3. `j` / `k` 上下节移动；字号与行宽可调。
4. 划词 → 「批注选区」出现 → 提交 → 右侧页边注出现，刷新后仍在（写进 `hr-meta`）。
5. 另一侧 `hr patch` 改完，页面**自己**变（闪烁高亮），并给一键 Undo；Undo 后回到旧内容。

## 契约

### K1 `hr serve` 的默认资源定位

- 无 `--app-dir` 时，服务端必须从**自身安装位置**解析 app 资源（`import.meta.url` 相对，或构建期把 `packages/app/dist` 复制进 `packages/cli/dist/app/`），**不得**依赖 cwd。
- 解析失败时：`{"ok":false,"code":"app_assets_missing","message":"…（装包不完整？重装 @hreader/cli）"}`，退出码 1；**不得**静默退化成 186B 链接页。
- `--app-dir` 仍可覆盖（保留现有行为）；`/` 无 cookie 时 401 JSON 保持。

### K2 `/s/:docId` 的语义

- 现状：`/s/:docId?t=` 302 到 `/s/:docId`，后者返回**原文件字节**。用户从 `/s/` 拿不到阅读器。
- 改为：`/s/:docId?t=` 种 cookie 后 302 到 `/?doc=<docId>`（阅读器），**不再**直出原文件字节；原文件仍可由 `/raw/:docId`（新增，带 cookie）取。若确有调用方依赖 `/s/` 返回字节，必须在卡片报告里列出并解释（`grep` 全仓 + `docs/`）。

### K3 书库与目录的数据来源

- `GET /api/library`（新增或复用现有路由）：返回当前 workspace 下 `.html` 文件列表 `{"ok":true,"data":{"docs":["a.html",…]}}`，排序稳定（按名字，locale 无关）。
- `GET /api/outline?doc=<id>`（新增或复用）：返回该文档的标题树（复用 `hr_outline` 的同一口径；`data-hr-id` 不出来时**不得**返回空树——见 M4.8 的 `needs_normalize`）。
- 前端**不得**自己解析 HTML 生成目录（否则又是一套口径）；只渲染服务端给的树。

### K4 目录/ID 冲突

- 外壳的容器 id 不得与文档内部可能出现的 id 相同：`#hr-toc` → 外壳改用 `#hr-toc-panel`（或文档侧进入 iframe/重写 `id`）。**同一文档里出现两个 `id="hr-toc"` 是 bug**（B-09）。

### K5 热更新与 Undo

- daemon 的文件 watcher 必须在 CLI/外部写入后广播 SSE `{"type":"doc.changed","doc":"…","changed":["p-1-1"]}`（现状 `/api/events` 8s 只收到 `ready`）。
- 前端收到 `doc.changed`：拉取该节点新 HTML → 就地替换 → 闪烁 → 底部提示条出现「Undo」→ 点击调 `POST /api/undo`（或既有端点）。
- 若 watcher 关闭（`--no-watch` 之类），前端**不得**假装热更新。

## 验收标准 (AC)

- **AC-1 默认即阅读器**：`hr serve <doc>` 在 `mkdtemp` 目录里跑，打印地址 `GET` 后跟随重定向，最终 body 含三栏根节点（`#hr-library`/`#hr-canvas`/`#hr-notes` 各存在且非空壳）。**判据是照打印的地址走完重定向链**。
- **AC-2 书库可用**：目录里有 3 个 `.html`，`GET /api/library` 返回 3 个名字；前端 `#hr-library` 渲染出 3 个可点条目。
- **AC-3 目录可用**：对一份 12 节文档，服务端 outline 返回 12 条；前端 `#hr-toc-panel a` 有 12 条；点击第一条后 `scrollY > 0`。
- **AC-4 j/k 生效**：CDP 发真 `j` 后 `scrollY` 增大，发 `k` 后回落；`activeElement` 或高亮类有变化。
- **AC-5 字号/行宽**：控件存在且改值后 `#hr-canvas` 的 `font-size`/`max-width` 实际变化（读 computed style）。
- **AC-6 批注落盘**：CDP 真鼠标划词 → `#hr-note-btn` 可见 → 提交 → 右侧出现 1 条 sidenote；文件里 `hr-meta` 含该批注；刷新后仍在。
- **AC-7 热更新 + Undo**：另一进程 `hr patch` 后 2s 内页面文本变新；出现 Undo 按钮；点击后文本回旧，文件字节回到 patch 前（md5 比）。
- **AC-8 `healthz` 链接**：B-07 页面（若仍保留）与桌面壳 README 里的健康检查路由**是同一个且可用**；打印出的所有链接逐个能 200。
- **AC-9 无回归**：`pnpm verify` + `desktop:check` 全绿；`/` 无 cookie 仍 401 JSON；`/raw/:doc` 可取原字节。

## 风险点

- **禁止用"再加一个静态 demo 页"充数**：AC 必须跑在真 Chrome 上（CDP），happy-dom 的绿不算。
- 前端**不得**复制 outline 逻辑（K3）；复制即视为把口径分裂。
- 热更新要防抖（一次 patch 可能触发多次 fs 事件），且 Undo 的锚点必须与 `hr undo` 的语义是同一套（不许前端自己维护 undo 栈）。
- `packages/app/dist` 是构建产物（`.gitignore` 忽略）：改了 `src` 必须 `pnpm build` 后才能被 e2e 看到——交付时要贴 build 后的时间戳。
