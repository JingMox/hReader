# M3.1 · `@hreader/mcp-server`（标准 MCP Server + MCP-UI）

> 唯一验收依据。依据 `docs/02` §Milestone 3 / §4②（`packages/mcp-server`）、§3（5 个原语）。
> 前置：`@hreader/core` 已导出全部原语（`buildOutline`/`readNode`/`patchFile`/`applyStyle`/`resolveAnnotation`/`discoverStyles`/`compileTone`）；`@hreader/app` 与 daemon 已过门禁。
> 本卡**只做 MCP 适配层**。不做 Pi 插件（M3.2）、不做 DSH 插件（M3.3）、不重写 core 原语。

## 0. 分层（写死）

```
packages/mcp-server/
  package.json          # name: @hreader/mcp-server；bin: hreader-mcp → dist/main.js
  src/main.ts           # 唯一 bin：读 argv → 选传输 → 启动；不承载协议逻辑
  src/server.ts         # 组装 McpServer：注册 tools/resources/prompts（纯装配）
  src/tools/*.ts        # 每个工具一个文件：入参校验 + 调 core 原语 + 结果整形
  src/resources.ts      # `hreader://styles/{id}` 与 MCP-UI 视图资源
  src/prompts.ts        # `use-hreader-style` prompt
  src/ui.ts             # MCP-UI 的 `_meta.ui.resourceUri` 构造 + 内联视图 HTML
  src/log.ts            # 只写 stderr 的日志；**禁止** console.log
```

**分层规则（AC 违约即返工）**：
1. `src/**` **只许** import `@hreader/core` 与 `@modelcontextprotocol/sdk`、Node 内置、自身兄弟模块。**禁** import `packages/cli/**`、`packages/app/**`、`packages/core/src/**`（深层路径）。
2. 原语语义**不许在适配层重写**：patch 必须走 `patchFile`（否则丢原子写/revision/undo 快照），style 必须走 `applyStyle`，批注必须走 `resolveAnnotation`。
3. `src/**` 里出现 `console.log` 即为 P0（见 AC-4）。

## 1. 契约（AC）

**AC-1 包与构建可跑通**
- 新包 `packages/mcp-server`，`name: "@hreader/mcp-server"`，`private: true`，`type: "module"`，`bin: { "hreader-mcp": "./dist/main.js" }`。
- `pnpm-workspace.yaml` 的 `packages/*` 自动覆盖，无需改；但 **`vitest.config.ts` 的 `ALIASES` 必须加 `@hreader/mcp-server`**（测试与运行期解析同一份源码）。
- 根 `build` 脚本改为 `pnpm -C packages/app build && pnpm -C packages/mcp-server build`；mcp 包用 `tsc -p tsconfig.build.json` 输出 ESM 到 `dist/`（`dist/` 不被 git 跟踪）。
- 依赖**精确锁版本**（不用 `^`），并在 `docs/02` §依赖策略下登记"引了什么、替代了什么手搓代码"。

**AC-2 六个工具，参数与 core 原语一一对应**

| 工具 | 入参 | 必须调用（禁止自实现） |
| :--- | :--- | :--- |
| `hr_outline` | `filePath` | `parseHtml` + `buildOutline`（大纲 + 未处理 `pending_ai` 批注） |
| `hr_read_node` | `filePath`, `nodeId` | `readNode` |
| `hr_patch_node` | `filePath`, `nodeId`, `action`, `htmlContent` | `patchFile`（`PatchRequest` 五动作之一，非法动作拒绝） |
| `hr_apply_style` | `filePath`, `visualId?`, `toneId?` | `applyStyle`（切 `visualId` 只换 `<style id="hr-theme">`；`toneId` 返回规约文本） |
| `hr_resolve_annotation` | `filePath`, `annotationId`, `resolutionNote?` | `resolveAnnotation`（走 patch 管线） |
| `hr_create_doc` | `filePath`, `title` | 生成最小合法文档并 `validateDocument` 过校验（MCP-UI 的落点，见 AC-7） |

每个工具的 `description` 必须写**何时用**（不是复述参数名），且必须在 `tools/list` 里带 `inputSchema`（zod → JSON Schema，不得手写一份可能与校验不一致的 schema）。

**AC-3 错误必须是工具错误，不是进程崩溃**
- 一切失败返回 `{ isError: true, content: [{ type: "text", text: … }] }`，文本里**保留 `HrError.code`**（例如 `HR-E-PATH-001: …`）。
- 禁裸 `throw` 穿透到 SDK 层；禁把堆栈当正文返回（堆栈只进 stderr 日志）。
- 未知 `nodeId`/`annotationId`/`toneId`/非法 `action` 各有独立用例（AC-9）。

**AC-4 stdout 纯净（本卡最高风险项）**
- 进程 stdout **只许**出现 JSON-RPC 帧。所有日志/诊断走 `process.stderr`。
- 需要一条**真进程**用例：`spawn` 编译后的 `dist/main.js`，完成 `initialize` → `tools/list` 后关闭，断言 stdout **每一行都是合法 JSON-RPC 对象**（无 banner、无 `console.log` 残留、无版本号横幅）。
- `hr_*` 工具**不许**在自己的返回值里 `console.log` 进度。

**AC-5 Resources：`hreader://styles/{id}`**
- `resources/list` 列出 `discoverStyles()` 发现的全部风格（含内置），URI 形如 `hreader://styles/{id}`。
- `resources/read` 返回该风格 YAML 原文 + `mimeType: "application/yaml"`。
- 未知 id → 工具错误（`isError` 语义按 SDK 的 resource 错误形状），不得返回空文本。

**AC-6 Prompts：`use-hreader-style`**
- 参数 `toneId` 的取值集合来自 `discoverStyles()`（动态，不硬编码枚举）。
- 返回的 messages 必须含 `compileTone(toneId)` 产出的**完整语言规约**（不是"请用 sharp-reviewer 风格"这种空话）。
- 未知 `toneId` → 明确错误。

**AC-7 MCP-UI**
- `hr_create_doc` 与 `hr_patch_node` 的成功响应带 `_meta.ui.resourceUri = "ui://hreader/view/{docId}"`。
- 同名 URI 必须能被 `resources/read` 读出，`mimeType` 为 `text/html;profile=mcp-app`，内容是内联阅读视图（引用本地 daemon `http://127.0.0.1:<port>/…`，不得写死端口）。
- 无 daemon 在跑时该资源仍要能读（视图里显示"daemon 未启动"），**不得**抛错——MCP-UI 宿主不该因为后台没开就拿不到资源。

**AC-8 两种传输**
- 默认 `stdio`（`hreader-mcp` 无参即用）。
- `--http <port>` 启用 Streamable HTTP，只绑 `127.0.0.1`；端口被占用 → 明确退出码 + stderr 说明。
- 两种传输共享**同一份** `createServer()` 装配（不许两套工具注册表）。

**AC-9 测试（充分审计，不是只跑测试函数）**
- 用 SDK 的 **in-memory transport**（`InMemoryTransport.createLinkedPair()`）跑真实客户端↔服务端握手，覆盖：6 个工具的正常臂 + 每个工具至少 1 条错误臂（AC-3 列表）、resources list/read（含未知 id）、prompts（含未知 toneId）、MCP-UI 资源可读。
- 至少 1 条**真子进程** stdio 端到端（AC-4）。
- 至少 1 条**真文件**端到端：`hr_patch_node` 落盘后 `hr_outline` 能看到变化、`git` 无关（用临时目录），并断言**原子写 + undo 快照确实产生**（复用 core 既有行为，不许绕过）。
- 覆盖率四维 **perFile 100%**（含 `src/main.ts` 的 argv 分支——该文件的每条分支都要有用例，含 `--help`/未知参数）。

**AC-10 安全**
- `filePath` 一律走 core 的既有路径校验（realpath/逃逸拒绝），适配层**不许**新增一套。
- `--http` 只绑 `127.0.0.1`；`_meta.ui.resourceUri` 里的 URL 只用 `127.0.0.1`。

**AC-11 门禁**
`pnpm verify` EXIT=0（含 `build`/四维 coverage/`depcruise`/`knip`）；`knip` 必须认得新包的 bin 入口（`dist/main.js`），不得靠 `knipignore` 糊。禁 `as any`/`@ts-expect-error`/`it.fails`/删断言。

## 2. 预设裁定（别来问）

1. **包名用 `@hreader/mcp-server`**，`docs/02:287` 的注释写的是 `@hreader/mcp`——以本卡为准，收口时我改文档。
2. **SDK 版本精确锁**：`@modelcontextprotocol/sdk` 用当前 latest 的**精确版本**（不是 `^`）。zod 允许引入（SDK 的 schema 依赖它）。
3. **`hr_patch_node` 不做 dry-run**（本卡不含），不猜；有需要另开卡。
4. **不实现 `hr_serve`**：daemon 生命周期属于 CLI/用户，MCP 工具不该代管进程。MCP-UI 视图只**引用**已有端口。
5. **`hr_create_doc` 用最小合法文档**（`<article>` + `<h1>` + 一个 `<section>`），不做模板系统。
6. **不做鉴权/多用户**：本地单用户，绑 127.0.0.1 即边界。

## 5. 本卡裁定记录（协调者，边写边记）

### 5.1 core 缺口：`hreader://styles/{id}` 的 YAML 原文（裁定 **E**，2026-11-14）
A（适配层拼路径）、B（放三个内部 export）、C（一律序列化）全部否掉，理由是**真值源不得出现第二份**：
- A 复制的是**路径约定**（`.hreader/style.yaml` / `~/.hreader/styles/<id>/style.yaml`），core 改约定时它不会跟着变；注释里写"不得分叉"不是防线。
- B 把 `readOptionalText` + `projectStylePath` + `userStyleDir` 三条内部缝一次漏光，破了 `packages/core/src/index.ts` 的"极小导出面"。
- C 返回的不是原文，注释与键序全丢。

**E**：core 新增 `readStyleSource(id, deps)` → `{ readonly yaml: string; readonly origin: "file" | "generated" }`。
- 自定义档读 `style.yaml` 原文（内部复用既有三行，不许重写）；内置档无源文件 → `stringify(spec)` 且 `origin: "generated"`。
- core 已依赖 `yaml`（`packages/core/package.json`，注意它是 `^2.9.1`，本卡不动），**不许新装**。
- **冻结例外范围**：仅该函数 + `style/index.ts` 与 `index.ts` 两处 export + 其测试 + 导出面门禁的**期望值**。不许为此删门禁用例。
- 额外要求：内置档序列化产物必须能被 `loadStyle` 读回（往返一致性）——**内核读不回去的 YAML 不该发给宿主**。
- 破冻结的正当性：M3.2(Pi)/M3.3(DSH) 同样需要"风格源文本"织 prompt；放 core 是一份，放三个适配层是三份。

### 5.2 构建形态：**不 emit、改单文件 bundle**（裁定 **C**，2026-11-14）
根因：`packages/core` 是 source-only（`exports: "." → ./src/index.ts`，无 dist/.d.ts），`tsconfig.base.json` 的 `paths` 指向 core 源码，故 leaf 包 `tsc -p tsconfig.build.json`（`rootDir: src`）必报 `TS6059: File 'packages/core/src/index.ts' is not under rootDir`。

- 否 A（`bin → ./src/main.ts`，仿 `@hreader/cli`）：cli 是仓库内自用，mcp-server 是**被外部宿主 spawn** 的第一个产物；A 把两个实验性依赖放进交付路径——手写的 extensionless resolve hook（宿主不会替你装）+ 运行时类型剥离行为。**等于把实验性风险从 CI 转移到用户机器。**
- 否 B（`rootDir: "../.."` → `dist/packages/{core,mcp-server}/...`）：产出一份没人 import、没人测、删不掉的 core 副本，且会与源码悄悄分叉。**产出自己有第二份真值源的 dist，比不产出更坏。**
- **取 C**：`build` = `tsc --noEmit -p tsconfig.build.json && esbuild --bundle --platform=node --format=esm --target=node22 --outfile=dist/main.js`；`bin` 指向 `dist/main.js`。
  - `esbuild@0.28.2` 精确锁（`^` 不许），作 mcp-server devDependency，离线装。
  - `--noEmit` 让 `TS6059` 消失，但 **`tsconfig.build.json` 不许删/不许放宽**——它继续守"leaf 视角能否单独过类型"。
  - 不许 `--packages=external`（那等于把"自包含"退回"依赖宿主 node_modules"）。
  - `build` 前清 `dist/`（否则改文件/删文件后用旧产物测新代码）。
  - AC-4 真子进程用例 **spawn `dist/main.js`**（测被交付的东西），另加一条断言 `bin` 指向该产物并用 `bin` 路径再握手一次。
  - 静态核验产物：贴体积、`grep -c "console.log" dist/main.js`、确认无 `require(` 残留。
- **AC-1 实现手段变、卡意不变**：产物仍是 ESM、仍在 `dist/`、仍可 `node dist/main.js` 直跑。

### 5.3 SDK 的 `HeadersInit`（裁定：本地 `ambient.d.ts` 一行，2026-11-14）
`@modelcontextprotocol/sdk` 的 `shared/transport.d.ts` 用 DOM 的 `HeadersInit`，本仓 `lib` 只有 ES2023 且 `skipLibCheck: false`。
- 允许 `packages/mcp-server/src/ambient.d.ts` 内一行 `type HeadersInit = NonNullable<RequestInit["headers"]>`（接名字，不另立定义）。
- **不许**给 `tsconfig.base.json` 加 `DOM` lib——那会让全仓以为有 `document`，代价远大于一行别名。
- 该文件只许有这一行；注释须写明"SDK 修好后删除此文件并让它变红"。
- 交付须附：删掉 `ambient.d.ts` 后 `tsc` 确实变红的证据（证明这一行不是装饰品）。
