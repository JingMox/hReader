## 1. 锚点（写死，别再来问）

**Daemon 握手**：`~/.hreader/daemon.json` = `DaemonInfo { port, token, pid, workspace }`（`packages/core/src/server/contracts.ts`；读写删在 `packages/core/src/server/daemon.ts:16` `DAEMON_FILE`，原子写 + 0600）。文件不存在 = daemon 没起，**不许自动 spawn**（Pi 会话里静默拉 daemon 会让用户失去对进程的控制权）。

**docId 推导**（F1 实施时定，AC-2 回填）：`docId = path.resolve(workspace, target)` 相对 `path.resolve(workspace)` 的路径，分隔符一律归一成 `/`；**相对路径的基是 daemon 的 `workspace`，不是 Pi 的 cwd**；`target` 指向 workspace 自身或越界（`..` 逃出）→ 报错，不拼 URL。`/hreader` 无参数时只给用法（没有"打开 workspace"这种语义：`/s/:docId` 需要一个文档）。

**认证**（已由协调者逐行复核，**不必再猜**）：
- cookie 名 `hr`（`packages/core/src/server/auth.ts:7` `COOKIE_NAME`）；CSRF 头 `x-hr-csrf`（`auth.ts:9` `CSRF_HEADER`）。
- **cookie 的值就是 daemon token**：`server.ts:42` 的 `Set-Cookie` 为 `${COOKIE_NAME}=${token}; HttpOnly; SameSite=Strict; Path=/; Max-Age=…`，`server.ts:123` 用 `cookieOfToken(env.token)` 下发 → 客户端自己发 `Cookie: hr=<daemon.token>` 即可。
- **CSRF 校验是字面量**：`auth.ts:68` `export const csrfAllowed = (value) => value === "1"` → 头 `x-hr-csrf: 1`。
- 判定链：`http-io.ts:195` 用 `tokenMatches(cookieOf(header, "cookie"), token)`；`:202` `if (route.auth === "cookie+csrf" && !csrfAllowed(headerOf(req, CSRF_HEADER)))`。
- 路由 auth 种类（`routes.ts:62-83` 逐字）：`cookie` / `cookie+csrf` / `none` / `token`；本卡要用的三类分别是——读类 `GET /api/doc/:docId/{model,outline,annotations}`=`cookie`；写类 `POST /api/{patch,style,annotation,doc/:docId/annotations,doc/:docId/undo}`=`cookie+csrf`；`GET /api/theme` 与 `/api/theme/:styleId`=`none`；`GET /s/:docId`=`token`。
- `originAllowed` 放行**无 `Origin`** 的请求（`auth.ts:34-37`），Node/Bun 侧客户端天然过 Origin 检查。

**路由表**（`packages/core/src/server/routes.ts:62-83`，逐字）：
`GET /`、`GET /assets/:path`、`GET /api/theme`、`GET /api/theme/:styleId`、`GET /healthz`、`GET /s/:docId`（`token`）、`GET /api/doc/:docId/model`、`GET /api/doc/:docId/outline`、`POST /api/patch`、`POST /api/style`、`POST /api/annotation`、`GET /api/doc/:docId/annotations`、`POST /api/doc/:docId/annotations`、`POST /api/doc/:docId/annotations/:anId/...`、`GET /api/doc/:docId/notes/:anId/diff`、`POST /api/doc/:docId/undo`、`GET /api/events`。

**业务事件类型**（只有这四个；`ready`/`reset` 是**帧控制**，不是业务事件，见下条）：
- `doc.changed` — `payload: { path, … }`（`runtime.ts:88` 与 `:232`）
- `library.changed` — `payload: { path }`（`runtime.ts:106`、`:110`）
- `doc.error` — `payload: { path }`（`runtime.ts:118`）
- `error` —（`server.ts:159`）

**SSE 帧事实**（`packages/core/src/server/event-ring.ts`、`hub.ts`，全部已复核，逐字）：
- **core 从不下发 `event:` 行**。`frameOf`（`event-ring.ts:79`）只写 `id:` + `data:`，事件类型在 `data` 的 JSON 里（`payloadLine({ ...event.payload, type: event.type })`）。解析器**必须**按"从 `data` JSON 取 `type`"认类型，不许依赖 `event:` 字段。
- `event-ring.ts:74` `READY_FRAME = 'retry: 2000\nid: 0\ndata: {"type":"ready"}\n\n'` —— 带 `retry:` 字段（可覆盖重连退避），`id: 0` **且 0 不在环里** → 解析器**不得**把 `id: 0` 当作 `Last-Event-ID` 缓存（否则重连带 `Last-Event-ID: 0`）。
- `event-ring.ts:76` `KEEP_ALIVE_FRAME = ": keep-alive\n\n"`，连接建立注释帧 `: ready`（`CONNECT_COMMENT`）—— 以 `:` 开头的行是注释，**不是字段**，解析器要跳过且不崩。
- `event-ring.ts:83` `resetFrameOf` 产出 `data: {"type":"reset","reason":"events_expired"}`，**没有 `id:`**。`hub.ts:70` 的 `backfill` 在 `ring.since(lastId)` 返回 `hit:false` 时下发它 → **`hit:false` 是 200 正常流里的一帧，不是 HTTP 状态码**，任何用 4xx/5xx 模拟它的替身都是伪造协议。
- `ring.since(lastId)` 返回 `hit:false` 表示断线期间事件已被裁掉（客户端只能提示"请刷新阅读器"）。
- 心跳帧由 `setInterval` 发且已 `unref()`。
- 多字节 UTF-8 会跨 chunk 断开 → 解析器必须用 `TextDecoder({ stream: true })` 或按 `Uint8Array` 累积再解码，逐 chunk `Buffer.toString()` 在真实联调里出乱码而单测全绿。

**Pi 扩展 API**（以你本机安装的 docs 为准：`/Users/liu/.bun/install/global/node_modules/@earendil-works/pi-coding-agent/docs/extensions.md`）：
- 形态：`export default function (pi: ExtensionAPI) { … }`；`pi -e ./file.ts` 可加载。
- 命令：`pi.registerCommand(name, { description, handler: async (args, ctx) => … })`。
- 工具：`pi.registerTool({ name, label, description, parameters: Type.Object({…}), async execute(toolCallId, params, signal, onUpdate, ctx) { return { content: [{ type: "text", text }], details } } })`。
- UI：`ctx.ui.notify(text, "info" | "error")`、`ctx.ui.confirm(title, body)`；`ctx.hasUI` 在 print/JSON 模式为 `false`。
- 注入上下文：`pi.sendUserMessage(text, { deliverAs: "steer" | "followUp" | "nextTurn", triggerTurn })`、`pi.sendMessage({ customType, content, display }, options)`；另有 `before_agent_start` 事件可注入消息/改 system prompt。

## 3. 验收标准（AC）

≥ 每条都要能在 CI 里机械判定；不可判定的不算 AC。

- **AC-1 单文件形态**：`packages/pi-extension/pi-hreader.ts` 是唯一实现文件，`export default (pi: ExtensionAPI) => void`；该文件的**运行时** import 只有 `typebox`（`Type`）与 `node:` 内建，**零本地相对 import、零 `@hreader/*` import**（`grep -E "^import" ` 逐行核对；类型导入必须 `import type`）。理由：扩展要能从 `~/.pi/agent/extensions/` 直接加载。
- **AC-2 命令 `/hreader`**：传 `[path]` 时绑定该文档（相路径的基是 `daemon.workspace`，不是 Pi 的 cwd），notify 里出现 `http://127.0.0.1:<port>/s/<docId>?t=<token>` 形状的 URL；**无参时只打用法**（`/hreader <path>`）与 daemon 状态，不造"打开 workspace"语义（D11：`GET /` 是 cookie 认证、`/s/:docId` 是 token 认证，无参情况下没有可点的合法链接）；daemon 未起 → `ctx.ui.notify(…, "error")` 且文本含 `hr serve`。`t=` 的 token 就是 `daemon.json` 的 `token`；`docId` 由 path 相对 workspace 推得，**推导规则已由写者回填 §1**。
- **AC-3 SSE 订阅**：`GET /api/events` 带 `Cookie: hr=<token>`；解析器按 `id:`/`data:` 两字段 + `:` 注释行处理（**core 无 `event:` 行**，见 §1），**多帧跨 chunk 时不许丢帧或并帧**，且必须过 §1 列的三类切点（`data:` 行腰斩 / 终止符 `\r`·`\n` 半分 / 多字节 UTF-8 字跨 chunk）；断线重连带 `Last-Event-ID`（且**不得**是 `ready` 的 `id: 0`）；`hit:false` 的 `reset` 帧 → 提示"事件已过期，请刷新阅读器"而不是静默，也**不得**被当成"未知类型"吞掉；四个业务类型之外的类型忽略且不崩。
- **AC-4 拉模型引流**：`doc.changed` 的 `path` 若属于本会话绑定文档 → `GET /api/doc/:docId/annotations`；只对 `pending` 且**未注入过**的条目询问；同一 `anId` 不重复注入（进程内去重集合）；`confirm=false` 后同一 `anId` 不再询问。
- **AC-5 `/hr-style`**：无参列出风格 id，**唯一来源是 `GET /api/theme`**（`routes.ts` 中 auth=`none`、kind=`themes`，返回列表）；**扩展里出现任何 `readdir`/文件名过滤/`style/deps.ts` 式扫描即判 P1**（那就是 `L-13` 的第三份拼写）。有参时先对照该列表校验，非法 id 给出全部可选值；成功后 `POST /api/style`（`cookie+csrf`：带 `x-hr-csrf: 1`）并记住本会话绑定。
- **AC-6 三工具**：名字 `hreader_outline` / `hreader_read_node` / `hreader_patch_node`；`parameters` 全用 `Type.Object`，字段**裸类型**（`Type.String()` / `Type.Number()` / `Type.Boolean()` / `Type.Array(...)` / `Type.Optional(...)`），不许 `any`；成功返回 `{ content: [{ type: "text", text }], details }`，`details` 里带 daemon 的 `revision`；失败**不抛裸异常**，返回带 daemon 错误码的文本（错误码集合以 `packages/core/src/errors.ts` 为准）。
- **AC-7 协议漂移钉子**：新增测试解析 `packages/core/src/server/routes.ts` 的 `route("METHOD", [segments], auth, kind)` 行与 `runtime.ts`/`server.ts`/`hub.ts` 里 `publish("…")` 的字面量，断言扩展里出现的**每个**路径段与事件名都在其中；任一侧改名/删路由 → 该测试红。（手法同 M3.1 的 `entry-points.test.ts`：两份拼写用测试钉住，不共享代码。）
  **两条防假绿硬要求**（缺一即 FAIL）：
  a) **下界断言**：提取出的路径段数、事件名数、完整路由数都要有非零下界（例：`expect(routes.length).toBeGreaterThanOrEqual(10)`、`expect(eventNames).toContain("doc.changed")`），防止扩展侧用模板字符串拼路径导致提取集为空、`every()` 真空为真；
  b) **反向验证输出**：写者必须在 F 报告里贴"临时删掉 core 一侧某路由 → 该测试红"的实际输出（改完复原、`git status` 干净）。
- **AC-8 离线确定性**：单测注入假 `fetch` + 假 `pi`（不 spawn 真 daemon、不连网），至少覆盖：SSE 三类跨 chunk 切点（`data:` 行腰斩 / 终止符半分 / 多字节 UTF-8 字跨 chunk）、`Last-Event-ID` 重连（含"`id: 0` 不得入缓存"）、`reset`/`hit:false` 降级（含"把 reset 当未知类型吞掉"的反向臂）、`anId` 去重、`confirm=false` 后不再问、`ctx.hasUI === false` 时只 `notify` 不 `confirm`（**要变异验证**：删掉该判断后应有用例红）、错误码映射、`daemon.json` 缺失。真实 daemon 的联调写成 `scripts/smoke-*.ts` 手工脚本，**不进 CI**。

## 5. 风险点（审计重点）

1. **认证链路靠猜**：cookie + `x-hr-csrf` 的取法必须从 `handlers.ts`/`auth.ts` 追出真实链路并写行号；猜错的表现是"本机联调 403，单测全绿"（假绿高危区）。
2. **单文件 vs 代码重复**：为了"零本地 import"，路径拼接/鉴权/SSE 解析都要在扩展里重写一遍——这正是 `L-13`（同一条规则两份拼写）的复发面。AC-7 是唯一的约束手段，**它必须真的能红**（写者要给出"改 core 里任一侧即红"的反向验证输出）。
3. **`ctx.hasUI === false`**：print/JSON 模式下 `confirm` 不可用，必须退化为只 `notify`。
4. **`setInterval` 未 `unref`** 会让 Pi 进程退出被挂住；SSE 读流要能被 `signal` 中断（Pi 的 `execute` 会给 `AbortSignal`）。
5. **不许自动 spawn daemon**：静默拉进程会让用户失去控制；只提示命令。
6. **knip/覆盖率连坐**：新包纳入 workspace 后，`perFile: true` 四维 100% 与 `knip` 无 hint 对新文件同样生效——单文件里若出现不可达分支，会被覆盖率门禁抓住，这是预期行为，不许用 `istanbul ignore` 绕过（要就删分支，要就用例覆盖）。

## 6. 裁定记录（协调者，边写边记）

**D1 走拉模型，不新增事件类型**（2026-11-15）。理由：`patch.requested` 需要动 core 路由 + app 按钮，而 M3.1 的教训是"单卡别撑爆"；拉模型用现有 `doc.changed` + `GET /annotations` 就能闭环，且完全离线可测。推模型与"让 Pi 修改此段"按钮另开 **M3.2.1**。

**D2 单文件、零本地 import**（2026-11-15，沿用 `docs/02:236` 的"单文件哲学"）。代价是协议知识在扩展里重写一遍；对策是 AC-7 的漂移钉子，而不是共享代码（共享代码会让扩展无法从 `~/.pi/agent/extensions/` 直接加载）。

**D3 不自动 spawn daemon**。理由见风险 5；用户对进程有控制权优先于"少一步操作"。

**D4 `hit:false` 是真帧，不是状态码**（2026-11-15，测试员查 `hub.ts:70` 后提出）。`GET /api/events` 永远是 200；事件被裁掉时下发 `data: {"type":"reset","reason":"events_expired"}`（无 `id:`）。假 `fetch` 不得用 4xx/5xx 模拟这个信号。

**D5 "四个业务事件"不等于"只认四个 type"**（2026-11-15，测试员指出卡面自相矛盾）。`ready` 与 `reset` 是**帧控制**：`ready` 丢弃即可，`reset` 必须被识别并降级为"事件已过期"提示。字面实现"未知类型一律忽略"会把 `reset` 吞掉，使 AC-3 后半句永远不成立。

**D6 授权写者在卡内自主分批推进**（2026-11-15）。细则见 §7。

**D7 AC-5 唯一来源是 `GET /api/theme`**（2026-11-15，协调者复核 `routes.ts` 后裁定）。原卡写"与 `style/deps.ts` 扫描口径一致"不可机械判定，且会诱导扩展里再写一套 `readdir`；改为走 HTTP 列表，**扩展里出现目录扫描即 P1**。
