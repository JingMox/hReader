## 1. 契约（AC）

### 1.1 批注模型与锚定

- **AC1.1** 批注形状固定为：
  ```ts
  type Annotation = {
    readonly id: string;            // "an-<8 hex>"，由 (nodeId, start, quote, createdAt) 决定，稳定可复现
    readonly nodeId: string;        // 锚定块 data-hr-id
    readonly anchor: { readonly exact: string; readonly prefix: string; readonly suffix: string; readonly start: number };
    readonly note: string;          // 用户写的话，≤ 2000 字符
    readonly status: "pending" | "resolved";
    readonly createdAt: string;     // ISO 8601，注入式时钟（可测）
    readonly resolvedAt?: string;
    readonly resolutionNote?: string;
  };
  ```
  `exact` ≤ 500 字符，`prefix`/`suffix` 各 ≤ 64 字符（超出按 32/64 截断并记诊断，**不许**静默丢）。
- **AC1.2** `resolveAnchor(annotation, documentText)` 纯函数：优先 `exact` 唯一命中；多处命中用 `prefix`/`suffix` 消歧；仍不唯一取最接近 `start` 的；完全找不到 → 返回 `{ ok: false, reason: "anchor_lost" }`（**不抛异常**，由调用方决定诊断）。
- **AC1.3** 块被删除 → 该块批注进入 `orphaned` 状态（不删数据）；块文本被改写导致锚定丢失 → `anchor_lost`，**两种都不抛错**，只在右侧栏显示"锚点失效（原节点 xxx）"。

### 1.2 持久化（内嵌 meta）

- **AC2.1** `<script id="hr-meta" type="application/json">` 的 `annotations` 数组是本卡的唯一真相源；读写**只经** `store.ts` 的纯函数，`annotationOps` 负责落盘。
- **AC2.2** 写批注 = 一次原子写：新内容先写临时文件、`fsync`、rename；失败时原文件**字节不变**；成功后 revision +1 并推 `doc.changed`（复用 M2.1 事件，**不新增事件类型**）。
- **AC2.3** 写批注**必须**进 undo 快照链，`hr undo` 能回滚最近一次批注变更（与 patch 共用同一条链，顺序严格）。
- **AC2.4** 读入时校验：未知字段 → 一条 `invalid_meta` 诊断（只为**新增**字段报一条，不逐字段刷屏）；`status` 非法值 → 该条批注视为 `pending`；`annotations` 不是数组 → 整份 meta 视为空 + 1 条诊断（**不许**因为脏 meta 让阅读器白屏）。
- **AC2.5** 批注变更不得改变 `<article>` 正文的任何字节（其余区块必须逐一相同——写测试时按块快照比对）。

### 1.3 路由（12 → 16）

- **AC3.1** `POST /api/doc/<docId>/annotations`：body `{ nodeId, anchor, note }` → 201 + `{ id, revision }`；校验失败 400 `invalid_payload`（含字段名，**不含**栈/路径）。
- **AC3.2** `POST /api/doc/<docId>/annotations/<anId>/resolve`：body `{ resolutionNote? }` → 200 `{ revision }`；未知 id → 404 `not_found`。
- **AC3.3** `POST /api/doc/<docId>/undo`：撤销最近一次操作 → 200 `{ revision }`；无可撤销 → 409 `nothing_to_undo`。
- **AC3.4** `GET /api/doc/<docId>/annotations`：`{ annotations: Annotation[], lost: string[] }`（`lost` = 锚定失效的 id 列表）。
- **AC3.5** 四条新路由都必须过既有的**鉴权、Origin/Host 校验、CSP、路径穿越检查**（复用 M2.1 中间件，不许旁路）。

### 1.4 Visual Diff 与闪烁

- **AC4.1** `diffText(before, after)`：返回 `{ kind: "same"|"ins"|"del", text }[]`，相邻同类必须合并；`same` 之外的空串丢弃（**不许**返回零长度 chunk）。
- **AC4.2** 输入超过 20 000 字符时退化为"按段落的 same/ins/del"（不做字符级 LCS），并在 `doc.changed` 里带 `degraded: true`——**性能上限必须写进注释**。
- **AC4.3** 收到 `doc.changed` 且 `changedNodes` 非空 → 对应块加 `hr-flash` 类，2 秒后移除（用注入的 `setTimeout`，可测）。
- **AC4.4** Diff 模式：右栏显示该块的 `ins`/`del` 文本（`<ins>`/`<del>` 元素），`Revert` 调 `POST /api/doc/<id>/undo` 并回到 diff 前的 revision；`Accept` 按钮已删除（关闭面板由 `Esc` / `shift+D` 承担，见 G2-R P1-5）。
  - **附注（协调者裁定，2026-11-14）**：`/diff` 只对比 `annotation.nodeId` 指向的**那一块**，不是全篇。块 ID 因 patch 被重建时（`fragment.ts:163` `stripHrIds` + `injectNodeIds` 按内容重算），按模型先序同位置 + 同 tag 重新识别，并**声明** `degraded:true`、`reason:"block_reidentified"`；块已不存在则 `after:""`、`degraded:true`、`reason:"block_missing"`；ID 命中则 `degraded:false`。降级必须对用户可见（`degradedReason` 进 `#hr-diff-status`），**不许**静默错配。
  - **响应字段（协调者裁定 D.4）**：`nodeId` = **当前文档**里那块的真实 id（前端拿它标块，旧 id 常已被 patch 换掉）；重识别成功时另带可选 `originNodeId` = 批注记录的旧 id；直接命中不给 `originNodeId`（新旧相同，给了是噪音）；`block_missing` 时 `nodeId` 与 `originNodeId` 都等于旧 id。类型见 `packages/core/src/server/contracts.ts` 的 `AnnotationDiffBody`。
- **AC4.5** Diff 模式**不许**改动正文 DOM（只在右栏渲染）；切回时正文零变化（用假 Host 调用序列断言）。

### 1.5 阅读器交互

- **AC5.1** 划词（`selectionchange`/`mouseup`）→ 中栏浮动按钮"批注"→ 点击打开右栏输入框；提交后 POST 并乐观渲染（失败回滚 + 一条提示）。
- **AC5.2** 右栏两条分组："待处理"、"已归档（resolved）"；resolved 项显示 `resolvedAt` 与 `resolutionNote`。
- **AC5.3** 点击批注卡 → 滚动到锚点块并高亮（复用 `scrollTo`）；锚点失效 → 卡片标灰 + 显示"锚点失效"。
- **AC5.4** `c` 键对当前块创建批注（`keys.ts` 已有该 intent，接线到真实提交路径——按 M2.2 §10.7 的端到端接线规则测）。

## 2. 预设裁定（别来问）

1. **批注存在文件里，不存在数据库**（`docs/02` 的核心承诺：单文件自包含，脱离 hReader 也能打开）。
2. **不做协同/多写者**：一个文件一个写者，靠 M1.5 的 `withLock`。
3. **不做富文本批注**：`note` 是纯文本，渲染时转义（`textContent`），**绝不许** `innerHTML`。
4. **不做跨块批注**：选区跨两个 `data-hr-id` 块时，取起点所在块 + 提示"仅支持块内批注"（跨块锚定是下一版的事）。
5. `diffText` **不许**引第三方库（零依赖），LCS 自己写，但要带"最坏 20k×20k"的上限保护（AC4.2）。
6. 时间戳一律由注入的 `now()` 提供，**禁止**在库代码里直接 `new Date()`（否则不可测、不可复现）。
7. 批注 id 的哈希输入**必须**包含 `createdAt`（同一位置同一句话写两条批注要得到两个 id，不能撞）。
8. 新增错误码只允许 3 个：`invalid_payload`、`nothing_to_undo`、`anchor_lost`（不给 `annotation_not_found`——用既有 `not_found`）。

## §8 声明：`data-hr-id` 的漂移语义与迁移义务（G2-R3 补充，2026-11-14）

`data-hr-id` 是**内容派生**的：seed = tag + 同标签兄弟序 + 子树文本前 64 字符 + 子树 digest，经 FNV-1a 取 8 位 hex（`packages/core/src/html/inject.ts:111-112`、`hash.ts:23-24`）。因此：

- 同一份字节两次注入**必然**产出同一组 id（无随机、无时间输入）——这是可复现性的基础，测试基线靠它；
- **编辑会让 id 漂移**，而批注记录里的 `nodeId` **不做落盘迁移**：`packages/core/src/ops/annotationOps.ts:67` 的 `rewriteOf` 只重写 meta 脚本内容、原样保留 `nodeId`；全仓无 remap/retarget；
- 锚点失效由**读时重识别**兜底（三档语义见 AC4.4 附注 D.4），而不是写时改写。

**迁移义务**：M2 未对外发布（`.workflow/state.md` 发布口径："不发 npm、不建远端、本地推进"），故不存在需迁移的外部数据。发布后若更换 id 方案（持久化计数器 / UUID 等），**必须**先交付 `nodeId` 迁移脚本，否则既有批注全部失效。登记 `L-02`，重构卡 R-6 跟踪。
