# M2.1 · 本地 Daemon 与同步桥（零新依赖）

> 依据：`docs/02` §五 Milestone 2 第 1 条、`docs/03` §6（IPC/服务端约定）、`docs/04`（可读性/注释/裸类型）。
> 前置：M1 全绿（`20d5e37`，1109 例，四维 100%）。

## 0. 范围与硬约束

- 新增 `packages/core/src/server/**`（HTTP + SSE + 文件监听），CLI 加一条 `hr serve`（薄适配）。
- **零新 runtime 依赖**：只用 `node:http`、`node:fs`、`node:crypto`、`node:path`、`node:url`。现有依赖上限保持 `parse5` + `yaml`。
- 不引入 `express`/`ws`/`chokidar`。**不做 WebSocket**（见 §1 D3）。
- `packages/core/tests/**`、`packages/cli/tests/**` 归测试员；编写员不碰。

## 1. 预设裁定（有疑问按这里，不要再问）

**D3 · 传输用 SSE 而非 WebSocket。** 理由：零依赖下自实现 RFC 6455 要处理掩码、分片、关闭握手，全是"能写对但很容易写错"的面；SSE 只有"一行行 `data:`"，且 `EventSource` 自带重连。`docs/02` 里的"WebSocket 同步桥"我改成"SSE 同步桥"，语义不变（服务端推送 + 客户端 POST 命令）。

**D4 · 一切经 HTTP，无第二条通道。** 客户端命令一律 `POST /api/<command>`，`Content-Type: application/json`，请求体上限 1 MiB。

**D5 · 鉴权：一次性 token → HttpOnly cookie。**
- token 存在 `~/.hreader/daemon.json`（`mode 0600`）：`{ "port": 7420, "token": "<32B hex>", "pid": 1234, "workspace": "/abs/path" }`。
- `GET /s/<docId>?t=<token>` 是唯一接受 query token 的入口：校验通过后 `Set-Cookie: hr=<随机32B>; HttpOnly; SameSite=Strict; Path=/`，随后**302 到同一路径去掉 `t`**（避免 token 留在地址栏/日志）。
- 其余全部请求只认 cookie。**没有 cookie → 401**，响应体是 `{"error":{"code":"unauthorized"}}`。
- cookie 只存内存（进程退出即失效），不落盘。

**D6 · 反 DNS-rebinding / CSRF 三重校验（任一不过 → 403）：**
1. `Host` 头必须是 `127.0.0.1:<port>` 或 `localhost:<port>`（端口必须等于实际监听端口）；
2. 有 `Origin` 头时，必须等于 `http://127.0.0.1:<port>` 或 `http://localhost:<port>`；
3. 所有非 `GET` 请求必须带 `X-HR-CSRF: 1`（自定义头，简单请求跨站带不上）。

**D7 · 路径只能落在 workspace 内。** 复用 `src/io/paths.ts` 的 realpath 守卫（M1.8 的教训：两边都取真实路径）。URL 里的 `%2e%2e%2f` 一律先 `decodeURIComponent` 再判，**不许**先拼再判。

**D8 · 事件流可恢复。** 每事件带 `id:`（单调递增，进程内）。客户端重连带 `Last-Event-ID`：
- 命中环形缓冲（容量 256）→ 逐条补发；
- 未命中 → 只发一条 `doc.reloaded`，客户端整页刷新（**不做**增量猜测）。

**D9 · 同一文档的写请求串行化。** `POST /api/patch` 与 `POST /api/style` 对同一 docId 用 M1.5 的锁；并发请求排队，超过 5 s 未拿到锁 → `503` + `{"code":"busy"}`。

**D10 · 关闭要干净。** SIGINT/SIGTERM → 停止接受新连接、关掉所有 SSE 连接、取消 watcher、删 `daemon.json`（**只在自己仍是持有者时删**：读回来比对 pid）、`exit 0`。未处理的 rejection 必须让进程以非 0 退出并打印 `hr:` 前缀的单行错误。

## 2. 验收标准

### AC1 · 启动与握手
- `hr serve --workspace <dir> [--port 7420]` 启动后在 **stdout 打印单行 JSON**（无其他输出、无 ANSI）：`{"port":7420,"token":"…","workspace":"…"}`。
- `--port 0` → 系统分配，JSON 里是真实端口。
- `daemon.json` 写得原子（写 tmp → `rename`），`mode 0600`；已有 daemon 在跑（文件里 pid 存活且端口可连）→ `invalid_invocation`，报文提示已在运行的端口。
- 端口被占 → 退出码 `3`（`style_io_failure`？否 —— 用 `invalid_invocation`，exit 2），报文含端口号。

### AC2 · 静态与文档服务
- `GET /` → 书库页（M2.2 才做，先返回占位 HTML）。
- `GET /s/<docId>` → 该文档 HTML 原文（**字节不变**，`Content-Type: text/html; charset=utf-8`，`Cache-Control: no-store`）。
- `GET /api/doc/<docId>/model` → `toModel()` 的 JSON；`GET /api/doc/<docId>/outline` → `outline()` 的 JSON（键序与 M1.3/M1.4 契约一致）。
- 不存在的 docId → `404` + `{"code":"not_found"}`；越界路径 → `403` + `{"code":"path_outside_workspace"}`。

### AC3 · 命令
- `POST /api/patch`：体 `{docId, nodeId, fragment}` → 复用 `patchNode`，返回 `{revision, changed}`；**先在内存校验再落盘**，失败不改文件。
- `POST /api/style`：体 `{docId, themeId}` → 复用 `applyStyle`，返回 `{revision, changed}`。
- `POST /api/annotation`：体 `{docId, start, end, text, note?}` → 见 M2.3，本期只落 `hr-meta` 的 `annotations` 数组并返回新 revision。
- 请求体非法 JSON → `400` + `{"code":"invalid_request"}`；超 1 MiB → `413`。

### AC4 · 推送
- `GET /api/events`（cookie 鉴权）→ `text/event-stream`；首帧是 `retry: 2000` + `id: 0` 的 `ready`。
- 文件被外部修改（watcher 触发，去抖 100 ms）→ 推 `doc.changed`，载荷 `{docId, revision, changedNodes: string[]}`。`changedNodes` 由两份模型对比得出（新增/文本变化/属性变化）。
- 服务器自身写入（patch/style）→ 推同样的 `doc.changed`，**不与 watcher 重复**（自身写的 200 ms 内 watcher 事件要吞掉）。
- `Last-Event-ID` 恢复按 D8。

### AC5 · 运维
- `GET /healthz` → `200 {"ok":true,"uptimeMs":n}`，**不需要 cookie**（供脚本探活）。
- SSE 连接数上限 64，超出 → `429` + `{"code":"too_many_clients"}`。
- 空闲连接 30 s 发一次 `: keep-alive` 注释行（防中间层超时）。
- 所有响应都带 `X-Content-Type-Options: nosniff`；HTML 响应带 `Referrer-Policy: no-referrer`。

## 3. 测试要求（给测试员的输入，不在这里做完）

- **真 socket**：用 `node:net` 手写请求测 HTTP 解析边界（`Transfer-Encoding: chunked`、重复 `Content-Length`、`Host` 缺失、超长 header 8 KiB+、慢速 loris 5 s 不发完）。
- **SSE 帧格式**：逐字节断言 `id:`/`data:`/空行；断线重连 + `Last-Event-ID` 命中/未命中两路。
- **鉴权矩阵**：无 cookie / 错 token / 过期 cookie / `Host` 伪造 / `Origin` 伪造 / 缺 `X-HR-CSRF`，逐条断言 401/403 与报文。
- **路径**：`..%2f`、`%252e%252e`、绝对路径、符号链接越界、`file://` 注入。
- **写串行化**：并发 20 个 patch，断言最终文件合法、revision 单调、无丢写。
- **关闭**：SIGTERM 后 `daemon.json` 被删、端口关闭、无残留 tmp 文件。
