## 分层裁定（避免 M1.2 重复造 AST）

- **本卡产出仓库内唯一的 HTML 树**（下称原始树），M1.2 只在其上加语义访问器/校验，不得新建第二棵树。
- 原始树必须是**纯数据**：不得把 parse5 的节点对象直接暴露到公开 API（内部可用，边界处转换）。
- 公开 API 一律裸类型：`string` 进、纯数据结构出；只有"输入不可恢复"才抛 `HrError`，可恢复问题一律进 `diagnostics`。

## 契约

1. **解析**：`parseHtml(html: string): ParsedHtml`，`ParsedHtml = { root: HtmlNode; diagnostics: readonly Diagnostic[] }`。
   - `HtmlNode` 是判别联合（至少 `element` / `text` / `comment` / `doctype`），`element` 含 `tag: string`、`attrs: readonly [string,string][]`（保序，便于往返稳定）、`children: readonly HtmlNode[]`。
   - 容错：无 doctype、未闭合、错嵌套、重复属性、`<script id="hr-meta">` 内含 `</script>` 字样均**不得抛异常**；对应 `Diagnostic { code, severity, message, path? }`，`code` 为稳定窄联合（不得用自由字符串）。
   - 空字符串、非字符串输入的处理必须在契约里写明（非字符串：抛 `HrError("invalid_html")`，因为类型系统外的东西不可恢复；空串返回空文档 + 诊断）。
2. **序列化**：`serializeHtml(parsed: ParsedHtml): string`。
   - 属性顺序保持输入顺序；文本/属性按 HTML 规范转义；`<script>`/`<style>` 内容不转义（raw text）。
   - 不做美化、不重排空白：解析器归一化后的空白即输出空白。
   - 往返：`parse(serialize(parse(x)))` 的树在 `tag/attrs/children` 上与 `parse(x)` 深度相等（文本按解析后归一化比较）。这条必须由测试用真实文档验证。
3. **ID 注入**：`injectNodeIds(parsed: ParsedHtml): { parsed: ParsedHtml; injected: readonly string[] }`，纯函数，不改入参。
   - 注入对象：`<article>` 内所有块级元素（section/header/footer/p/h1–h4/ul/ol/li/table/figure/details/pre/div[data-hr-component]/blockquote）。
   - 已有合法 `data-hr-id` 一律保留；非法值（空串/含空白/非 `[a-z0-9-]`）→ 改写 + 诊断。
   - 新 ID 规则：`hr-` + 8 位小写十六进制，由**内容 + 结构位置**确定（如 tag、归一化文本、同标签兄弟序号做输入），**不得**依赖时间、随机、文件路径、进程状态。哈希实现必须自包含（不得 `import "node:crypto"`）。
   - 冲突（文档里已有同值）：确定性追加后缀 `-2`、`-3`…，且结果与遍历顺序无关地稳定。
   - 同一输入两次调用，输出逐字节一致。
4. **诊断**：`DiagnosticCode` 在本卡只允许：`unclosed_tag`、`misnested_tag`、`duplicate_attribute`、`invalid_component`、`invalid_hr_id`、`script_in_meta`、`empty_document`。新增值必须走卡片修订。
5. **组件白名单**：`data-hr-component` 仅 6 个值（`kpi-bento`、`callout-insight`、`callout-warning`、`split-compare`、`deep-dive`、`step-timeline`）+ `diagram-stage`（若 `docs/02` 写的是 7 个，以 `docs/02` 为准并在报告里指出冲突）。非法值：保留节点、产生 `invalid_component` 诊断，**不得静默丢属性**。
6. **依赖**：只允许 `parse5`（生产依赖，声明在 `packages/core/package.json`）。不得引入 `jsdom`/`linkedom`/`cheerio`。若 parse5 无法满足"属性保序"或 raw text，先问协调者。
7. **代码形态**：每文件 ≤ 400 行、函数 ≤ 40 行、复杂度 ≤ 10；模块头 ≤ 3 行且只写"这层管什么"；导出面最小——`src/html/index.ts` 只导出后续卡确实要用的符号，`packages/core/src/index.ts` 不加未用导出（knip 会抓）。
8. **性能**：`parseHtml + injectNodeIds` 对 1MB 文档 ≤ 300ms（本机基线由测试员测；你需在报告给出自己的测量方法与数值，不得只写"很快"）。

## 审计重点

ID 是否真的确定性（换目录、换进程、改系统时间后是否同值）；哈希碰撞/追加后缀是否可能产生二次冲突；属性保序在重复属性与大小写混写下是否成立；raw text 元素是否被错误转义/执行；`</script>` 出现在 meta 里时是否会提前截断；诊断码是否被自由字符串绕过；空/超深嵌套（10k 层）是否会栈溢出；1MB 性能是否线性。

## 测试义务

真实文档往返、畸形输入不抛异常、ID 确定性（同输入两次 + 不同 cwd）、已有 ID 保留/非法 ID 改写、冲突后缀、6/7 组件白名单、属性顺序、raw text、10k 深嵌套、1MB 性能、空串与非字符串输入、`instanceof HrError` 且 `code` 正确。
