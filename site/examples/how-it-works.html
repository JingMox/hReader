hReader 原理：Agent 怎样只改一段

一句话：hReader 给 HTML 文档里的每个块分配稳定的 data-hr-id，Agent 先看大纲、再读一块、只改一块；所有写入都是原子的，并且留下可撤销的快照。

为什么不整篇重写

整篇重新生成

每次都把全文塞进上下文；改好一处，其他地方的措辞和版式也可能跟着变。

按块修改

只读、只写目标块，其余字节原样保留；写错了一条命令撤销。

Agent 的五步工作流

  1. 看结构

    hr outline doc.html：每行一个块 id、标题和字数。

  2. 读原文

    hr read doc.html <id>：拿到这一块的 HTML 片段。

  3. 写片段

    把新内容写进临时文件，只用 8 个语义组件。

  4. 落盘

    hr patch doc.html <id> --action replace --html-file new.html。

  5. 验证

    hr style doc.html --lint 检查禁用词；不满意就 hr undo doc.html。

安全边界

写入的片段不允许出现脚本、iframe、事件属性和 javascript: 链接，命中就整体拒绝，文件一个字节都不会变。路径也被限制在工作区之内。

展开：块 id 是怎么来的

没有 id 的块会由 hr normalize 按内容派生一个确定的 id（形如 hr-24a9f952）。同一份内容得到同一个 id，所以 Agent 拿到的 id 可以直接喂回下一条命令；内容变化后应以最新的 outline 为准。

接入方式

{
  "mcpServers": {
    "hreader": {
      "command": "node",
      "args": ["/path/to/hreader-mcp-server/dist/main.js", "--workspace", "/path/to/docs"]
    }
  }
}

也可以把 Agent Skill 包放进 Agent 的 skills 目录，或者直接用 CLI。详见项目 README。
